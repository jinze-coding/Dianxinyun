# 智慧工地视频接入专项方案

## 面向智慧工地多项目监管平台的视频接入与管理方案

------

## 一、文档定位

本文档用于说明 **智慧工地多项目监管平台 V1.0** 中视频监控接入的建设思路、接入方式、设备要求、点位要求、数据字段、系统功能、技术边界及实施步骤。

本专项方案重点解决以下问题：

```text
1. 工地摄像头应该接哪些点位；
2. 摄像头设备信息如何标准化管理；
3. 国标设备ID如何记录；
4. GB28181、海康、天翼视联、RTSP等接入方式如何兼容；
5. 视频画面如何在平台中展示；
6. 多项目、多摄像头如何统一管理；
7. 视频存储、在线率、带宽如何纳入系统管理；
8. 软件平台如何与后续视频监管要求保持一致。
```

本方案适用于建工后续智慧工地平台建设、项目试点接入、视频系统对接、摄像头资源管理、平台开发及后期运维。

------

# 二、建设背景

根据上海市住房和城乡建设管理委员会相关文件要求，符合条件的建设工程施工现场应完成视频监控接入“上海市建筑工地安全监管平台”，并对安装点位、传输存储、接入阶段、在线率、设备参数等作出要求。文件明确提出，视频设备应覆盖工地人员出入口、塔吊/制高点、基坑及其他危险性较大的分部分项工程作业区等基础点位，并要求支持 GB/T28181-2016、H.264 视频编码、云台控制、巡航、红外夜视等能力。

因此，建工后续智慧工地平台中的视频模块，不应只理解为“播放摄像头画面”，而应建设成一套完整的 **视频资源管理与接入体系**。

该体系应包括：

```text
摄像头档案管理
摄像头点位管理
国标设备ID管理
接入协议管理
接入平台管理
视频播放地址获取
视频窗口布局管理
视频在线状态管理
视频在线率统计
视频访问日志
视频接入运维管理
```

------

# 三、建设目标

## 3.1 总体目标

建设一套适用于多项目智慧工地场景的视频接入与管理能力，实现：

> 多项目摄像头统一建档、统一接入、统一展示、统一监管、统一运维。

------

## 3.2 具体目标

```text
1. 建立摄像头资源标准档案；
2. 支持人员出入口、塔吊/制高点、危大工程作业区等重点点位管理；
3. 支持 GB28181、RTSP、海康平台、天翼视联、流媒体平台等多种接入方式；
4. 支持摄像头国标设备ID记录；
5. 支持视频画面在系统内实时展示；
6. 支持 1 / 4 / 8 / 16 路视频窗口布局；
7. 支持摄像头在线状态和在线率统计；
8. 支持视频存储天数记录；
9. 支持视频访问日志记录；
10. 为后续 AI 视频识别、告警联动、监管平台对接预留接口。
```

------

# 四、视频点位建设要求

## 4.1 基础点位要求

根据施工现场视频监管要求，智慧工地平台中建议将摄像头安装位置标准化为以下基础点位：

| 点位类型            | 说明                                     | 是否建议一期纳入 |
| ------------------- | ---------------------------------------- | ---------------- |
| 人员出入口          | 监控施工人员进出、防汛防台人员撤离等情况 | 是               |
| 塔吊/制高点         | 监控现场施工进度、文明施工、整体作业面   | 是               |
| 基坑/危大工程作业区 | 监控基坑、危大工程、重点风险区域         | 是               |
| 生活区              | 监控生活区人员活动、安全管理             | 可选             |
| 材料区              | 监控材料堆场、物资进出                   | 可选             |
| 其他区域            | 根据项目现场实际情况补充                 | 可选             |

------

## 4.2 系统安装位置枚举

平台中建议使用统一编码管理安装位置：

| 编码              | 中文名称            | 说明                         |
| ----------------- | ------------------- | ---------------------------- |
| `PERSON_ENTRANCE` | 人员出入口          | 工地或生活区人员进出口       |
| `TOWER_CRANE`     | 塔吊/制高点         | 塔吊或高点位摄像头           |
| `DANGER_AREA`     | 基坑/危大工程作业区 | 基坑、深基坑、危大工程作业面 |
| `LIVING_AREA`     | 生活区              | 工人生活区、宿舍区           |
| `MATERIAL_AREA`   | 材料区              | 材料堆场、仓储区             |
| `OTHER`           | 其他                | 其他自定义点位               |

------

# 五、视频设备参数要求

结合视频接入操作手册要求，平台摄像头档案中应支持记录以下设备参数：

| 参数         | 要求/建议                                    |
| ------------ | -------------------------------------------- |
| 摄像机类型   | 建议球机                                     |
| 视频协议     | 支持 GB/T28181-2016                          |
| 视频编码     | H.264                                        |
| 分辨率       | 1080x720P@25fps 及以上，建议 1920x1080       |
| 帧率         | 25fps                                        |
| 云台控制     | 建议支持                                     |
| 巡航功能     | 建议支持 360° 巡航                           |
| 自动归位     | 建议支持                                     |
| 光学变倍     | 不低于 20 倍                                 |
| 数字变倍     | 不低于 16 倍                                 |
| 夜视能力     | 支持红外夜视                                 |
| 防护等级     | 建议 IP66                                    |
| 视频叠加信息 | 左上角标注时间，右下角标注项目名称及安装位置 |

这些内容不一定全部由软件平台自动校验，但应在摄像头档案中具备记录、查看和后续扩展能力。

# 六、视频传输与存储要求

## 6.1 带宽估算

根据视频接入要求，可按每路视频约 4Mbps 作为带宽基准，并增加 20% 冗余。

计算方式：

```text
项目视频上行带宽 = 摄像头数量 × 4Mbps × 1.2
```

示例：

```text
3 路摄像头 × 4Mbps × 1.2 = 14.4Mbps
建议上行带宽不低于 15Mbps
```

平台中建议记录每路摄像头的预估带宽字段：

```text
bandwidth_mbps
```

------

## 6.2 视频存储要求

文件中提出，一般项目视频数据存储 1 个月，市管项目视频数据存储 3 个月。

平台中建议以字段形式记录：

```text
storage_days
```

建议值：

| 项目类型          | 存储天数 |
| ----------------- | -------- |
| 一般项目          | 30 天    |
| 市管项目/重点项目 | 90 天    |

------

## 6.3 在线率要求

文件中明确提出，设备在线率不得低于应运行天数的 80%。

平台中建议记录：

```text
online_rate
```

并设置判断规则：

| 在线率 | 状态        |
| ------ | ----------- |
| ≥ 80%  | 正常        |
| < 80%  | 异常/需关注 |

------

# 七、视频接入方式设计

智慧工地平台不应只绑定某一种接入方式，应支持多种接入模式。

## 7.1 接入方式一：GB28181 国标协议接入

### 适用场景

适用于按照监管要求或平台规范进行视频接入的项目。

### 特点

```text
1. 标准化程度较高；
2. 适合对接监管平台、天翼视联、国标视频平台；
3. 需要记录国标设备ID；
4. 需要摄像头支持 GB/T28181-2016；
5. 适合施工现场正式视频接入。
```

### 系统需要记录

```text
国标设备ID
接入协议
接入平台
设备编码
安装位置
项目名称
摄像头名称
```

------

## 7.2 接入方式二：海康平台接入

### 适用场景

如果项目现场或建工已有海康综合平台、HikCentral、NVR 或海康相关视频平台，可通过海康接口或平台能力获取播放地址。

### 系统设计

```text
海康平台 / NVR / 视频平台
→ 后端视频适配器
→ 获取播放地址
→ 前端播放器播放
```

### 注意事项

```text
1. 需确认海康平台是否开放接口；
2. 需确认账号、权限、AppKey、Secret等；
3. 需确认返回的视频流格式；
4. 需确认播放地址有效期；
5. 不建议业务后端直接转发视频流。
```

------

## 7.3 接入方式三：RTSP + 流媒体服务器

### 适用场景

适用于项目现场只有摄像头、NVR 或 DVR，尚无统一视频平台的情况。

### 技术链路

```text
摄像头 / NVR
→ RTSP
→ 流媒体服务器转封装/转码
→ FLV / HLS / WebRTC
→ 前端播放
```

### 常见流媒体服务

```text
ZLMediaKit
SRS
LiveGBS
EasyCVR
其他流媒体服务
```

### 注意事项

浏览器通常无法直接播放 RTSP，因此需要通过流媒体服务转换成浏览器可播放的格式。

------

## 7.4 接入方式四：天翼视联/监管平台接入

### 适用场景

适用于已通过“天翼视联装维端”或视频专线接入的项目。

### 说明

根据操作手册，现场可通过“天翼视联装维端”APP 进行设备绑定、获取平台配置信息、填写 GB28181 配置、记录国标 ID、绑定视频云回看套餐等操作。

### 系统侧需关注

```text
是否能获取播放地址；
是否具备接口调用权限；
是否需要书面申请数据调用权限；
是否会产生接口开发或附加流量费用；
是否只能在监管平台内查看。
```

------

# 八、系统视频接入总体架构

## 8.1 推荐架构

```text
现场摄像头 / NVR / 视频平台
        ↓
海康平台 / GB28181平台 / 天翼视联 / 流媒体服务器
        ↓
智慧工地平台后端
        ↓
智慧工地平台前端视频窗口
```

------

## 8.2 后端职责

平台后端只负责：

```text
1. 摄像头资源档案管理；
2. 项目与摄像头关系管理；
3. 用户项目权限校验；
4. 视频播放地址获取；
5. 视频布局配置；
6. 摄像头在线状态记录；
7. 视频访问日志记录；
8. 第三方视频平台适配。
```

------

## 8.3 前端职责

平台前端负责：

```text
1. 视频窗口展示；
2. 视频播放器加载；
3. 1 / 4 / 8 / 16 路布局切换；
4. 视频播放失败提示；
5. 离线摄像头占位展示；
6. 视频窗口全屏；
7. 摄像头名称、安装位置、状态显示。
```

------

## 8.4 禁止事项

平台业务后端不应直接承载视频流。

禁止架构：

```text
摄像头视频流 → 业务后端 → 前端
```

原因：

```text
1. 视频流带宽大；
2. 多项目并发时后端压力过高；
3. 云服务器流量成本高；
4. 容易影响业务接口稳定性；
5. 不利于横向扩展。
```

推荐方式：

```text
后端返回播放地址/播放令牌
→ 前端直接从视频平台或流媒体服务拉流
```

------

# 十、视频播放功能设计

## 10.1 视频播放地址接口

前端播放视频时，不直接读取数据库中的视频地址，而是调用后端接口：

```http
GET /api/v1/cameras/{cameraId}/play-url
```

后端处理流程：

```text
1. 获取当前登录用户；
2. 查询摄像头信息；
3. 校验用户是否拥有该摄像头所属项目权限；
4. 根据 access_protocol 判断接入方式；
5. 调用对应视频适配器获取播放地址；
6. 写入视频访问日志；
7. 返回前端可播放地址。
```

返回示例：

```json
{
  "code": 200,
  "message": "success",
  "data": {
    "cameraId": 1,
    "cameraName": "1号人员出入口摄像头",
    "playUrl": "https://video.example.com/live/camera001.flv",
    "streamType": "FLV",
    "expireTime": "2026-05-07 18:30:00"
  }
}
```

------

## 10.2 视频窗口布局

前端支持以下布局：

| 布局     | 说明      |
| -------- | --------- |
| 单窗口   | 1 路视频  |
| 四宫格   | 4 路视频  |
| 八窗口   | 8 路视频  |
| 十六窗口 | 16 路视频 |

后端需提供：

```http
GET /api/v1/video-layouts
POST /api/v1/video-layouts
```

用于查询和保存项目默认视频窗口布局。

------

## 10.3 视频窗口展示信息

每个视频窗口建议展示：

```text
摄像头名称
项目名称
安装位置
在线状态
播放状态
视频时间
全屏按钮
刷新按钮
```

# 十一、视频适配器设计

为了兼容不同视频接入方式，后端建议采用适配器模式。

## 11.1 视频适配器接口

```java
public interface VideoProviderAdapter {
    VideoPlayUrlDTO getPlayUrl(CameraResource camera);
    CameraStatusDTO getStatus(CameraResource camera);
}
```

## 11.2 适配器实现

```text
MockVideoProviderAdapter
Gb28181VideoProviderAdapter
HikCentralVideoProviderAdapter
RtspMediaServerAdapter
TianyiVideoProviderAdapter
```

## 11.3 设计原则

```text
1. Controller 不直接调用海康或视频平台接口；
2. Service 根据 access_protocol 选择适配器；
3. 第三方接口变化时，只修改对应适配器；
4. 前端播放逻辑保持稳定；
5. 后续可扩展 AI 视频、告警事件等能力。
```

# 十三、与上海市监管要求的关系

## 13.1 平台自身定位

本平台不是直接替代上海市建筑工地安全监管平台，而是作为建工内部智慧工地多项目监管平台。

平台主要作用：

```text
1. 管理建工项目自身的视频资源；
2. 记录摄像头接入信息；
3. 记录国标设备ID；
4. 展示视频播放入口；
5. 支持多项目视频统一查看；
6. 为后续监管平台数据对接预留条件。
```

------

## 13.2 数据调用权限说明

如果项目视频已通过视频专线或监管平台接入“上海市建筑工地安全监管平台”，其他单位或管理部门如需调用相关数据，通常需要根据数据权限进行申请，相关接口开发和附加流量等费用也可能由数据调用方承担。

因此，本平台如需调用监管平台中的视频数据，应提前确认：

```text
是否允许调用；
由谁申请权限；
接口是否开放；
是否需要费用；
播放地址如何获取；
是否有访问限制；
是否支持实时预览；
是否支持回放。
```

# 十四、实施步骤

# 十六、风险与控制措施

## 16.1 视频接入方式不统一

### 风险

不同项目可能使用不同视频接入方式，如海康平台、GB28181、RTSP、天翼视联等。

### 控制措施

采用视频适配器模式，不将第三方接入逻辑写死在业务代码中。

------

## 16.2 视频流压力过大

### 风险

多项目、多窗口同时播放视频，可能带来较大带宽和播放压力。

### 控制措施

```text
1. 视频流不经过业务后端；
2. 使用子码流；
3. 前端切换页面时销毁播放器；
4. 16路视频播放时控制码率；
5. 必要时接入专用流媒体服务。
```

------

## 16.3 监管平台视频无法直接调用

### 风险

监管平台视频数据可能存在权限和接口限制。

### 控制措施

```text
1. 提前确认调用权限；
2. 明确由谁申请接口；
3. 系统先支持自有视频资源管理；
4. 后续根据授权情况再接入监管平台视频。
```

------

## 16.4 现场摄像头资料不完整

### 风险

缺少国标设备ID、安装位置、RTSP地址、平台账号等信息。

### 控制措施

上线前制定摄像头资料采集表，由项目方统一补齐。

## 17.2 视频播放验收

```text
1. 可获取视频播放地址；
```

# 十九、给实施团队的关键原则

```text
1. 先管理摄像头资源，再接真实视频流；
2. 先做 Mock 视频播放，再做真实平台联调；
3. 视频流不经过业务后端；
4. 摄像头必须绑定项目；
5. 摄像头必须记录安装位置；
6. 国标设备ID要作为重要字段管理；
7. 视频接入方式要可扩展；
8. 监管平台视频调用需提前确认权限；
9. 多项目视频播放要考虑带宽和并发；
10. 一期聚焦接入和展示，二期再做AI和高级控制。
```

# 二十、总结

视频接入模块是智慧工地多项目监管平台 V1.0 的核心能力之一。

该模块不只是“播放视频”，而是要形成一套完整的：

```text
摄像头资源管理
视频接入管理
点位合规管理
国标设备ID管理
播放地址获取
视频窗口展示
在线率统计
访问日志记录
后续AI扩展预留
```

通过本专项方案，建工可以先建立标准化的视频资源管理体系，再逐步接入真实视频流、监管平台、海康平台、天翼视联平台或自建流媒体服务，最终形成适用于多项目统一监管的视频能力底座。
