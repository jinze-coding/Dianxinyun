# 智慧建造软件平台建设建议书

## 面向建工智慧建造业务落地的软件平台建设方案

------

## 一、文档定位

本文档用于说明我方作为软件开发与系统集成供应商，对建工后续智慧建造业务落地的理解、建设建议、产品切入方向和分阶段实施路径。

建工当前已形成“智建未来”的战略方向，围绕智慧建造、数字化施工管理、虚拟建造、智能装备运用等内容，提出了面向未来总承包管理能力升级的整体设想。相关材料中明确提出，智慧建造应围绕智慧化施工管理、虚拟建造、智能装备运用三大核心能力展开，并通过“诊断与规划、部署与集成、培训与赋能、优化与迭代”的实施方法推动落地。

我方认为，建工后续如需将该战略真正落地，不能仅停留在概念展示或单一大屏建设层面，而应优先建设一套可运行、可接入、可复制、可持续迭代的 **智慧建造软件平台底座**。

本文档重点说明：

1. 我方对建工智慧建造方向的理解；
2. 软件平台在智慧建造业务中的作用；
3. 第一阶段建议建设的核心产品；
4. 平台建设的功能范围；
5. 分阶段实施路径；
6. 建工需要提供的配合资料；
7. 我方可承担的开发与集成工作；
8. 后续可扩展方向。

# 二、对建工智慧建造战略的理解

## 2.1 智慧建造不是单一系统，而是一套能力体系

从建工当前规划方向看，智慧建造不是单独建设一个大屏，也不是单纯采购几个智能设备，而是需要逐步形成一套覆盖项目现场管理、施工过程管控、数据采集、设备协同、人员安全、资料留档、BIM应用、智能装备和运营分析的综合能力体系。

结合现有材料，建工未来智慧建造能力可概括为三条主线：

```text
1. 智慧化施工管理
2. 虚拟建造
3. 智能装备运用
```

其中，智慧化施工管理是最适合优先软件化、平台化落地的部分。

------

## 2.2 软件平台应成为智慧建造的第一阶段抓手

智慧建造涉及硬件、软件、现场施工、设备、BIM、机器人、AI算法等多个方向。若一开始全面铺开，容易出现建设范围过大、投入过重、交付周期长、现场配合难、数据来源不明确等问题。

因此，我方建议第一阶段不要直接建设“大而全”的智慧建造全生命周期平台，而是从最容易落地、最能形成管理价值的软件平台切入。

第一阶段建议建设：

# 智慧工地多项目监管平台 V1.0

该平台可作为建工后续智慧建造业务的软件底座，优先解决以下实际问题：

```text
项目在哪里？
现场怎么看？
视频怎么接？
人员怎么管？
安全资料怎么留？
设备状态怎么看？
多个项目怎么统一监管？
后续 BIM、AI、智能装备数据如何接入？
```

# 三、建设必要性

## 3.1 多项目监管需要统一入口

建工后续若管理多个项目，项目分布在不同区域，现场数据分散在不同系统、不同设备、不同项目部中。如果没有统一平台，总部、分公司或业务部门很难实时掌握项目现场情况。

通过建设多项目监管平台，可实现：

- 多项目统一地图展示；
- 项目概况集中查看；
- 视频监控统一入口；
- 摄像头资源统一管理；
- 人员安全信息统一归档；
- 设备状态统一查看；
- 资料文件统一留存；
- 后续项目快速复制接入。

------

## 3.2 视频监管已成为智慧工地基础能力

结合上海市施工现场视频监控相关要求，建设工程现场视频监控需覆盖人员出入口、塔吊/制高点、基坑及危大工程作业区等基础点位，同时对 GB/T28181、H.264 编码、存储天数、在线率等提出要求。

因此，视频接入不是简单“放几个摄像头画面”，而应形成完整的视频资源管理能力，包括：

```text
摄像头档案
国标设备ID
安装点位
接入协议
接入平台
存储天数
在线率
视频播放地址
视频窗口布局
访问权限
运行日志
```

这部分是智慧工地平台第一阶段必须建设的核心能力。

------

## 3.3 现场人员与安全资料需要数字化留档

施工现场存在临时人员进场、安全三级教育、培训资料、工人签字文件、证书凭证等管理需求。若仍采用纸质文件或分散存储方式，后期查询、追溯、检查和验收都会存在困难。

平台应提供：

- 临时人员登记；
- 安全三级教育批次管理；
- 培训资料上传；
- 签字文件上传；
- 教育记录留档；
- 文件查询、下载、归档；
- 项目资料统一管理。

------

## 3.4 后续 BIM、数字孪生、智能装备需要统一软件底座

PPT 中提到的虚拟建造、BIM深化设计、4D施工模拟、施工过程数字测绘、VR安全教育、智能装备应用等方向，均需要一个底层平台承载数据和业务入口。

如果第一阶段不搭建统一的软件平台，后续各项能力可能继续形成新的数据孤岛。

因此，V1.0 阶段的平台建设应预留：

```text
BIM数据接入能力
AI视频事件接入能力
设备物联网数据接入能力
智能装备运行数据接入能力
项目进度与质量数据接入能力
```

------

# 四、建设目标

## 4.1 总体目标

建设一套面向建工多项目管理场景的智慧工地监管平台，实现项目现场的地图化、视频化、数据化、档案化和可追溯管理。

平台第一阶段目标是：

```text
以多项目监管为入口，
以视频监控为重点，
以人员安全和资料管理为基础，
以设备接入为扩展，
为后续智慧建造能力建设打底。
```

# 六、平台功能规划

## 6.1 项目地图定位

### 功能说明

通过接入百度地图，在系统中展示各项目地理位置。用户可在项目列表中选择项目，地图自动跳转至对应项目位置。

### 主要功能

- 百度地图接入；
- 项目经纬度管理；
- 项目 Marker 展示；
- 左侧项目选择联动地图；
- 项目信息弹窗；
- 项目状态颜色区分；
- 未配置定位项目提示；
- 支持后续按区域、状态、告警筛选。

### 建设价值

帮助管理方快速掌握项目地理分布，实现多项目可视化监管。

------

## 6.2 项目概况总览

### 功能说明

作为项目首页，展示当前项目基本信息、项目进度、视频摘要、资料摘要、人员安全摘要和设备摘要。

### 主要功能

- 项目基础信息；
- 项目阶段；
- 项目进度；
- 时间进度；
- 平台接入进度；
- 摄像头统计；
- 资料统计；
- 设备统计；
- 人员安全统计；
- 原有人员管理系统入口。

### 建设价值

让管理者在一个页面掌握项目核心状态。

------

## 6.3 视频监控与摄像头资源管理

### 功能说明

对项目现场摄像头进行统一登记、分类、管理和播放接入。

### 主要功能

- 摄像头新增、编辑、查询；
- 国标设备 ID 管理；
- 安装位置管理；
- 接入协议管理；
- 接入平台管理；
- 视频存储天数管理；
- 在线状态管理；
- 在线率统计；
- 视频播放地址获取；
- 1 / 4 / 8 / 16 路视频窗口展示；
- 视频访问日志。

### 摄像头重点字段

```text
国标设备ID
安装位置
接入协议
接入平台
存储天数
预估带宽
在线率
分辨率
编码格式
帧率
是否支持云台
是否支持巡航
是否支持夜视
```

### 建设价值

实现工地视频资源标准化管理，为后续接入 GB28181、海康、天翼视联、流媒体平台等提供基础。

------

## 6.4 人员与安全管理

### 功能说明

用于管理临时人员、安全三级教育、培训资料和签字文件。

### 主要功能

- 临时人员登记；
- 临时人员查询；
- 临时人员状态管理；
- 安全三级教育批次；
- 关联培训人员；
- 上传培训文件；
- 上传签字确认文件；
- 教育完成状态管理；
- 教育记录留档。

### 建设价值

解决施工现场临时人员和安全教育资料分散、纸质文件难追溯的问题。

------

## 6.5 资料管理

### 功能说明

用于管理项目资料、安全资料、会议纪要、施工日志、证书凭证等文件。

### 主要功能

- 文件上传；
- 文件分类；
- 文件查询；
- 文件下载；
- 文件删除；
- 文件归档；
- 文件状态管理；
- 文件与业务数据关联。

### 资料类型

```text
项目资料
安全培训资料
签字文件
证书文件
会议纪要
施工日志
其他资料
```

### 建设价值

实现资料留档、查询和追溯，为项目检查、验收和内部管理提供依据。

------

## 6.6 设备与塔吊管理

### 功能说明

对项目现场设备进行统一管理，并预留塔吊、人货梯、施工机器人等设备接入能力。

### 主要功能

- 设备列表；
- 设备详情；
- 设备状态；
- 塔吊接入预留；
- 状态记录；
- 异常统计；
- 后续智能装备数据接入预留。

### 建设价值

为后续机械可视化、设备监测、智能装备应用打基础。

# 十二、项目风险与控制建议

## 12.1 视频接入风险

风险：

```text
现场摄像头接入方式不统一
海康、GB28181、RTSP、天翼视联等方式不同
视频流网络条件不确定
```

控制方式：

```text
先做摄像头资源管理和播放地址接口
视频流不经过业务后端
通过 Adapter 方式适配不同视频平台
优先选择 1 个项目试点联调
```

------

## 12.2 现场数据不完整风险

风险：

```text
项目地址、经纬度、摄像头清单、国标ID、设备接口资料不完整
```

控制方式：

```text
建设前提供资料清单
先用测试数据跑通平台
试点项目逐步补齐真实数据
```

------

## 12.3 需求过大风险

风险：

```text
智慧建造范围过大
一期如果同时做 BIM、AI、机器人、数字孪生，容易失控
```

控制方式：

```text
一期聚焦智慧工地监管平台
二期再扩展高级能力
明确一期不做内容
```

------

## 12.4 第三方接口不稳定风险

风险：

```text
海康、塔吊、人员系统接口可能不稳定或暂未开放
```

控制方式：

```text
先使用 Mock 接口
正式接口确认后替换 Adapter
主系统与第三方接入层解耦
```

# 十四、总结建议

我方建议建工后续智慧建造业务落地，不应直接从“大而全”的智能建造平台开始，而应以 **智慧工地多项目监管平台 V1.0** 作为第一阶段建设抓手。

该平台能够优先解决项目现场管理中最现实的问题：

```text
多项目看不清
现场视频难统一
摄像头档案不完整
人员安全资料难追溯
设备状态不透明
项目资料分散
后续智能化能力缺少底座
```

通过先建设 V1.0 平台，建工可以快速形成：

```text
一个软件平台
一个试点项目
一套视频接入方案
一套项目数据模型
一套标准交付流程
一个智慧建造落地样板
```

后续再逐步扩展 BIM、数字孪生、AI 视频识别、智能装备数据接入等能力，形成更加完整的智慧建造全生命周期解决方案。
