

#  AI 应用方向说明

## 一、先明确：我们这里说的 AI 不是空概念

智慧大脑不是单独一个聊天机器人，也不是单独一个视频识别功能。

智慧化施工管理是“智慧大脑”中枢，要围绕工地“人、机、料、法、环”进行全方位、智能化管控；同时提出虚拟建造、智能装备运用，以及“感知—分析—决策—反馈”的管理闭环。

所以我们系统里的 AI，应该落在这些真实业务上：

```text
1. 帮人看视频
2. 帮人查项目
3. 帮人审资料
4. 帮人做合规检查
5. 帮人写日报周报
6. 帮人发现风险
7. 帮人生成整改建议
8. 帮人沉淀项目知识
9. 帮人分析设备与人员状态
10. 帮人辅助后续 BIM、智能装备、数字孪生扩展
```

这些功能都不是凭空编造，前提是系统里要有对应的数据来源，例如项目数据、摄像头数据、人员安全数据、资料文件、设备状态、视频截图、BIM 模型或智能装备数据。

# 二、AI 功能落地分级

## 第一类：一期就可以落地

这些不依赖复杂硬件，主要依赖系统已有数据、资料文件和大模型能力。

```text
1. AI项目问答助手
2. AI项目简报生成
3. AI资料识别与自动归档
4. AI视频接入合规检查
5. AI视频接入流程助手
6. AI摄像头在线率异常分析
7. AI风险提示与整改建议
8. AI知识库问答
```

## 第二类：二期可以落地

这些需要视频截图、视频流、视觉模型或第三方算法服务。

```text
1. AI视频截图巡查
2. AI安全帽识别
3. AI反光衣识别
4. AI危险区域闯入识别
5. AI烟火识别
6. AI摄像头画面异常检测
```

## 第三类：三期扩展能力

这些需要 BIM、智能装备、材料、环境、能耗等更多数据接入。

```text
1. AI+BIM模型问答
2. AI施工方案辅助分析
3. AI智能装备作业分析
4. AI设备调度建议
5. AI材料消耗分析
6. AI环境与能耗分析
7. AI多项目风险预测
```

**分阶段建设智慧大脑。**

# 三、AI项目问答助手

## 1. 这个功能能做什么

AI项目问答助手就是让用户不用一个个点菜单查数据，而是直接问系统。

用户可以问：

```text
XX项目现在有多少路摄像头？
哪些摄像头离线了？
XX项目视频接入是否合规？
哪些项目缺少危大工程作业区摄像头？
XX项目安全三级教育完成了吗？
今天上传了哪些资料？
哪个项目摄像头在线率低于80%？
帮我汇总一下本周异常项目。
```

AI 根据系统数据库和文件资料，自动回答。

## 2. 它替代了哪些人工工作

原来人工要做：

```text
打开项目页面
查看摄像头列表
查看在线率
查看资料列表
查看人员安全状态
手工汇总问题
再整理成文字
```

AI 可以直接完成数据查询和文字汇总。

## 3. 具体怎么落地

### 第一步：建立可查询的数据接口

后端需要有这些接口：

```text
项目列表接口
项目概况接口
摄像头列表接口
摄像头在线率接口
人员安全接口
资料列表接口
设备状态接口
视频接入合规接口
```

### 第二步：建立 AI 查询工具

AI 不能直接乱查数据库，应该通过后端封装好的接口查。

例如：

```text
queryProjectOverview(projectId)
queryCameraStatus(projectId)
querySafetyEducation(projectId)
queryFileList(projectId)
queryDeviceStatus(projectId)
```

### 第三步：大模型理解用户问题

用户问：

```text
XX项目的视频接入有没有问题？
```

AI 识别意图：

```text
查询项目
查询摄像头
查询点位
查询在线率
查询存储天数
生成合规结论
```

### 第四步：返回自然语言答案

输出类似：

```text
XX项目当前共配置3路摄像头，已覆盖人员出入口和塔吊/制高点，但尚未配置危大工程作业区摄像头。当前摄像头整体在线率为86%，符合不低于80%的要求。建议补充危大工程作业区摄像头后再进行接入验收。
```

## 4. 需要的数据

```text
项目表
摄像头资源表
视频接入流程表
在线率记录表
人员安全表
资料表
设备表
用户项目权限表
```

## 5. 注意事项

必须做权限控制。用户只能问自己有权限的项目，AI不能绕过系统权限。

# 五、AI资料识别与自动归档

## 1. 这个功能能做什么

用户上传资料后，AI 自动识别文件类型，并给出归档建议。

可以识别：

```text
安全三级教育资料
安全教育签字文件
证书文件
会议纪要
施工日志
视频接入资料
设备资料
验收资料
整改资料
项目方案文件
```

AI 可以自动提取：

```text
项目名称
文件标题
文件日期
涉及人员
培训时间
签字情况
资料类型
建议归档目录
摘要说明
```

## 2. 它替代了哪些人工工作

原来人工要做：

```text
下载文件
打开查看
判断是什么资料
手动分类
手动填写标题
手动写备注
再放入对应目录
```

AI 可以自动完成初步分类和摘要，人工只需确认。

## 3. 具体怎么落地

### 第一步：文件上传后触发AI识别

用户上传文件后，系统自动触发：

```text
OCR识别
文档解析
大模型分类
字段提取
摘要生成
```

### 第二步：建立资料分类规则

系统预置分类：

```text
PROJECT_DOC 项目资料
SAFETY_TRAINING 安全培训资料
SIGN_FILE 签字文件
CERTIFICATE 证书文件
MEETING_MINUTES 会议纪要
CONSTRUCTION_LOG 施工日志
VIDEO_ACCESS 视频接入资料
DEVICE_DOC 设备资料
OTHER 其他
```

### 第三步：AI生成归档建议

例如：

```text
文件类型：安全三级教育签字文件
关联项目：XX项目
培训日期：2026年X月X日
涉及人员：张三、李四、王五
建议归档目录：人员与安全 / 安全三级教育 / 签字文件
资料摘要：该文件为XX项目安全三级教育培训签到确认表。
风险提示：第3页签字区域不清晰，建议人工复核。
```

### 第四步：人工确认

前端展示：

```text
AI识别结果
AI归档建议
确认归档
修改分类
重新识别
```

## 4. 需要的数据

```text
文件资源表
OCR文本
项目名称
资料分类字典
人员名单
安全教育批次
```

## 5. 注意事项

AI不能直接替代最终资料审核。
系统应该设计成：

```text
AI识别 → 人工确认 → 正式归档
```

# 七、AI视频接入合规检查

## 1. 这个功能能做什么

根据上海施工现场视频监控文件，系统可以自动检查：

```text
项目是否属于应接入范围
是否配置人员出入口摄像头
是否配置塔吊/制高点摄像头
是否配置基坑或危大工程作业区摄像头
摄像头是否支持GB/T28181-2016
编码是否为H.264
分辨率和帧率是否达标
是否记录国标设备ID
是否绑定30天/90天云存储
设备在线率是否低于80%
是否填写监管平台设备编码
```

该文件明确要求基础点位覆盖人员出入口、塔吊/制高点、基坑及其他危大工程作业区，并规定一般项目存储1个月、市管项目存储3个月，设备在线率不得低于应运行天数的80%。

## 2. 它替代了哪些人工工作

原来人工要逐项翻台账、查配置、算在线率。

AI 可以自动生成：

```text
合规结论
缺失点位
不合规摄像头
低在线率设备
整改建议
```

## 3. 具体怎么落地

### 第一步：建立规则库

规则包括：

```text
人员出入口摄像头 >= 1
塔吊/制高点摄像头 >= 1
危大工程作业区摄像头 >= 1
online_rate >= 80
video_codec = H.264
fps >= 25
resolution >= 1080x720
storage_days = 30 或 90
gb_device_id 不为空
regulatory_device_code 已填写
```

### 第二步：系统自动执行规则判断

后端接口：

```text
GET /api/v1/video-access/compliance?projectId=xxx
```

系统返回：

```text
点位检查结果
设备参数检查结果
存储检查结果
在线率检查结果
监管平台编码检查结果
```

### 第三步：AI生成自然语言报告

规则负责判断，AI负责解释。

输出：

```text
当前项目视频接入状态为“部分合规”。已配置人员出入口和塔吊/制高点摄像头，但尚未配置危大工程作业区摄像头。当前整体在线率为78%，低于80%要求，建议优先排查离线摄像头网络和供电情况。
```

### 第四步：生成整改建议

AI自动输出：

```text
建议一：补充危大工程作业区摄像头；
建议二：检查2号塔吊摄像头网络连接；
建议三：补充监管平台设备编码填写截图；
建议四：确认云存储套餐是否为30天或90天。
```

## 4. 需要的数据

```text
project_info
camera_resource
video_access_process
camera_online_record
camera_compliance_check
file_resource
```

# 八、AI视频接入流程助手

## 1. 这个功能能做什么

这个功能专门针对文件里的复杂接入流程。

用户可以问：

```text
我现在已经拿到国标ID，下一步做什么？
摄像头已经绑定天翼视联了，后面还要填什么？
监管平台设备编码在哪里填写？
为什么要配置H.264？
这个项目视频接入还差哪一步？
```

AI 根据操作手册和系统当前流程状态回答。

文件中视频接入操作手册明确包含填写工地视频接入信息、选择现场接入或自行接入、使用天翼视联装维端、选择国标28181协议、获取平台配置信息、配置摄像机、记录国标ID、绑定云回看套餐、调试设备、填写监管平台设备编码等步骤。

## 2. 它替代了哪些人工工作

原来现场人员不会操作时，需要反复问技术人员。

AI 可以变成：

```text
接入流程说明员
操作步骤提醒员
资料缺失提示员
下一步引导员
```

## 3. 具体怎么落地

### 第一步：把操作手册做成知识库

导入：

```text
上海市施工现场视频监控通知
视频接入操作手册
公司内部操作说明
常见问题
```

### 第二步：建立流程状态表

系统记录：

```text
未申报
已填写接入信息
已选择接入方式
已获取平台配置
已配置GB28181
已绑定设备
已绑定云存套餐
已完成调试
已填写监管平台设备编码
已完成接入
```

### 第三步：AI结合流程状态回答

用户问：

```text
我现在完成了设备绑定，还要做什么？
```

AI 查当前状态后回答：

```text
下一步需要绑定视频云回看套餐，根据项目类型选择30天或90天云存储套餐。绑定完成后，需要点击已绑定设备进行实时视频调试，确认能够看到实时视频流。
```

### 第四步：前端做“AI下一步指引”

每个流程节点放一个按钮：

```text
AI告诉我下一步
```

## 4. 需要的数据

```text
视频接入操作手册知识库
video_access_process
camera_resource
project_info
file_resource
```

# 九、AI视频截图巡查说明

## 1. 这个功能能做什么

系统可以从摄像头画面中截取图片，然后由 AI 生成画面说明。

例如：

```text
画面显示为塔吊制高点视角，可见主体结构施工区域、材料堆放区及部分施工车辆。当前画面未发现明显烟火或大面积人员聚集，建议持续关注塔吊区域摄像头在线状态。
```

## 2. 它替代了哪些人工工作

人工原来要看视频、截图、写巡查记录。

AI 可以自动生成：

```text
巡查画面描述
重点区域说明
疑似异常提示
巡查记录初稿
```

## 3. 具体怎么落地

### 第一步：获取视频截图

方式可以是：

```text
前端播放器截图
视频平台截图接口
流媒体服务定时截图
人工上传截图
```

### 第二步：调用多模态AI分析图片

AI分析：

```text
场景类型
是否为人员出入口
是否为塔吊/制高点
是否为基坑区域
画面中可见内容
是否存在明显异常
```

### 第三步：生成巡查记录

输出：

```text
摄像头名称
截图时间
画面描述
风险提示
建议处理
```

### 第四步：人工确认归档

安全员确认后形成正式巡查记录。

## 4. 需要的数据

```text
摄像头截图
摄像头安装位置
项目名称
摄像头名称
巡查时间
```

## 5. 注意事项

一期建议做“截图分析”，不要一上来承诺全实时视频 AI 分析。
截图分析更容易落地，也更适合演示。

# 十、AI安全行为识别

## 1. 这个功能能做什么

AI可以识别现场安全行为问题：

```text
未戴安全帽
未穿反光背心
人员进入危险区域
基坑边异常停留
明火烟雾
高空作业异常
车辆人员混行
夜间异常活动
```

## 2. 这项功能怎么落地才真实

这里必须说清楚：
**安全帽、反光衣、人员闯入等实时识别，不建议完全依赖大语言模型。**

正确做法是：

```text
视频流/截图
→ 视觉识别模型
→ 生成结构化事件
→ 大模型总结事件和整改建议
```

视觉模型负责“看见”，大模型负责“解释和写报告”。

## 3. 具体怎么落地

### 第一步：接入视频截图或视频流

先从重点点位开始：

```text
人员出入口
塔吊/制高点
危大工程作业区
```

### 第二步：部署或采购视觉算法

算法包括：

```text
安全帽识别
反光衣识别
人员区域入侵
烟火识别
车辆识别
```

### 第三步：生成AI事件

数据表：

```text
video_ai_event
```

字段：

```text
项目ID
摄像头ID
事件类型
截图
识别结果
置信度
风险等级
处理状态
```

### 第四步：大模型生成说明

例如：

```text
系统检测到人员出入口画面中有1名人员疑似未佩戴安全帽，建议现场安全员核实并提醒整改。
```

### 第五步：人工确认和闭环

AI识别结果必须允许人工确认：

```text
有效
误报
已处理
无需处理
```

## 4. 需要的数据

```text
视频流或截图
视觉识别算法
摄像头点位信息
事件记录表
整改任务表
```

# 十一、AI摄像头在线率与画面异常分析

## 1. 这个功能能做什么

AI 可以分析摄像头运行问题：

```text
摄像头离线
在线率低于80%
画面黑屏
画面模糊
画面遮挡
画面冻结
长时间无变化
画面角度偏移
视频流频繁中断
```

## 2. 它替代了哪些人工工作

人工原来要一个个打开摄像头检查。

AI 可以自动输出：

```text
低在线率摄像头清单
疑似黑屏摄像头
疑似遮挡摄像头
连续离线摄像头
优先处理建议
```

## 3. 具体怎么落地

### 第一步：采集在线状态

通过视频平台、流媒体服务或定时探测记录：

```text
ONLINE
OFFLINE
UNKNOWN
```

### 第二步：计算在线率

```text
在线率 = 实际在线天数 / 应运行天数 × 100%
```

### 第三步：画面质量检测

通过定时截图判断：

```text
是否黑屏
是否过暗
是否模糊
是否遮挡
是否长时间无变化
```

这部分可以先用图像算法规则实现，后续再接AI多模态模型。

### 第四步：AI生成异常说明

例如：

```text
2号塔吊摄像头近7天在线率为72%，低于80%要求，且最近一次离线持续超过6小时。建议优先检查现场供电、网络链路和摄像头设备状态。
```

## 4. 需要的数据

```text
camera_online_record
camera_resource
视频截图
视频平台在线状态接口
```

```text

safety_education_batch
safety_education_person
file_resource
```

# 十三、AI设备与塔吊状态分析

## 1. 这个功能能做什么

针对塔吊、人货梯、施工设备，AI可以分析：

```text
设备是否离线
设备是否频繁告警
塔吊运行状态是否异常
设备维保是否到期
设备长时间未上报
多个项目设备风险排名
```

PPT 中提到了设备安全监测、机械可视化、设备智能调度管理，这部分可以作为设备与监控模块的 AI 扩展。

## 2. 具体怎么落地

### 第一步：先做设备台账

```text
设备编号
设备名称
设备类型
所属项目
厂商
状态
最近上报时间
```

### 第二步：接入设备状态

通过第三方塔吊系统或设备平台获取：

```text
运行中
停机
离线
告警
故障
```

### 第三步：AI分析异常

规则判断：

```text
超过N小时未上报
连续多次告警
维保日期超期
设备在线率下降
```


### 第四步：生成设备日报


# 十四、AI风险预警与整改建议

## 1. 这个功能能做什么

AI可以综合判断项目风险。

风险来源包括：

```text
摄像头缺失点位
在线率低于80%
人员未完成安全教育
资料缺失
设备离线
塔吊异常
视频接入流程未完成
项目进度滞后
环境数据异常
```

AI可以输出：

```text
项目风险等级
风险原因
整改优先级
整改建议
责任部门建议
整改期限建议
```

## 2. 它替代了哪些人工工作

原来管理人员要自己判断：

```text
哪个问题最严重
先处理哪个
谁来处理
怎么写整改通知
```

AI 可以自动生成初稿。

## 3. 具体怎么落地

### 第一步：建立风险指标库

例如：

```text
摄像头在线率低于80%：高风险
缺少危大工程摄像头：高风险
未教育人员进入项目：高风险
资料未归档：中风险
设备离线超过24小时：中高风险
```

### 第二步：计算项目风险分

系统按规则打分。

例如：

```text
低风险：0-40
中风险：41-70
高风险：71-100
```

### 第三步：AI解释风险原因

AI生成：

```text
当前项目风险等级为高，主要原因是视频点位不完整、塔吊摄像头在线率低于80%、部分临时人员未完成安全教育。
```

### 第四步：生成整改建议

输出：

```text
1. 补充危大工程作业区摄像头；
2. 排查塔吊摄像头网络；
3. 今日内完成3名临时人员安全教育；
4. 上传补充培训签字文件。
```

### 第五步：形成整改任务

人工确认后派发整改任务。

## 4. 需要的数据

```text
风险指标库
项目数据
摄像头数据
人员安全数据
资料数据
设备数据
整改任务表
```

## 1. 这个功能能做什么

### 第一类：制度规范类

```text

摄像头在线率要求是多少？
一般项目视频存储多少天？
市管项目视频存储多少天？
GB28181配置流程是什么？
```

### 第二类：系统操作类

```text
怎么新增摄像头？
怎么填写国标ID？
怎么上传安全教育签字文件？
怎么生成项目简报？
```

## 2. 具体怎么落地

### 第一步：建立知识库

导入：

```text
上海施工现场视频监控通知
视频接入操作手册
系统操作手册
项目管理制度
安全教育流程
内部常见问题
```

### 第二步：做RAG检索问答

技术链路：

```text
用户问题
→ 检索知识库
→ 找到相关文档片段
→ 大模型组织回答
→ 返回来源依据
```

### 第三步：回答要带来源

例如：

```text
根据《上海市住房和城乡建设管理委员会关于规范建设工程施工现场视频监控管理的通知》，基础点位应覆盖人员出入口、塔吊/制高点、基坑及其他危大工程作业区。
```

## 3. 需要的数据


# 二十、最重要的落地原则

```text
AI不是替代所有管理人员，而是替代重复性、统计性、整理性、初筛性的工作。
```

AI可以做：

```text
查数据
看资料
做摘要
做初筛
找异常
生成报告
给建议
```

AI不能直接替代：

```text
最终安全责任判断
重大隐患定性
监管平台正式申报
施工方案审批
最终验收结论
设备维修责任判断
```

所以系统设计应采用：

```text
AI分析
→ 人工确认
→ 任务派发
→ 整改反馈
→ 归档留痕
```
