# 智慧建造平台 AI 智慧大脑应用能力说明

## 一、建设定位

后续平台中的 AI 能力不应简单理解为一个聊天机器人，也不应只停留在单一的视频识别功能上，而应建设为面向项目现场管理的 **AI 智慧大脑**。

该智慧大脑应围绕建筑项目管理中的真实业务场景展开，重点服务于项目经理、安全员、资料员、施工员、质量员、机械员、劳务员、标准员、管理层等不同角色的日常工作内容。

建设思路：

```text
从岗位职责出发
→ 梳理日常工作内容
→ 找出重复性、统计性、整理性、提醒性工作
→ 接入系统已有数据
→ 由 AI 辅助分析、汇总、生成、提醒
→ 人工确认后形成业务闭环
```

AI 在系统中的定位不是替代项目岗位人员，而是作为岗位工作助手，辅助完成数据查询、资料整理、风险识别、报告生成、合规检查、整改建议、知识问答等工作。

#  **三、AI 通用应用能力设计**

## 3.1 AI 项目问答助手

### 能力说明

AI 项目问答助手用于帮助用户通过自然语言查询项目数据。用户无需逐个进入页面查找信息，可以直接向系统提问。

可支持的问题包括：

```text
XX项目有多少路摄像头？
哪些摄像头当前离线？
XX项目视频接入是否合规？
哪些项目缺少危大工程作业区摄像头？
XX项目安全三级教育完成情况如何？
今天上传了哪些资料？
哪个项目摄像头在线率低于80%？
本周有哪些项目存在异常？
```

### 可辅助的工作内容

该功能可辅助项目经理、安全员、资料员、管理层快速获取项目状态，减少反复查询页面、人工汇总数据的工作量。

### 落地实现

AI 不能直接连接数据库随意查询数据，而应通过后端封装好的接口获取数据。

后端需要提供 AI 专用查询接口，例如：

```text
queryProjectOverview(projectId)       查询项目概况
queryCameraStatus(projectId)          查询摄像头状态
querySafetyEducation(projectId)       查询安全教育情况
queryFileList(projectId)              查询资料情况
queryDeviceStatus(projectId)          查询设备状态
queryVideoCompliance(projectId)       查询视频接入合规情况
```

技术流程：

```text
用户提问
→ AI识别问题意图
→ 调用后端授权接口
→ 后端校验用户项目权限
→ 返回结构化数据
→ AI生成自然语言回答
```

### 数据依赖

```text
项目表
摄像头资源表
视频接入流程表
摄像头在线率表
人员与安全教育表
资料文件表
设备状态表
用户项目权限表
```

### 输出成果

```text
自然语言查询结果
项目状态摘要
异常数据说明
风险提示
处理建议
```

## 3.3 AI 资料识别与自动归档

### 能力说明

用户上传文件后，AI 自动识别文件类型，提取关键字段，生成资料摘要，并给出归档建议。

可识别资料类型包括：

```text
安全三级教育资料
安全教育签字文件
证书文件
会议纪要
施工日志
视频接入资料
设备资料
验收资料
整改资料
项目方案文件
材料合格证
检测报告
```

### 可辅助的工作内容

该功能主要辅助资料员、安全员、质量员、材料员进行资料整理、分类、摘要、归档和缺失检查。

### 落地实现

技术流程：

```text
文件上传
→ OCR识别
→ 文档解析
→ 大模型判断资料类型
→ 提取项目名称、日期、人员、标题等字段
→ 生成摘要
→ 给出归档目录建议
→ 人工确认归档
```

系统预置资料分类：

```text
PROJECT_DOC          项目资料
SAFETY_TRAINING      安全培训资料
SIGN_FILE            签字文件
CERTIFICATE          证书文件
MEETING_MINUTES      会议纪要
CONSTRUCTION_LOG     施工日志
VIDEO_ACCESS         视频接入资料
DEVICE_DOC           设备资料
MATERIAL_DOC         材料资料
OTHER                其他
```

### 输出示例

```text
文件类型：安全三级教育签字文件
关联项目：XX项目
文件日期：2026年5月13日
建议归档目录：人员与安全 / 安全三级教育 / 签字文件

风险提示：第2页签字区域较模糊，建议人工复核。
```

### 数据依赖

```text

OCR识别结果

资料分类字典
安全教育批次
人员名单
业务关联表
```

### 输出成果

```text

关键字段提取结果
归档建议
```

## 3.5 AI 视频接入合规检查

### 能力说明

AI 可结合视频接入规范、项目摄像头台账、在线率数据和视频接入流程，辅助检查项目视频监控是否满足要求。

系统可检查：

```text
项目是否属于应接入范围
是否配置人员出入口摄像头
是否配置塔吊/制高点摄像头
是否配置基坑或危大工程作业区摄像头
摄像头是否支持GB/T28181-2016
编码是否为H.264
分辨率和帧率是否达标
是否记录国标设备ID
是否绑定30天/90天云存储
设备在线率是否低于80%
是否填写监管平台设备编码
```

上海施工现场视频监控文件要求基础点位覆盖人员出入口、塔吊/制高点、基坑及其他危大工程作业区，并要求一般项目存储1个月、市管项目存储3个月，设备在线率不得低于应运行天数的80%。

### 可辅助的工作内容

该能力可辅助安全员、机械员、项目经理、管理层进行视频接入状态检查、问题识别和整改建议生成。

### 落地实现

先建立规则库：

```text
人员出入口摄像头 >= 1
塔吊/制高点摄像头 >= 1
危大工程作业区摄像头 >= 1
online_rate >= 80
video_codec = H.264
fps >= 25
resolution >= 1080x720
storage_days = 30 或 90
gb_device_id 不为空
regulatory_device_code 已填写
```

后端接口：

```text
GET /api/v1/video-access/compliance?projectId=xxx
```

规则引擎负责判断，AI负责生成自然语言报告和整改建议。

### 输出示例

```text
当前项目视频接入状态为“部分合规”。已配置人员出入口和塔吊/制高点摄像头，但尚未配置危大工程作业区摄像头。当前整体在线率为78%，低于80%要求，建议优先排查离线摄像头网络和供电情况。
```

### 数据依赖

```text
project_info
camera_resource
video_access_process
camera_online_record
camera_compliance_check
file_resource
```

### 输出成果

```text
视频接入合规结论
缺失点位清单
不合规摄像头清单
低在线率设备清单
整改建议
```

## 3.6 AI 视频接入流程助手

### 能力说明

视频接入流程涉及申报、绑定、GB28181配置、云存储套餐、调试、监管平台设备编码填写等多个步骤。AI 可结合操作手册和当前流程状态，辅助用户判断下一步应该做什么。

用户可提问：

```text
我现在已经拿到国标ID，下一步做什么？
摄像头已经绑定天翼视联了，后面还要填什么？
监管平台设备编码在哪里填写？
为什么要配置H.264？
这个项目视频接入还差哪一步？
```

### 可辅助的工作内容

该能力可辅助项目实施人员、设备接入人员、安全员、项目管理人员理解视频接入流程，减少反复沟通和操作遗漏。

### 落地实现

系统需建立视频接入流程状态：

```text
未申报
已填写接入信息
已选择接入方式
已获取平台配置
已配置GB28181
已绑定设备
已绑定云存套餐
已完成调试
已填写监管平台设备编码
已完成接入
```

技术流程：

```text
导入视频接入操作手册
→ 建立知识库
→ 记录项目当前接入状态
→ 用户提问或点击“AI下一步指引”
→ AI结合知识库和流程状态生成操作建议
```

### 数据依赖

```text
视频接入操作手册
video_access_process
camera_resource
project_info
file_resource
```

### 输出成果

```text
下一步操作提示

操作说明

接入完成度说明
```

# 五、系统落地支撑机制

## 5.1 AI 不直接访问数据库

AI 查询项目数据时，不应直接连接数据库，也不应自行生成 SQL 查询。

正确方式是：

```text
用户提问
→ AI识别意图
→ 调用后端授权接口
→ 后端校验用户权限
→ 后端返回必要数据
→ AI生成回答
```

这样可以保证：

```text
用户权限可控
项目数据隔离
敏感字段不暴露
数据库安全稳定
AI回答有数据来源
```

------

## 5.2 AI 输出必须保留人工确认机制

系统设计应采用：

```text
AI分析
→ 人工确认
→ 任务派发
→ 整改反馈
→ 归档留痕
```

AI 可辅助：

```text
查询数据
整理资料
生成摘要
初步识别异常
生成报告
提出建议
```

关键事项仍需人工确认：

```text
安全责任判断
重大隐患定性
监管平台正式申报
施工方案审批
最终验收结论
设备维修责任判断
```

------

## 5.3 AI 能力应嵌入业务流程

 AI 不单独做成孤立功能，而是嵌入现有业务页面：

```text
项目概况页：AI项目简报、AI风险分析
设备与监控页：AI视频合规检查、AI摄像头异常分析
人员与安全页：AI安全教育检查、AI安全日报
资料管理页：AI资料识别、AI归档建议
地图大屏页：AI多项目风险摘要
管理驾驶舱：AI领导汇报、AI督办建议
```

这样 AI 才能真正服务业务，而不是停留在展示层面。

# 六、总体汇报口径

后续平台中的 AI 能力，按照“智慧大脑 + 岗位助手”的方式建设。

智慧大脑负责统一接入项目、视频、人员、安全、资料、设备、BIM、智能装备等多源数据；岗位助手负责把这些能力落实到项目经理、安全员、资料员、施工员、质量员、机械员、劳务员、标准员和管理层的实际工作场景中。

通过这种方式，平台未来可以逐步具备：

```text
能问
能查
能总结
能检查
能提醒
能分析
能生成报告
能提出整改建议
能沉淀项目知识
能辅助多项目管理决策
```

最终形成以项目现场数据为基础、以 AI 分析为支撑、以岗位工作流为落点、以管理闭环为目标的智慧建造 AI 智慧大脑。
