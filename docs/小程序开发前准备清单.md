## 二、微信侧准备

开发前需由项目方提供或确认：

- 微信小程序 AppID。
- 小程序管理员和开发者账号权限。
- 微信开发者工具可登录账号。
- 服务器域名白名单：
  - request 合法域名
  - uploadFile 合法域名
  - downloadFile 合法域名
- 小程序隐私协议内容。
- 小程序服务类目。
- 相机、相册、扫码权限说明。
- 是否需要订阅消息模板。
- 订阅消息模板内容，若启用：
  - 待复核提醒
  - 待整改提醒
  - 整改逾期提醒
  - 复查退回提醒

首版建议不强依赖订阅消息审核结果。站内“我的待办”为必做，微信订阅消息作为增强。

## 三、本地开发环境

当前 Web/后端默认地址：

```text
后端：http://localhost:8080
前端：http://localhost:3002
接口文档：http://localhost:8080/doc.html
```

小程序工程建议目录：

```text
wechat-miniprogram/
  site-platform-miniprogram/
```

建议环境变量：

```text
VITE_API_BASE_URL=/api/v1
VITE_UPLOAD_MAX_SIZE_MB=20
```

当前工程按运行端拆分接口地址：H5 真实联调默认使用相对 `/api/v1` 和 Vite 同源代理，不依赖本地 `.env.real`；微信开发者工具使用 `.env.mp-real` 中的绝对地址。微信 `wx.request` 不接受 `/api/v1` 这类相对 URL，真机和生产环境必须配置合法 HTTPS 绝对地址。

本地联调注意：

- 微信开发者工具需开启“不校验合法域名”用于本地调试。
- 生产环境不能使用 localhost。
- token 存储使用小程序本地存储，不使用浏览器 localStorage。
- 小程序请求封装必须检查业务 `code`，不能只看 HTTP 状态。
- 文件下载接口返回文件流，不走统一 `Result<T>`。

## 四、后端准备

开发现场检查模块前必须先处理或明确：

1. `ProjectPermissionService.getUserProjects` 应真正查询 `sys_user_project`。
2. 非项目模块的项目权限校验规则应统一，尤其是文件下载、文件删除和附件读取。
3. 文件上传接口应明确 `projectId` 必填。
4. 检查记录附件复用 `file_resource`，并约定：
   - `businessType=inspection_record`
   - `businessType=inspection_rectification`
   - `fileType=inspection_outer_photo`
   - `fileType=inspection_inner_photo`
   - `fileType=inspection_problem_photo`
   - `fileType=inspection_rectification_photo`
5. 检查导出接口如果返回文件流，应与现有下载接口一样不使用 `Result<T>`。
6. 新增电箱台账和检查接口时，必须以后端 token 写入检查人、复核人、整改反馈人。
7. 所有包含 `projectId`、`electricBoxId`、检查记录 ID、整改 ID 的接口都要反查项目并校验权限。

## 五、数据库准备

现场检查模块计划新增表：

- `electric_box`
- `inspection_template`
- `inspection_template_item`
- `inspection_record`
- `inspection_record_item`
- `inspection_rectification`

实施前准备：

- 编写增量 SQL，不直接执行带 `DROP TABLE` 的 `init.sql`。
- 当前为开发阶段，如用户确认执行，可直接更新开发库。
- 初始化电箱检查模板 `ELECTRIC_BOX_DAILY`。
- 初始化六个检查项：内外观、漏电保护器、熔断、保护接零、220V 插座、380V 插座。
- 准备电箱台账测试数据。
- 准备测试项目、测试用户、角色和项目授权。
- 明确逻辑删除字段 `deleted` 和审计字段命名。

建议唯一性：

- `electric_box`: 同一项目内 `box_code` 唯一。
- `electric_box`: 同一项目内 `qr_code` 唯一。
- `inspection_record`: 同一项目、同一电箱、同一模板、同一日期、`source=ELECTRICIAN_DAILY` 只允许一条有效记录。

## 六、电箱与二维码准备

项目现场需要提前准备：

- 试点项目电箱总数。
- 每个电箱的编号。
- 每个电箱的安装位置。
- 每个电箱的负责电工。
- 每个项目的安全负责人或复核安全员。
- 电箱启用或停用状态。
- 二维码贴纸尺寸、材质和张贴位置。
- 二维码编码规则。
- 二维码补打流程。
- 电箱拆除、停用、换绑流程。

建议电箱编号示例：

```text
EB-001
EB-002
```

建议二维码编码只作为随机或规则编码，不直接暴露用户身份、权限和敏感业务字段。

## 七、测试数据准备

### 7.1 用户与角色

至少准备：

| 用户类型 | 角色 | 用途 |
| --- | --- | --- |
| 平台管理员 | `PLATFORM_ADMIN` | 验证所有项目查看、台账和导出 |
| 项目管理员 | `PROJECT_ADMIN` | 验证授权项目管理 |
| 安全管理员 | `SAFETY_ADMIN` | 验证电箱台账、复核、抽查和整改关闭 |
| 负责电工 | `USER` 或项目授权用户 | 验证扫码日检和整改反馈 |
| 普通用户 | `USER` | 验证只读和越权拦截 |

### 7.2 项目数据

至少准备两个项目：

- 项目 A：授权给项目管理员、安全管理员、负责电工和普通用户。
- 项目 B：不授权给普通用户，用于验证越权访问被拒绝。

### 7.3 电箱台账

项目 A 至少准备：

| 电箱 | 场景 |
| --- | --- |
| `EB-001` | 正常启用，有负责电工 |
| `EB-002` | 启用，存在异常巡检 |
| `EB-003` | 启用，存在漏检 |
| `EB-004` | 停用，用于验证扫码不可巡检 |

### 7.4 检查模板

电箱检查模板：

| 检查项 | 字段编码 | 是否必填 |
| --- | --- | --- |
| 内外观 | `APPEARANCE` | 是 |
| 漏电保护器 | `LEAKAGE_PROTECTOR` | 是 |
| 熔断 | `FUSE` | 是 |
| 保护接零 | `PROTECTIVE_ZERO` | 是 |
| 220V插座 | `SOCKET_220V` | 是 |
| 380V插座 | `SOCKET_380V` | 是 |

### 7.5 流程数据

需要覆盖：

- 正常电工日检。
- 复核通过记录。
- 复核退回记录。
- 复核转整改记录。
- 安全员现场抽查生成整改。
- 待整改任务。
- 已整改待复查任务。
- 复查退回任务。
- 已关闭整改任务。
- 逾期整改任务。
- 月度导出数据。

## 九、导出准备

需要提前确认：

- 导出文件名规则。
- Excel 标题、字体、边框和页边距。
- 汇总 Sheet 字段。
- 每个电箱明细 Sheet 的命名规则。
- 无记录日期显示方式，首版固定为 `未检`。
- 异常项显示方式，首版固定为 `异常`。
- 附件照片是否需要单独清单，首版不嵌入主表。
- 导出接口是否由 Web 后台触发，或小程序也允许触发下载。

首版默认：

- 一个项目一个月一个工作簿。
- 一个“巡检汇总”Sheet。
- 每个电箱一个明细 Sheet。
- 普通用户不可导出。

## 十二、风险与待确认

- 当前后端项目权限仍有开发期简化逻辑，需在小程序上线前修复。
- 当前非项目模块大多未严格校验 `projectId`，新增检查模块不能沿用这个缺口。
- 当前没有数据库迁移体系，新增表必须使用增量 SQL 留档。
- 二维码是否支持外部检查免登录查看汇总，需要业务确认。
- 微信订阅消息不应作为首版闭环的唯一提醒方式。
- 月度导出首版已确定 Excel 优先，如仍需 Word/PDF 需另行排期。
- 电箱二维码换绑留痕如果要强审计，可能需要新增二维码操作日志表。
- 如果后续接入微信手机号或企业微信，需要新增用户绑定设计。
