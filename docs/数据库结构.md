## 2026-07-29 小程序微信快捷注册与首次密码设置

在既有 RBAC 和跨端业务模块迁移之后，追加执行以下可重复检查脚本：

```text
backend/src/main/resources/sql/migrations/20260729_wechat_quick_registration_initial_password.sql
```

脚本仅为 `registration_application` 新增非空 `registration_mode`，默认值为 `STANDARD`，并将历史空值补为 `STANDARD`；不会重建表、覆盖审批结果或执行 `init.sql`。新值包括：

- `STANDARD`：原 Web/小程序标准注册，审批前保存 BCrypt 密码摘要；
- `WECHAT_QUICK`：只允许小程序的微信快捷注册，审批前不保存用户密码。

快捷注册批准时仍写入 `sys_user.password` 的随机 BCrypt 占位摘要，以适配非空列；同时设置 `password_login_enabled=0`、`password_reset_required=1`。首次微信登录必须调用 `/auth/initial-password` 设置强密码，完成后才启用账号密码登录并递增 `credential_version`。该状态不额外增加用户表字段，两个既有认证字段的组合即为唯一业务含义。

当前本地 `dianxinyun` 已在备份后连续执行两次并验证通过：表数保持 47，`registration_mode` 为 `VARCHAR(30) NOT NULL DEFAULT 'STANDARD'`，历史空值为 0。迁移前备份为 `backups/development/dianxinyun-before-wechat-quick-registration-20260729_150000.sql`，SHA-256 为 `b9750dd54c76ea3d2cbe5eebc3436ca1f0cc514f2986f6a9a6dd5452cb3c1c1c`；未执行 `init.sql`。

## 2026-07-28 统一注册与 RBAC 增量结构（前置迁移）

本轮唯一允许执行的数据库脚本是：

```text
backend/src/main/resources/sql/migrations/20260728_unified_registration_rbac_wechat_login.sql
```

该脚本为可重复检查的增量迁移，已先在数据库副本连续演练，并于 2026-07-29 应用到当前本地 `dianxinyun`。数据库由 39 张表升级为 45 张表，新增以下 6 张表：

| 新表 | 用途 |
| --- | --- |
| `registration_application` | Web/小程序统一账号注册申请、审批、随机状态令牌及待审批账号/手机号占用 |
| `sys_menu` | Web/小程序菜单、目录和功能资源 |
| `sys_permission` | 后端接口与页面操作权限码 |
| `sys_role_menu` | 角色与菜单关联 |
| `sys_role_permission` | 角色与操作权限关联 |
| `sys_data_migration` | 记录一次性数据种子版本，防止重复执行迁移时恢复管理员已撤销的授权或启用状态 |

迁移同时执行以下兼容扩展：

- `sys_user` 新增 `credential_version` 和 `password_reset_required`；非 BCrypt 历史密码标记为待重置。
- `sys_role` 新增 `scope_type`、`builtin`、`enabled`，并以 `role_code + scope_type + deleted` 区分平台角色和项目角色。
- `sys_user_wechat_binding` 新增仅对有效绑定生成的 `active_unionid` 及 `(app_id, active_unionid)` 唯一索引；结合既有用户/OpenID 约束和服务层冲突校验，保证同一 AppID 下系统用户、OpenID、UnionID 的有效绑定一对一。
- `wechat_access_application` 新增待审批生成列 `pending_access_key` 和唯一索引；历史重复待审批记录保留最新一条，其余转为 `CANCELLED`，审批时服务层再使用行锁防止批准/驳回并发覆盖。
- `sys_user_role` 增加 `user_id + role_id` 唯一索引；角色菜单和角色权限表也使用联合唯一约束，防止重复授权。
- 脚本首次写入资料、巡检、质量、系统管理菜单与权限种子，并将当前平台管理员映射为全菜单、全操作权限；种子版本落入 `sys_data_migration`，后续重跑只补结构和缺失目录，不恢复已撤权/停用配置。现有项目职责继续由 `sys_user_project.project_role_code` 兼容。

`registration_application.status` 只允许业务状态 `PENDING / APPROVED / REJECTED / CANCELLED`。结构化项目意向保存在 `desired_project_ids`，Web 无法确定项目 ID 时填写的项目名称/说明保存在 `desired_project_text`。申请提交时保存 BCrypt 摘要而不创建账号；批准、驳回或申请人取消后必须清除 `password_hash`。待审批唯一列 `pending_username`、`pending_phone`、`pending_wechat_key` 只在 `PENDING` 时生成，处理完成后自动释放占用，允许用户重新申请。

严禁在现有库执行 `backend/src/main/resources/sql/init.sql`：该兼容入口当前会立即中止，
不能替代增量迁移。旧 35 表建库内容已移入仅供受保护空库工具读取的基线模板，模板不含
`DROP TABLE / DROP DATABASE`，也不得人工直接执行。其他仍停留在旧基线的环境应用
增量脚本前仍需备份，并核对旧角色、微信绑定、项目授权及现有业务表记录；最终执行结果
以交付验证记录为准。

迁移前至少执行以下预检；任一重复结果非空时应先人工核对，不能直接创建唯一索引：

```sql
-- 有效用户手机号必须唯一
SELECT phone, COUNT(*) AS duplicate_count
FROM sys_user
WHERE deleted = 0 AND phone IS NOT NULL AND phone <> ''
GROUP BY phone
HAVING COUNT(*) > 1;

-- 同一 AppID 下有效 UnionID 必须唯一
SELECT app_id, unionid, COUNT(*) AS duplicate_count
FROM sys_user_wechat_binding
WHERE deleted = 0 AND status = 'ACTIVE'
  AND unionid IS NOT NULL AND unionid <> ''
GROUP BY app_id, unionid
HAVING COUNT(*) > 1;

-- 上线前必须至少保留一个可用 BCrypt 平台管理员
SELECT u.id, u.username
FROM sys_user u
JOIN sys_user_role ur ON ur.user_id = u.id
JOIN sys_role r ON r.id = ur.role_id
WHERE u.status = 1 AND u.deleted = 0
  AND u.password_login_enabled = 1
  AND u.password REGEXP '^[$]2[aby][$][0-9]{2}[$].{53}$'
  AND r.role_code = 'PLATFORM_ADMIN';
```

同时记录迁移前后的平台角色、`sys_user_project` 项目授权及有效微信绑定数量。若管理员密码属于历史非 BCrypt 凭证，迁移后必须通过 `ADMIN_RESET_USERNAME`、`ADMIN_RESET_PASSWORD` 显式重置，再移除变量。

## 数据库概览

默认数据库名：`dianxinyun`。

空库初始化入口：`scripts/init-empty-database.sh`。

重要提醒：`backend/src/main/resources/sql/init.sql` 已禁用，直接执行会立即中止。空库工具
要求 `DIANXINYUN_INIT_CONFIRM=CREATE_EMPTY_DATABASE_ONLY:{数据库名}`，且目标库必须为
0 张表；基线模板不包含 `DROP TABLE / DROP DATABASE`。生产或长期开发库新增字段只使用
增量 SQL。

MyBatis-Plus 配置：

- 下划线转驼峰：`map-underscore-to-camel-case: true`
- 逻辑删除字段：`deleted`
- 未删除值：`0`
- 删除值：`1`

当前没有显式外键约束，表之间通过业务字段关联。

## 表结构说明

### project_info

用途：保存项目基础资料、施工信息、状态、地图定位。

关键字段：

- `id`: 项目 ID。
- `project_name`: 项目名称，必填。
- `short_name`: 项目简称。
- `area`: 建筑面积。
- `period`: 工期文本。
- `phase`: 当前阶段。
- `project_status`: 项目状态，当前常见值 `normal`、`warning`、`danger`、`stopped`。
- `safety_goal`: 安全目标。
- `quality_goal`: 质量目标。
- `manager`: 项目经理。
- `contractor`: 施工单位。
- `description`: 项目描述。
- `start_date`, `end_date`: 项目起止日期，用于前端计算进度。
- `longitude`, `latitude`: 经度和纬度。
- `province`, `city`, `district`, `address`: 地址信息。
- `coordinate_type`: 坐标系，当前支持 `BD09`、`GCJ02`、`WGS84`，默认 `BD09`。
- `deleted`: 逻辑删除。
- `create_time`, `update_time`: 创建和更新时间。

关联关系：

- `project_info.id` 被多数业务表的 `project_id` 引用。
- 项目定位更新会写 `sys_operation_log.business_type = PROJECT`、`business_id = project_id`。
- 项目定位与审计日志在同一事务写入，任一步未影响恰好 1 行时整体回滚。

不允许随意修改：

- `id`
- `deleted`
- `longitude` / `latitude` 精度规则
- `coordinate_type` 枚举
- `project_status` 的业务枚举，需要先统一前后端字典

写入边界：项目名称 200 字符且必填；简称/面积/阶段/项目经理 50，工期 100，安全目标、
质量目标、施工单位 200，项目描述 5000，省/市/区各 64，地址 500。项目状态只允许
`normal / warning / danger / stopped`，截止日期不能早于开工日期。新增和通用更新不接受
客户端主键、删除标记或创建时间。

### sys_user

用途：用户账号。

关键字段：

- `id`: 用户 ID。
- `username`: 用户名，唯一。
- `password`: BCrypt 密码摘要，不保存明文。

  检查重复，避免并发请求同时通过；冲突或任一步单记录写入未生效时返回 HTTP `409` 并
  回滚。
- 新巡检提交后直接完成，不再分配复核人、写复核日志或生成复核/整改待办。

## 新增字段规则

新增字段必须遵守：

1. 先确认业务含义和所属表。
2. 优先写增量 SQL，不要直接要求执行 `init.sql`。
3. 字段名使用 snake_case，Java 属性使用 camelCase。
4. 需要默认值时明确历史数据如何回填。
5. 涉及状态、类型、权限的字段必须同步更新前端字典。
6. 涉及用户或项目的数据必须考虑权限隔离。
7. 修改后同步更新本文件和 `docs/接口规则.md`。

- 各表 `id`
- 各表 `project_id`

- `sys_user.username`
