# 数据库结构

## 2026-07-28 统一注册与 RBAC 增量结构

本轮唯一允许执行的数据库脚本是：

```text
backend/src/main/resources/sql/migrations/20260728_unified_registration_rbac_wechat_login.sql
```

该脚本为可重复检查的增量迁移，当前仅在数据库副本上连续演练，尚未应用到正式本地 `dianxinyun`。因此正式本地库当前仍为 39 张表；应用后新增以下 6 张表，表数变为 45：

| 新表 | 用途 |
| --- | --- |
| `registration_application` | Web/小程序统一账号注册申请、审批、随机状态令牌及待审批账号/手机号占用 |
| `sys_menu` | Web/小程序菜单、目录和功能资源 |
| `sys_permission` | 后端接口与页面操作权限码 |
| `sys_role_menu` | 角色与菜单关联 |
| `sys_role_permission` | 角色与操作权限关联 |
| `sys_data_migration` | 记录一次性数据种子版本，防止重复执行迁移时恢复管理员已撤销的授权或启用状态 |

迁移同时执行以下兼容扩展：

- `sys_user` 新增 `credential_version` 和 `password_reset_required`；非 BCrypt 历史密码标记为待重置。
- `sys_role` 新增 `scope_type`、`builtin`、`enabled`，并以 `role_code + scope_type + deleted` 区分平台角色和项目角色。
- `sys_user_wechat_binding` 新增仅对有效绑定生成的 `active_unionid` 及 `(app_id, active_unionid)` 唯一索引；结合既有用户/OpenID 约束和服务层冲突校验，保证同一 AppID 下系统用户、OpenID、UnionID 的有效绑定一对一。
- `wechat_access_application` 新增待审批生成列 `pending_access_key` 和唯一索引；历史重复待审批记录保留最新一条，其余转为 `CANCELLED`，审批时服务层再使用行锁防止批准/驳回并发覆盖。
- `sys_user_role` 增加 `user_id + role_id` 唯一索引；角色菜单和角色权限表也使用联合唯一约束，防止重复授权。
- 脚本首次写入资料、巡检、质量、系统管理菜单与权限种子，并将当前平台管理员映射为全菜单、全操作权限；种子版本落入 `sys_data_migration`，后续重跑只补结构和缺失目录，不恢复已撤权/停用配置。现有项目职责继续由 `sys_user_project.project_role_code` 兼容。

`registration_application.status` 只允许业务状态 `PENDING / APPROVED / REJECTED / CANCELLED`。结构化项目意向保存在 `desired_project_ids`，Web 无法确定项目 ID 时填写的项目名称/说明保存在 `desired_project_text`。申请提交时保存 BCrypt 摘要而不创建账号；批准、驳回或申请人取消后必须清除 `password_hash`。待审批唯一列 `pending_username`、`pending_phone`、`pending_wechat_key` 只在 `PENDING` 时生成，处理完成后自动释放占用，允许用户重新申请。

严禁在现有库执行 `backend/src/main/resources/sql/init.sql`：该文件包含 `DROP TABLE`，不能替代本轮迁移。正式本地库应用增量脚本前仍需备份，并核对旧角色、微信绑定、项目授权及现有业务表记录；最终执行结果以交付验证记录为准。

迁移前至少执行以下预检；任一重复结果非空时应先人工核对，不能直接创建唯一索引：

```sql
-- 有效用户手机号必须唯一
SELECT phone, COUNT(*) AS duplicate_count
FROM sys_user
WHERE deleted = 0 AND phone IS NOT NULL AND phone <> ''
GROUP BY phone
HAVING COUNT(*) > 1;

-- 同一 AppID 下有效 UnionID 必须唯一
SELECT app_id, unionid, COUNT(*) AS duplicate_count
FROM sys_user_wechat_binding
WHERE deleted = 0 AND status = 'ACTIVE'
  AND unionid IS NOT NULL AND unionid <> ''
GROUP BY app_id, unionid
HAVING COUNT(*) > 1;

-- 上线前必须至少保留一个可用 BCrypt 平台管理员
SELECT u.id, u.username
FROM sys_user u
JOIN sys_user_role ur ON ur.user_id = u.id
JOIN sys_role r ON r.id = ur.role_id
WHERE u.status = 1 AND u.deleted = 0
  AND u.password_login_enabled = 1
  AND u.password REGEXP '^[$]2[aby][$][0-9]{2}[$].{53}$'
  AND r.role_code = 'PLATFORM_ADMIN';
```

同时记录迁移前后的平台角色、`sys_user_project` 项目授权及有效微信绑定数量。若管理员密码属于历史非 BCrypt 凭证，迁移后必须通过 `ADMIN_RESET_USERNAME`、`ADMIN_RESET_PASSWORD` 显式重置，再移除变量。

## 数据库概览

默认数据库名：`dianxinyun`。

初始化脚本：`backend/src/main/resources/sql/init.sql`。

重要提醒：`init.sql` 包含 `DROP TABLE IF EXISTS`，执行会删除并重建同名表。不要在已有数据环境直接执行。生产或长期开发库新增字段应使用增量 SQL。

MyBatis-Plus 配置：

- 下划线转驼峰：`map-underscore-to-camel-case: true`
- 逻辑删除字段：`deleted`
- 未删除值：`0`
- 删除值：`1`

当前没有显式外键约束，表之间通过业务字段关联。

## 表结构说明

### project_info

用途：保存项目基础资料、施工信息、状态、地图定位。

关键字段：

- `id`: 项目 ID。
- `project_name`: 项目名称，必填。
- `short_name`: 项目简称。
- `area`: 建筑面积。
- `period`: 工期文本。
- `phase`: 当前阶段。
- `project_status`: 项目状态，当前常见值 `normal`、`warning`、`danger`、`stopped`。
- `safety_goal`: 安全目标。
- `quality_goal`: 质量目标。
- `manager`: 项目经理。
- `contractor`: 施工单位。
- `description`: 项目描述。
- `start_date`, `end_date`: 项目起止日期，用于前端计算进度。
- `longitude`, `latitude`: 经度和纬度。
- `province`, `city`, `district`, `address`: 地址信息。
- `coordinate_type`: 坐标系，当前支持 `BD09`、`GCJ02`、`WGS84`，默认 `BD09`。
- `deleted`: 逻辑删除。
- `create_time`, `update_time`: 创建和更新时间。

关联关系：

- `project_info.id` 被多数业务表的 `project_id` 引用。
- 项目定位更新会写 `sys_operation_log.business_type = PROJECT`、`business_id = project_id`。

不允许随意修改：

- `id`
- `deleted`
- `longitude` / `latitude` 精度规则
- `coordinate_type` 枚举
- `project_status` 的业务枚举，需要先统一前后端字典

### sys_user

用途：用户账号。

关键字段：

- `id`: 用户 ID。
- `username`: 用户名，唯一。
- `password`: BCrypt 密码摘要，不保存明文。
- `password_login_enabled`: 是否允许账号密码登录。
- `credential_version`: 凭证版本，改密和关键认证变化时递增，使旧 JWT 失效。
- `password_reset_required`: 是否必须由管理员重置密码。
- `real_name`: 真实姓名。
- `phone`, `email`: 联系方式。
- `status`: `0` 禁用，`1` 启用。
- `deleted`: 逻辑删除。

关联关系：

- `sys_user_role.user_id`
- `sys_user_project.user_id`
- `file_resource.uploader_id`
- `sys_operation_log.user_id`
- `video_access_log.user_id`

注意：

- `password_login_enabled=0` 的账号只能通过已绑定微信身份登录；统一注册审批创建的账号默认启用密码登录。
- 迁移会将非 BCrypt 历史密码标记为 `password_reset_required=1`，登录入口强制拒绝，直到管理员显式重置为有效 BCrypt。
- 不要在接口中返回密码，当前 `/auth/user-info` 会将 `password` 置空。

### sys_role

用途：角色字典。

关键字段：

- `role_name`: 角色名称。
- `role_code`: 角色编码，当前种子数据包括：
  - `PLATFORM_ADMIN`
  - `PROJECT_ADMIN`
  - `SAFETY_ADMIN`
  - `USER`

不允许随意修改：

- `role_code`，因为权限代码通过它判断角色。

### sys_user_role

用途：用户与角色多对多关系。

关键字段：

- `user_id`
- `role_id`

当前代码：

- `SysUserMapper.selectRoleCodesByUserId(userId)` 通过本表查询角色编码。

### sys_user_project

用途：用户可访问项目关系、兼容项目职责和电箱巡检权限模板绑定。

关键字段：

- `user_id`
- `project_id`
- `project_role_code`: 兼容保留的项目内职责，当前枚举 `PROJECT_ADMIN`、`SAFETY_ADMIN`、`USER`，默认 `USER`。
- `inspection_permission_template_id`: 当前用户在该项目内绑定的电箱巡检权限模板 ID。
- `status`: 项目访问状态，`ACTIVE` 表示授权生效，`DISABLED` 表示暂停访问。
- `status_reason`: 暂停原因或最近一次状态变更原因。
- `status_changed_by`, `status_changed_time`: 最近一次项目访问状态操作人和时间。
- `create_time`, `update_time`: 创建和更新时间。

约束和索引：

- `uk_sys_user_project_user_project (user_id, project_id)`，确保同一用户在同一项目只有一条授权记录。
- `idx_sys_user_project_permission_template (inspection_permission_template_id)`，用于按模板关联授权查询。
- `idx_sys_user_project_status (project_id, status)`，用于项目成员和权限查询过滤暂停成员。

当前状态：

- `ProjectPermissionService.getUserProjects` 已改为查询本表。
- 项目成员/权限模板接口新增、修改、移除成员后会清理 Redis 缓存 `user:projects:{userId}`。
- 本地开发库已执行增量脚本 `backend/src/main/resources/sql/migrations/20260701_inspection_project_roles.sql`。
- 新增电箱巡检权限模板增量脚本 `backend/src/main/resources/sql/migrations/20260701_inspection_permission_templates.sql`，目标环境需执行，不要用 `init.sql` 替代。
- 新增微信用户与项目访问状态增量脚本 `backend/src/main/resources/sql/migrations/20260712_wechat_user_permission_management.sql`。该脚本补充 `password_login_enabled`、项目访问状态字段、有效微信绑定唯一约束，并将内置权限模板收口到当前极简巡检权限目录；本地开发库已执行。

### inspection_permission_template

用途：保存平台管理员维护的电箱巡检权限模板。项目成员通过 `sys_user_project.inspection_permission_template_id` 绑定模板后，在每个项目内获得对应权限码集合。

来源脚本：`backend/src/main/resources/sql/migrations/20260701_inspection_permission_templates.sql`。

关键字段：

- `template_name`: 模板名称，例如“项目管理员”“安全管理员”“项目成员/负责电工”。
- `template_code`: 模板编码，全局唯一。
- `description`: 模板说明。
- `permission_codes`: 逗号分隔的权限码集合。
- `enabled`: 是否启用。
- `builtin`: 是否内置模板。
- `create_time`, `update_time`: 创建和更新时间。

当前内置模板：

- `PROJECT_ADMIN`: 项目管理员，拥有台账、二维码、公开访问、巡检、记录、汇总、导出和成员授权权限。
- `SAFETY_ADMIN`: 巡检记录管理员，拥有台账查看、二维码、公开访问、记录、汇总和导出权限。
- `USER`: 巡检员，拥有日检提交和项目巡检记录查看权限。

### sys_user_wechat_binding

用途：保存系统账号与指定小程序 AppID 下微信身份的绑定关系。Web 管理接口不返回 OpenID、UnionID。

关键字段：

- `user_id`, `app_id`, `open_id`, `union_id`, `phone`。
- `status`: `ACTIVE` 可登录，`DISABLED` 被平台管理员停用，`UNBOUND` 已解绑并可重新发起申请。
- `last_login_time`, `bind_source`, `bind_time`, `unbind_time`。
- 生成列 `active_user_id`: 仅 `ACTIVE` 时等于 `user_id`，配合 `uk_wechat_binding_active_user (app_id, active_user_id)` 保证同一 AppID 下一个系统账号只有一个有效绑定。

迁移遇到历史重复有效绑定时，保留最近登录/最近更新的一条为 `ACTIVE`，其余改为 `DISABLED`，不删除历史数据。

### wechat_access_application

用途：保存已经存在的系统账号申请新增项目访问权限，以及相关审批历史。新用户账号注册不得写入本表，统一使用独立的 `registration_application`。

审批通过时必须选择已有且启用的系统用户、项目职责和已启用权限模板；不得自动创建账号，也不得创建 `password_login_enabled=0` 的微信专用随机账号。没有可绑定账号的申请人必须先提交统一注册申请，待平台审批创建账号后再申请项目访问。申请、审批和拒绝记录继续保留用于项目授权审计。

### external_system_config

用途：配置原人员管理系统、塔吊监控系统等外部入口。

关键字段：

- `project_id`: 所属项目。
- `system_name`: 系统名称。
- `system_type`: 系统类型，例如 `personnel`、`safety`、`device`。
- `access_url`: 访问地址。
- `status`: `normal`、`abnormal` 等。

当前状态：

- 仅有实体和 mapper，未有 controller 和前端动态读取。

### temporary_person

用途：项目临时人员登记和教育状态管理。

关键字段：

- `project_id`: 所属项目。
- `name`: 姓名。
- `gender`: 性别。
- `idcard`: 身份证号。
- `phone`: 手机号。
- `unit`: 所属单位/班组。
- `role`: 工种。
- `entry_time`: 入场时间。
- `status`: 人员状态。
- `remark`: 备注。
- `deleted`: 逻辑删除。

## 新增字段规则

新增字段必须遵守：

1. 先确认业务含义和所属表。
2. 优先写增量 SQL，不要直接要求执行 `init.sql`。
3. 字段名使用 snake_case，Java 属性使用 camelCase。
4. 需要默认值时明确历史数据如何回填。
5. 涉及状态、类型、权限的字段必须同步更新前端字典。
6. 涉及用户或项目的数据必须考虑权限隔离。
7. 修改后同步更新本文件和 `docs/接口规则.md`。

不允许随意修改的字段：

- 各表 `id`
- 各表 `project_id`
- 各表 `deleted`
- `sys_role.role_code`
- `sys_user.username`
- `file_resource.file_path`
- `project_info.longitude`、`project_info.latitude`、`project_info.coordinate_type`
