# 阿里云正式更新步骤

更新日期：2026-09-02。

本页是本次正式更新的可执行清单。它只适用于已核定的旧正式基线：**68 张精确表和 13 个精确
迁移标记**。任意一项不同都要停止，不要手工补标记、跳过脚本或执行 `init.sql`。

上传、解包和运行命令都可在阿里云工作台完成。数据库不需要在命令里输入密码：使用服务器已有的 MySQL
受控客户端配置/本机认证；如需指定，只设置 `MYSQL_DEFAULTS_FILE=/root/.my.cnf`，且文件权限必须是
`600`。不要把数据库密码、AppSecret或任何业务密钥写入命令、聊天或发布包。

## 0. 上传和验包

在阿里云工作台文件管理中，把外层 `智慧营造生产更新-<时间>.tar.gz` 和同名 `.sha256` 上传到一个新目录。
先在 Shell 中显式填写实际路径：

```bash
export DXY_UPLOAD_DIR='/root/releases/20260901'
export DXY_OUTER="$DXY_UPLOAD_DIR/智慧营造生产更新-<实际时间>.tar.gz"
export DXY_RELEASE_ID='20260901-<实际时间>'
export DXY_RELEASE_DIR="$DXY_UPLOAD_DIR/智慧营造生产更新-<实际时间>"

cd "$DXY_UPLOAD_DIR"
sha256sum -c "$(basename "$DXY_OUTER").sha256"
test ! -e "$DXY_RELEASE_DIR"
tar -tzf "$DXY_OUTER" >/dev/null
tar --no-same-owner -xzf "$DXY_OUTER" -C "$DXY_UPLOAD_DIR"
cd "$DXY_RELEASE_DIR"
sha256sum -c SHA256SUMS
python3 ops/verify-release-archive.py outer "$DXY_OUTER"

```

任何一条非 0 退出都停止。不要在旧目录上解包，不要上传工作区 `dist/dev/mp-weixin`、
`dist/build/mp-weixin` 或自行重新压缩的小程序目录。

核对包内文件后设置本次运行参数；带 `<...>` 的值必须替换为包内真实文件名：


## 1-A. 安装并核验后端自恢复保护

必须在当前后端、MySQL、Redis 和本机验证码接口都健康，且尚未进入停机窗口时执行。首次安装或已与
包内版本完全一致时：

```bash
"$DXY_OPS/05-self-heal-control.sh" install
"$DXY_OPS/05-self-heal-control.sh" verify
```

脚本不得改变主服务 `InvocationID` 或 `MainPID`。如提示目标文件与包内版本不同，先逐文件核对差异，
再显式执行：

```bash
"$DXY_OPS/05-self-heal-control.sh" install \
  --replace --confirm REPLACE_SITE_PLATFORM_SELF_HEAL
"$DXY_OPS/05-self-heal-control.sh" verify
```

替换模式会在写入前把旧文件备份到 `/var/backups/site-platform-self-heal/`。

任一命令非 0 都停止，不得手工拼接 unit 或用 `systemctl restart site-platform.service` 代替。
安装与核验也会等待 `/run/site-platform-release.lock`。包括后续 `10` 至 `90` 在内的所有非 dry-run
生产写阶段都全程持有这把排他租约；看到等待提示时不要并行重跑，也不要删除锁文件。命令退出后内核
自动释放租约，锁文件继续存在是正常现象。

## 2. 停服同点备份

先看 dry-run，确认维护窗口开始后再真实执行：

```bash
"$DXY_OPS/10-stop-and-backup.sh" \
  --backup-dir "$DXY_BACKUP_DIR" --dry-run

"$DXY_OPS/10-stop-and-backup.sh" \
  --backup-dir "$DXY_BACKUP_DIR" \
  --confirm STOP_AND_BACKUP_DIANXINYUN
```

脚本在取得发布操作锁后，会再与已运行的 watchdog 争用同一把 `/run/site-platform-watchdog.lock`，取得
串行门禁后创建维护锁，并一直持有协调锁到后端确认停止。成功后后端必须保持停止，且
`/etc/site-platform/maintenance.lock` 必须存在并与本次备份目录绑定。
这一个目录同时保存完整 MySQL dump、uploads、旧 JAR、旧 Web、env、
Nginx、systemd、实际软链目标和逐文件 SHA-256：

```bash
cd "$DXY_BACKUP_DIR"
sha256sum -c SHA256SUMS
gzip -t database/dianxinyun.sql.gz
tar -tzf files/uploads.tar.gz >/dev/null
test "$(systemctl is-active site-platform.service)" != 'active'
test "$(systemctl is-enabled site-platform.service 2>/dev/null || true)" = 'disabled'
test -f /etc/site-platform/maintenance.lock
install -d -o root -g root -m 0700 "$DXY_RUN_DIR"
```

真实执行前脚本会拒绝 `Unattended-Upgrade::Automatic-Reboot=true` 或已有 `/run/reboot-required` 的主机。
从本步创建维护锁到 `40` 或 `90` 健康解锁之间，禁止在阿里云控制台重启实例，也禁止执行 `reboot`。
若意外重启，主服务应因 `disabled` 保持停止；仍要保持流量关闭并核对
`systemctl is-enabled/is-active site-platform.service`、维护锁、同点备份、离线 worker、数据库标记和
当前软链。若服务意外为 `active`，立即停止，再决定从精确停点继续或回滚；不得直接删除锁。

读取正式配置，不 `source` env，不打印密钥；wrapper 会在 Java exec 前最后覆盖离线 Profile、关闭调度及
VERIFY/APPLY 控制量，避免正式 env 中的 `APP_SCHEDULING_ENABLED=true` 把离线任务切回在线模式。

如果 SSH 断连、OOM 或强制终止后 `/run/site-platform-offline-worker.state` 仍存在，不得直接删除，也不得
先执行下一发布阶段。先读取其中的 unit，核对 `systemctl status`、`journalctl` 和数据库精确状态；确认
worker 已无 job/PID，数据库只能是 `98/24/0` 或 `98/25/1` 后，使用：

```bash
"$DXY_OPS/06-offline-worker-recovery.sh" \
  --backup-dir "$DXY_BACKUP_DIR" \
  --confirm CLEAR_STALE_OFFLINE_WORKER_AFTER_DATABASE_REVIEW
```

输出为 `98/25/1` 时下一步只能重新运行 `post-verify`；输出为 `98/24/0` 时必须重新运行 `verify`，不能复用
断连前的 APPLY 参数。其他状态全部停止并保留现场。

`/run/site-platform-offline-worker.lock` 是 wrapper 状态切换、自动复核和 `06` 受控清理共用的
内核租约载体。禁止删除它来“解锁”；文件存在不代表租约正被占用。

## 11. 任一阶段失败：同点回滚

不执行反向 DDL，不单独恢复数据库或 uploads。回滚脚本要求已验证的备份目录、故障现场新目录和明确确认语；
它先封存故障现场，再把数据库、uploads、JAR、Web、env、Nginx、systemd 恢复到同一停机点。

小程序尚未发布：

```bash
export DXY_FAILURE_DIR="/root/backups/dianxinyun/${DXY_RELEASE_ID}-failure-before-rollback"

"$DXY_OPS/90-rollback.sh" \
  --backup-dir "$DXY_BACKUP_DIR" --failure-snapshot-dir "$DXY_FAILURE_DIR" \
  --mini-state not-released --dry-run

"$DXY_OPS/90-rollback.sh" \
  --backup-dir "$DXY_BACKUP_DIR" --failure-snapshot-dir "$DXY_FAILURE_DIR" \
  --mini-state not-released \
  --confirm RESTORE_DIANXINYUN_FROM_SAMEPOINT_BACKUP
```

小程序 0.1.8 已发布：先确认微信端回退方案或旧后端兼容性，然后另外提供确认语：

```bash
export DXY_FAILURE_DIR="/root/backups/dianxinyun/${DXY_RELEASE_ID}-failure-before-rollback"

"$DXY_OPS/90-rollback.sh" \
  --backup-dir "$DXY_BACKUP_DIR" --failure-snapshot-dir "$DXY_FAILURE_DIR" \
  --mini-state released \
  --mini-confirm MINI_0_1_8_ROLLBACK_OR_OLD_BACKEND_COMPATIBILITY_APPROVED \
  --confirm RESTORE_DIANXINYUN_FROM_SAMEPOINT_BACKUP
```

回滚恢复旧服务时，脚本会先有界轮询本机接口，再轮询公网入口；旧 Spring 启动较慢时不会因固定
3 秒后的临时 `502` 误判失败。若有界等待仍失败，脚本会停止后端、保留同点备份已经恢复的
Nginx/systemd 配置和故障现场，并在回滚版本目录写 `ROLLBACK_FAILED`；只有两级健康均通过才写
`ROLLBACK_COMPLETE`。回滚成功后再验证旧验证码、登录、业务表/迁移标记精确基线、附件读取和
Nginx。回滚成功且两级健康通过后脚本才解除维护锁；任何失败都保留锁，防止 watchdog 在半恢复状态
拉起后端。故障原因未关闭前不重试发布。

禁止用 `rm` 删除 `/run/site-platform-release.lock`、`/run/site-platform-watchdog.lock` 或
`/etc/site-platform/maintenance.lock` 处理等待或失败。前两者是内核租约载体，维护锁则是发布状态；
