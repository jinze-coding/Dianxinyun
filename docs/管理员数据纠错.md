# 管理员数据纠错

更新日期：2026-09-17。交付范围为原本地 Web 3002、共享后端 8080 和小程序开发产物；正式部署和微信发布另行安排。

## 使用方式

模块目录采用白蓝卡片，显示业务图标、用途说明和当前目录数量；宽屏最多四列，窄屏按内容宽度收拢。三步指引为“选择业务模块 → 筛选并修改记录 → 核对前后内容并保存”，全部业务入口保持原分组。

平台管理员进入「系统管理 → 数据纠错」，按业务分组选择记录类型，再选择项目和关键词、日期、状态条件。列表固定标题、筛选、表头和底部分页，仅记录区滚动；每页支持 10/20/50/100 条。

每次处理一条记录及其现有明细。编辑内容、合格业务人员、业务日期或附件后，填写 1–500 字原因，先查看修改前后对照，再确认保存。五分钟预览到期或记录变化返回 409，页面保留输入并要求重新核对。人员以稳定用户 ID 保存，姓名快照随之更新；上传人和过去的实际操作人不改写。

记录内可查看「纠错历史」，系统操作日志的 DATA_CORRECTION 条目可打开同一详情。历史含操作者、时间、原因、前后字段和前后附件；无修改或删除日志入口。

## 业务关系

- 人员候选由项目成员、账号状态和原业务资格筛选，确认时再校验；当前本人归属、访问和动态待办读取实际用户 ID。历史上传人、实际审批/复查/提交/签到人保持。临边整单反馈要求同一负责人，更正整改人时同步同一任务下非作废的现有整改项及任务默认整改人，递增任务和关联项版本，预览列明受影响项；不改状态。
- 电箱日检更正日期复用有效巡检范围判断，校验同箱同日唯一；锁电箱后锁记录。周检日期同步自然周一及有效关联问题的业务日期，校验同项目同周唯一；关联问题日期变化出现在预览与审计。周检问题不能单独改变业务日期。目标重复时拒绝，不合并。
- 工程资料替换创建新不可变版本，原版本成为 SUPERSEDED；既有收发、签收引用保持。会议资料新版本成为当前内部版本，`published_version_id` 保持，公开发布仍需原流程。质量资料保持业务文件 ID，安装新的物理文件，旧字节先复制到不可变纠错历史。
- 附件沿用原格式、大小策略；会议资料 1GiB、安委会照片 15MiB/办公文件 100MiB/视频 500MiB，其余使用现有图片/资料策略，传输统一 8MiB 分片、分片及整文件 SHA-256、24 小时暂存会话。附件绑定校验项目、记录、用途、上传管理员及有效期，不能借用别人的暂存或跨记录附件。
- 历史原件作为独立 DATA_CORRECTION_HISTORY 文件保存，按业务对象、源文件和内容摘要复用；暂存清理仅处理到期 PENDING，不处理已提交的历史引用。业务永久删除的原影响预览计入纠错历史和暂存文件，复用同一提交后物理清理，文字日志保留。
- 业务 API 返回可选 `correctionNotice`，只含提示与时间，不暴露纠错原因或管理员日志。Web 及受影响小程序详情展示只读标识。新生成的巡检、质量、用印和访客导出附加标识，已生成文件保持原样。小程序没有纠错入口。

## 接口与事务

统一前缀 `/api/v1/system/data-corrections`，目录、查询、候选、上传、确认及历史文件每次均校验有效 `PLATFORM_ADMIN` 身份及 `system.data.correct`；项目停用和业务模块关闭仍拒绝。

| 方法与路径 | 用途 |
|---|---|
| GET /catalog | 七组、22 类业务目录与字段元数据 |
| GET /records/{type} | projectId、keyword、startDate/endDate、status、pageNo、pageSize 分页查询 |
| GET /records/{type}/{id} | 可编辑值、只读值、现有明细、附件和 expectedRevision |
| GET /records/{type}/{id}/candidates?field=… | 当前字段的合格人员 |
| POST /records/{type}/{id}/preview | expectedRevision、reason、changes、children、attachments、confirmLocation |
| POST /confirm | confirmationToken、requestKey |
| GET /records/{type}/{id}/history | 分页纠错历史（每页 20 条） |
| GET /logs/{id} | 解密后的前后对照和原因，管理员专用 |
| POST /uploads | targetType、targetId、slotKey、fileName、totalSize、sha256 |
| GET /uploads/{session}?projectId=… | 上传进度 |
| PUT /uploads/{session}/chunks/{index} | projectId、sha256、multipart file |
| POST /uploads/{session}/complete | 完成暂存，返回文件 ID |
| DELETE /uploads/{session}?projectId=… | 取消上传会话 |
| GET /records/{type}/{id}/files/{fileId} | 当前附件；历史须传 correctionId 和 phase=BEFORE/AFTER |

预览在 Redis 保存加密请求，绑定管理员、目标、内容和五分钟有效期。确认重新鉴权，在数据库事务中锁项目、管理员、记录及相关明细/附件，比较完整快照摘要；存在业务版本字段继续递增，无版本字段使用锁内快照校验。更正、附件引用、专用日志、系统操作摘要同事务提交；审计失败全部回滚。

`requestKey` 通过数据库 `(operator_id, request_key)` 唯一键持久化，`preview_token` 也唯一。同管理员同键同令牌重试返回原纠错结果，即使 Redis 令牌已经过期；换令牌复用同键或重复消费预览产生冲突。敏感业务值及完整快照使用现有业务加密服务，普通操作日志只有对象/纠错编号摘要。
