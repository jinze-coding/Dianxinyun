## 本轮已实现

### 统一注册

- Web 和小程序共用独立 `registration_application`。
- 标准注册提交时只保存 BCrypt 摘要；小程序 `WECHAT_QUICK` 只保存微信身份和手机号，不保存申请密码，均不创建 `sys_user`。
- 状态固定为 `PENDING / APPROVED / REJECTED / CANCELLED`。
- 待审批账号、手机号和微信身份使用唯一约束防并发占用。
- 审批通过时在事务内创建用户、分配项目角色和项目范围、建立申请中的微信绑定并写审计日志；平台全局身份不在用户管理页分配，只能由系统初始化或受保护运维流程维护。
- 批准、驳回或申请人取消后清除申请表密码摘要。
- Web 使用图形验证码，手机号首版人工核验；申请状态只允许使用随机状态令牌查询或取消。
- 小程序微信快捷注册只要求微信手机号和真实姓名；审批通过后首次微信登录必须设置初始密码。完成前禁止进入业务、申请项目访问、自助解绑微信或使用 Web 扫码登录。

### 认证与微信快捷登录

- 密码只使用 BCrypt；历史非 BCrypt 凭证禁止登录并标记为待重置。
- JWT 与 Redis 会话默认 7 天，凭证版本变化、停用、改密、微信解绑和关键授权变化会注销全部会话。
- 系统不提供默认测试账号或明文密码；管理员恢复使用一次性 `ADMIN_RESET_USERNAME`、`ADMIN_RESET_PASSWORD`。
- 小程序支持账号密码、微信快捷登录、绑定已有账号和申请注册。
- 新注册申请统一使用手机号作为系统登录账号；Web 与小程序不再展示独立用户名输入，兼容请求若带 `username` 必须与手机号一致。
- 绑定已有账号必须同时验证账号密码和新的 `uni.login` code；手机号相同绝不能自动绑定。
- 同一 AppID 下有效系统用户、OpenID、UnionID 一对一。
- 已启用密码登录的用户重新验证密码后可自助解绑；仅微信登录账号由平台管理员处理。
- Web 扫码登录使用 2 分钟 Redis challenge、浏览器私有校验密钥、小程序明确确认/取消和一次性交换码。二维码不携带 JWT 或浏览器密钥。
- `/auth/user-info` 返回 `initialPasswordSetupRequired`，小程序页面守卫会将该账号强制导向 `pages/initial-password`；`POST /auth/initial-password` 成功后注销旧会话并签发新 JWT。
- 原电箱扫码申请只允许已有用户申请项目访问，不创建微信专用随机账号。

### RBAC 与系统管理

- `PLATFORM_ADMIN` 是唯一平台级全局资格，拥有注册审核、全量用户、角色、菜单、微信、审计和跨项目管理；其他业务角色均为项目角色。该受保护身份不在用户管理页展示或分配。
- 同一成员在同一项目可以拥有多个角色，关系保存在 `sys_user_project_role`，菜单和操作权限按并集合并；`sys_user_project.status=ACTIVE` 是生效前提。
- `PROJECT_ADMIN` 正式显示为“项目经理”且受保护，只有系统管理员能授予、撤销或调整。项目经理可管理自己项目的普通成员：加入、移出、调整非项目经理角色、暂停/恢复访问；不能处理任何项目经理角色或平台权限。
- 资料、巡检、质量在角色配置中是三个跨端统一模块，而不是重复的 Web/小程序菜单。关闭模块会同时隐藏两端入口并由后端按目标项目返回 `403`；细分操作权限保留，重新启用后继续生效。系统管理仍为独立 Web 平台目录。
- `/api/v1/auth/user-info` 返回 `menus`、平台 `permissionCodes`、每个项目的 `projectRoles[]`、菜单和有效权限码。项目权限按目标 `projectId` 精确计算；A 项目写权限不能用于 B 项目。
- 系统管理员可见注册审核、用户、角色与权限、菜单与功能、项目成员与权限、微信绑定和操作日志；项目经理只可见“项目成员与权限”，普通成员无系统管理入口。
- 独立“巡检权限角色模板”已删除；历史表/字段只保留追溯兼容，`/inspection-permission-templates` 返回 HTTP `410`。
- 前端菜单和按钮显隐只用于体验，资料、巡检、质量和系统管理服务端继续返回真实 HTTP 403。
