## 本轮已实现

### 统一注册

- Web 和小程序共用独立 `registration_application`。
- 提交时只保存 BCrypt 摘要，不创建 `sys_user`。
- 状态固定为 `PENDING / APPROVED / REJECTED / CANCELLED`。
- 待审批账号、手机号和微信身份使用唯一约束防并发占用。
- 审批通过时在事务内创建用户、分配平台/项目角色和项目范围、建立申请中的微信绑定并写审计日志。
- 批准、驳回或申请人取消后清除申请表密码摘要。
- Web 使用图形验证码，手机号首版人工核验；申请状态只允许使用随机状态令牌查询或取消。

### 认证与微信快捷登录

- 密码只使用 BCrypt；历史非 BCrypt 凭证禁止登录并标记为待重置。
- JWT 与 Redis 会话默认 7 天，凭证版本变化、停用、改密、微信解绑和关键授权变化会注销全部会话。
- 系统不提供默认测试账号或明文密码；管理员恢复使用一次性 `ADMIN_RESET_USERNAME`、`ADMIN_RESET_PASSWORD`。
- 小程序支持账号密码、微信快捷登录、绑定已有账号和申请注册。
- 绑定已有账号必须同时验证账号密码和新的 `uni.login` code；手机号相同绝不能自动绑定。
- 同一 AppID 下有效系统用户、OpenID、UnionID 一对一。
- 已启用密码登录的用户重新验证密码后可自助解绑；仅微信登录账号由平台管理员处理。
- Web 扫码登录使用 2 分钟 Redis challenge、浏览器私有校验密钥、小程序明确确认/取消和一次性交换码。二维码不携带 JWT 或浏览器密钥。
- 原电箱扫码申请只允许已有用户申请项目访问，不创建微信专用随机账号。

### RBAC 与系统管理

- 权限由平台角色、当前项目角色、菜单、操作权限和有效项目范围共同决定。
- `/api/v1/auth/user-info` 返回 `menus`、平台 `permissionCodes`、`projectRoles/projectContexts` 和项目权限。
- 平台系统管理接口只认可平台角色权限；项目角色不能进入全局注册、用户、角色、菜单、微信或审计管理。
- 项目权限按目标 `projectId` 精确计算；A 项目写权限不能用于 B 项目。
- 前端菜单和按钮显隐只用于体验，资料、巡检、质量和系统管理服务端继续返回真实 HTTP 403。
- 系统管理包含注册审核、用户、角色权限、菜单功能、项目授权、微信绑定和操作日志。
- 项目管理员只能管理已授权项目的成员、项目角色和项目访问申请，不能审批新账号或授予平台角色。

## 数据库状态

正式本地 `dianxinyun` 当前仍是 39 张表，尚未创建 `registration_application`。本轮没有对该库执行统一注册/RBAC 迁移，也没有执行 `init.sql`。

唯一允许用于当前 39 表基线的本轮增量脚本：

```text
backend/src/main/resources/sql/migrations/20260728_unified_registration_rbac_wechat_login.sql
```

脚本新增 6 张表，应用后为 45 张。迁移已在隔离副本 `dianxinyun_migration_verify_20260728` 连续双跑验证：

- 45 张表；
- 1 条数据种子标记；
- 14 个菜单；
- 21 个操作权限；
- 已处理申请无密码摘要残留；
- 待审批账号和手机号无重复；
- 重跑不会恢复管理员主动停用的菜单或撤销的角色授权。

迁移正式库前必须：

1. 备份数据库和相关文件；
2. 执行 `docs/数据库结构.md` 中的重复手机号、有效微信绑定和平台管理员预检；
3. 记录旧角色、微信绑定、项目授权和关键业务表数量；
4. 只执行增量脚本；
5. 使用显式管理员密码重置确保至少一个可用 BCrypt 平台管理员；
6. 回归登录、权限和三大业务。

`backend/src/main/resources/sql/init.sql` 包含 `DROP TABLE`，只允许明确确认的全新空库使用。严禁在当前有数据环境或生产库执行。
