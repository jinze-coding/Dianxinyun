# 访客资料复用、门卫预约匹配与会议签到大屏

更新日期：2026-09-10。本文以本次代码和数据库验证为准。

当前本地 8080/3002 已直接更新，原开发库为 103 表，当前项目的测试数据见
[访客与会议本地测试数据](访客与会议演示数据.md)。后续直接在该环境开发和展示。

## 业务与资料

三个免账号入口（单次预约、会议预约、门卫现场登记）共用同一项目、AppID、微信身份的本人快捷资料。
资料来源是访客填写的单位、姓名、手机号码、出行方式和车牌，微信身份只用于确定归属。首次勾选
“记住信息”才持续保存；每次成功提交更新，关闭后清空快捷字段并保留关闭偏好，避免旧命名资料再次
自动带入。首次没有快捷记录时，已有命名常用资料可提供本人预填；手动选择命名资料也只带入本人，
保留本次已填同行人，同行人员每次另行填写。

异步预填只写未编辑字段，用户清空或修改的字段不能被迟到响应覆盖。取消记住同样有编辑保护。
获取微信身份失败时保留表单并提供重新识别；单次预约不再匿名降级提交。内部 contactName、CONTACT
编码兼容保留，面向访客、管理端和导出的称呼统一为单位、姓名、手机号码。

快捷表、单次、会议、门卫、签到身份使用不同 HMAC 用途；服务器在已验证短会话内做跨用途计算。
旧单次预约无可靠微信字段时不按手机号码补认领。手机号与快捷资料审计都使用访客专用密钥加密。

## 门卫扫码

1. 验证 G: 门卫 scene、项目状态和微信身份，签发原有 30 分钟短会话。
2. 查询本人在当前项目的 SUBMITTED 单次预约、REGISTERED 会议登记以及有效门卫登记。
   预约要求开始时间 ≤ 当前时间 < 结束时间；会议还要求父邀请 OPEN、本人登记有效。
3. 多条预约分别展示来源、事由/会议、时间、人数及各自人员，提示“已填写，允许放行”。
   若另有现场登记，仍按原记录 24 小时有效期处理；门卫展示不会写入会议签到。
4. 没有有效记录时显示现场表单及今天至后六天尚未结束的会议（包含仍进行中的跨日会议）。
   不选会议就是普通来访，可以多选，已预约的会议标识已预约并复用原登记。
5. 选择凭证是随机不透明值，只存在于当前会话，30 分钟过期；提交重新验证项目、状态、时间和版本。
   一次最多选择 50 场。任一会议变化时整批回滚，刷新会议列表后重新选择，已填本人信息保留。
6. 门卫登记、会议登记/人员、关联、快捷资料和审计同事务提交，项目行锁及稳定会议顺序串行处理重试。
   会场 MC: 码继续逐人确认实际到场。门卫报名只进入预约名单。
7. 门卫页面每 15 秒核验，在恢复前台时立即核验；失效会话重新交换身份，轮换、停用、项目停用或
   状态读取失败时不继续展示绿色放行。页面自身用服务端时间计算截止。

## 新增与扩展接口

接口前缀均为 /api/v1，普通响应沿用 Result。公开短会话用 X-Visitor-Session 请求头，不进入 URL。

| 接口 | 行为 |
| --- | --- |
| POST /public/site-access/visitor-sessions | 单次会话增加 personalInfo |
| POST /public/site-access/meeting/session | 未预约表单状态增加 personalInfo |
| POST /public/site-access/guard/session | 返回 FORM / REGISTERED / MATCHED、serverTime、matchedPasses、personalInfo |
| POST /public/site-access/guard/state | 校验短会话/当前门卫码/项目，刷新表单或放行状态 |
| POST /public/site-access/guard/meetings | 只返回 title、visitStartTime、visitEndTime、location、registered、choiceToken |
| POST /public/site-access/guard/submit | 增加 meetingChoiceTokens、rememberInfo；原 24 小时凭证兼容 |
| POST /public/site-access/invitations/submit | 必须验证单次微信会话，增加 rememberInfo |
| POST /public/site-access/meeting/submit | 增加 rememberInfo |
| GET /site-access/invitations/{id}/meeting-attendance/screen?pageNo=1 | 登录及目标项目 site_access.view；固定每页 24 人 |

personalInfo 包含 available、rememberInfo 及五个本人字段，不含同行人。FORM 才需要返回预填；
状态刷新不续期、不重新签发短会话。门卫匹配结果不返回数据库记录 ID、手机号、OpenID 或邀请令牌。
新增公开读取先按受信客户端 IP 限流（state 600/10 分钟、meetings 120/10 分钟），业务内另按身份
60/10 分钟限流；保持 64KB 请求体保护与真实 HTTP 401/403/409/410/429。

## 签到大屏

会议邀请列表提供预约码、签到码、签到大屏三个独立入口。大屏新窗口地址只含会议 ID，沿用后台
登录态，不携带公开 scene、JWT 或浏览器密钥。普通后台登录落点保持个人待办。

展示会议名称、时间、预约人数、已签到人数、预约待签到和现场补录签到人数，以及已签人员姓名、
单位、签到时间。名单按签到时间倒序，24 人一页，10 秒循环翻页；数据每 5 秒刷新。签到码按版本
缓存，与名单刷新独立请求，生成慢不会阻塞名单。查看权限与码管理权限分别校验；关闭码、轮换、
权限失效及会议结束均清理/隐藏对应展示。断网时显示最后更新时间并自动重试；查看权限失效清空名单。
