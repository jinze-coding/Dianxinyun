## 功能入口

平台管理员进入 Web「系统管理 → 用户管理」，可按姓名/账号/手机号、项目、该项目角色、项目访问状态和账号状态筛选。勾选多名用户后点击「批量更改项目权限」。单批最多 200 人，翻页保留选择；改变筛选或切换页签清空选择。

用户列表的标题、筛选、表头与底部分页保持可见，中间数据区独立滚动，少量/空结果仍填满剩余区域；加载和错误提示显示在数据区。底部可选每页 10/20/50/100 条（默认 20），同时展示总数、页码和本页实际条数。改变条数回到第一页和数据顶部，保留已勾选人员；其他系统管理页仍沿用原分页设置。左侧「返回业务工作台」为蓝色按钮，固定在侧栏底部。

停用账号和平台管理员不能参与批量操作。后端在预览和保存时重新校验账号、项目、角色和管理员身份，页面禁用按钮不代替服务端鉴权。

## 操作方式

页面先选择「调整项目内的角色」或「加入另一个项目」。选择项目和角色后，「保存后会怎样」会用实际项目名、角色名和已选人数说明结果；同项目操作另有具体例子。点击「下一步：核对变化」才请求预览，再核对每个人「现在的角色 / 保存后角色」并确认。

| 页面选择 | 保存结果 |
| --- | --- |
| 调整项目内的角色 → 增加角色，原来的保留（默认） | 与每个人在所选项目的原角色合并；尚未加入者加入项目。 |
| 调整项目内的角色 → 取消选中的角色，其他的保留 | 仅移除选择的角色；必须已经加入项目。任何人移除后没有角色时，标出该用户并阻止整批保存，不自动移出项目。 |
| 调整项目内的角色 → 重新设置，只保留本次选中的角色 | 将每个人在所选项目的角色替换为本次所选角色；必须已经加入项目。 |
| 加入另一个项目 → 保留原项目（默认） | 保留来源项目，为目标项目增加授权，对应复制操作。 |
| 加入另一个项目 → 从原项目移出 | 为目标项目增加授权，并移出来源项目，对应迁移操作；两个步骤在同一事务中保存。 |

切换这两个入口时回到「增加角色」或「保留原项目」默认值，清空角色勾选；切换同项目的增/减/重设方式也清空勾选，避免把上一种操作的选择直接用于另一种含义。

复制和迁移默认沿用各人在来源项目的角色，也可为所有人统一选择目标角色。目标项目已有角色按并集合并；已有目标项目的访问启用/暂停状态保持，新目标项目继承各人的来源项目状态。同项目调整保持原访问状态。

这些操作更改成员和角色授权。业务记录、历史、附件仍属于原项目，不跟随迁移。平台角色、账号密码和微信绑定保持原流程。

## 预览与确认

预览逐人展示项目、变更前后角色、访问状态、减少的操作权限及需要解除的责任，汇总加入/调整/移出项目数、变化/无变化/需修正人数。任何用户校验失败都会阻止整批保存，可返回修改或取消选择该用户。

追加角色按角色并集合并，不因已有无关责任产生撤权提示。用印审批配置与待审批任务按具体用户指派，保留项目成员资格的角色调整不解除它们。电箱、临边、质量责任只在本次确实失去对应处理能力时计入；质量整改同时依赖查看与整改资格。移出来源项目时预览该用户在来源项目的全部责任。

有责任影响时，管理员必须勾选确认后才能保存。解除负责人/配置绑定后，原业务记录保留，后续重新分配仍走现有管理流程。

预览令牌绑定管理员和本次请求，五分钟有效、只能使用一次。确认时锁定相关项目、用户、成员和角色，重新计算当前授权和责任数量；状态变化、过期或重复提交返回 409，页面要求重新预览。新一次预览以数据库当前授权为准。

整批成员、角色、责任解除和审计同事务保存，任一步失败均回滚；成功后清除受影响用户的权限缓存并注销旧会话。审计使用现有 `BATCH_PROJECT_ACCESS` 操作类型，保留批次标识、操作方式和项目角色前后值，按现有描述列长度分段保存。

## 接口

均位于 `/api/v1`，批量接口仅启用的平台管理员可调用。

- `GET /system/users`：原分页、关键词和账号状态参数保留，新增 `projectId / roleId / accessStatus`。角色和访问状态筛选必须指定项目，并且匹配同一个项目；`accessStatus` 为 `ACTIVE / DISABLED`。
- `POST /system/users/project-role-assignments/batch/preview`：传 `userIds`（1–200 人，不重复）、`operation`。同项目操作传 `projectId / roleIds`；跨项目操作传 `sourceProjectId / targetProjectId / roleSource`，`roleSource=SELECTED` 时传 `roleIds`。来源和目标必须不同，角色只能为有效项目角色。
- `operation` 为 `ADD_ROLES / REMOVE_ROLES / REPLACE_ROLES / COPY_PROJECT / MOVE_PROJECT`；`roleSource` 为 `SOURCE / SELECTED`，跨项目默认 `SOURCE`。
- `POST /system/users/project-role-assignments/batch/confirm`：仅传 `confirmationToken / confirmResponsibilityRelease`，使用服务端保存的请求，客户端不能替换预览内容。

预览与确认返回 `changedUserCount / unchangedUserCount / blockedUserCount / addedCount / updatedCount / removedCount / responsibilityCount / users`；有效且有变化的预览另有 `confirmationToken / expiresAt`。`users[].projects[]` 包含项目、动作、前后角色/状态、减少的权限与责任影响。
