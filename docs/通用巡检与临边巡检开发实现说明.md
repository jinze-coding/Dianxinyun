# 固定式临边巡检开发实现说明

更新时间：2026-08-26

## 当前结论

已停止面向用户的开放式通用巡检方案。业务端只显示“临边巡检”，项目不能创建模板、修改检查项、新增点位类型或配置多套计划。`general_inspection_*` 仅作内部表名和历史兼容数据域，不是产品名称。

“巡检管理”分成完全独立的两个专区：

- 电箱巡检：继续使用电箱台账、六项日检、专用月表、统一二维码和原整改流程。
- 临边巡检：使用 8 类系统固定检查表，只提供点位、项目周期设置、任务、记录、整改和统计。

项目开关继续默认关闭，缺少 `general_inspection_project_setting` 记录也视为关闭；只允许 `PLATFORM_ADMIN` 开启或关闭。首次上线按发布流程只选择一个项目试运行，完成完整闭环验收后可由平台管理员逐项目开放。

## 固定点位类型和检查表

系统内置且只允许以下 8 类点位，每类对应一份不可编辑、不可删除的固定检查表：

1. 楼层、阳台及挑檐边。
2. 楼梯口、平台及梯段边。
3. 屋面边。
4. 基坑、沟槽边。
5. 洞口、预留洞。
6. 电梯井口、井道。
7. 升降机、物料提升机停层平台。
8. 接料、卸料平台。

每份表约 5 项，任务生成时根据点位类型选择对应系统模板，并保存不可变检查项快照。只允许 `NORMAL / ABNORMAL`，不提供“不适用”。检查提示和规范依据只读展示。

参考依据为现行公开的 [JGJ 80-2016](https://zjw.sh.gov.cn/xcsc2020-jsbz/20200430/f141c8d12a494a1c8a9eb155a6e420ce.html)、[JGJ 311-2013](https://zjw.sh.gov.cn/xcsc2020-jsbz/20200430/b6b94960c50e48fd83484b27845f1c6d.html)、[GB 55034-2022](https://szwb.sz.gov.cn/gwszwfw/zsk/hybz/index_5.html) 和[房屋市政工程生产安全重大事故隐患判定标准（2024 版）](https://zjw.sh.gov.cn/xwfb/20241224/8929913b394e4777b7ccb79921251af4.html)。系统检查表只用于日常巡检，不能替代项目专项施工方案、验收和法定责任。

## Web 与小程序交互

Web 临边专区固定为 5 个子页：

- 临边点位：只填写名称、固定类型、楼栋、楼层和位置说明；编码由服务端生成。已生成任务的点位不能修改类型。停用时自动取消其未提交任务并记录原因；首版停用后不可恢复，需要继续巡检时重新创建点位。
- 巡检设置：每项目只保留 `EDGE_PROJECT_SCHEDULE` 一套设置，支持每天、每周指定星期、每月 1—31 日或月末；指定日期在当月不存在时该月不生成任务。只有一个开始/截止时段，以及一组巡检人、整改人、复查人和整改期限。新点位只纳入创建后的任务，已生成任务保留旧快照。项目开关重新启用或计划恢复时推进独立生成下界，不补功能关闭/计划暂停期间的历史任务；功能持续启用时仍保留服务停机补偿生成。
- 临边记录：只显示临边任务，状态为待巡检、逾期未检、按时完成、逾期补检、整改中、已闭环或已取消。
- 整改闭环：按“一次任务 = 一张整改单”聚合全部异常项，不与电箱整改混排。
- 统计：只统计临边应检、按时完成、逾期补检、仍未检、异常点位和整改关闭率。

小程序巡检首页和个人待办都把“电箱巡检”和“临边巡检”分区展示。临边表单必须满足：

- 每次任务至少 1 张现场全景照片。
- 所有检查项都必须选择正常或异常。
- 异常项必须填写说明并至少上传 1 张证据照片；正常项不要求单项说明和照片。
- 总备注选填，本地草稿保留选择、文字和持久化照片路径；正式提交前必须联网重新校验任务、权限和快照版本。

## 整改与复查

一次巡检的全部异常项在数据库内仍逐项保存，但对外只提供一张聚合整改单：

1. 整改人必须对每个异常项填写整改说明并上传至少 1 张整改后照片，一次事务性提交全部项。
2. 全部异常反馈成功后，整单进入待复查。
3. 复查人只能“全部通过并关闭”或“整单退回整改”；退回原因必填。
4. 管理者可以改派整改人或复查人，但必须填写原因并写入操作日志。
5. 执行、整改、复查均只允许当前明确指派人。平台管理员未被指派时也不能代替业务人员复查。
6. 复查退回前重新校验原整改人的项目成员与整改权限；已失效时整单转为 `UNASSIGNED` 并进入管理待分派，不把任务退给无权人员。

## 权限与接口

临边巡检接口同时校验项目有效成员、`INSPECTION` 业务模块、项目试点开关和下列独立权限：

- `EDGE_INSPECTION_VIEW`
- `EDGE_INSPECTION_MANAGE`
- `EDGE_INSPECTION_SUBMIT`
- `EDGE_INSPECTION_RECTIFY`
- `EDGE_INSPECTION_REVIEW`

Web 菜单码为 `INSPECTION_EDGE / 临边巡检`。业务接口前缀统一为 `/api/v1/edge-inspections`，包含项目开关、固定类型、点位、项目设置、任务、整改和统计。`/api/v1/general-inspections/**` 和 `/api/v1/public/general-inspection-points/**` 不再注册为业务接口。

临边任务照片使用 `EDGE_INSPECTION_TASK_PENDING`，整改后照片使用 `EDGE_INSPECTION_RECTIFICATION_PENDING`；只允许真实 JPEG/PNG/WebP 等栅格图片，单图最大 15MB。

## 迁移现状和上线门禁

2026-08-26 根据当前 `backend/.env` 只读核对，文档原先记录的“长期库未应用旧通用巡检迁移”已与实际不符：

- `20260826_GENERAL_INSPECTION_V1` 已于 2026-08-26 13:42 写入当前配置库。
- 当前库已有 14 张 `general_inspection_*` 表、6 个旧类别、1 个旧参考模板和 9 个旧检查项。
- 项目开关已有 1 条启用记录，但点位、计划、任务和整改均为 0 条。

因此不得重写、替换或在当前长期库重跑旧迁移。新实现保留原 `20260826_general_inspection.sql` 作为已应用历史基线，另行增加幂等的固定临边转换迁移。

2026-08-26 已完成完整 91 表隔离副本双跑。首次执行核对 8 类、8 套表单、40 个固定项、五项权限、
新菜单、字段/索引和迁移标记；其中 `edge_generation_lower_bound_time` 单独记录最近启用下界。随后模拟管理员停用菜单/权限、撤销平台角色关联并开启一个试点再复跑，
这些选择均未被脚本恢复或覆盖。迁移已增加首次标记门禁和跨排序规则安全比较，临时库已删除；长期库
复核仍为 91 表且没有固定式迁移标记。

正式应用前仍必须：

1. 备份目标数据库和上传目录。
2. 复核本次隔离双跑证据适用于目标备份；目标结构有变化时重新在其完整副本连续执行两次。
3. 在新后端部署前完成迁移，不允许新代码连接未转换库。
4. 首轮只为一个明确的试点项目开启，完成巡检—整改—退回/关闭的完整真机验收后再逐项目扩大。

项目开关缺行等同关闭，且只能由平台管理员启停。首轮只开启一个项目属于发布运营门禁，不固化为永久
业务数量约束；完成试点闭环验收后，平台管理员可以按项目逐个放开。

## 明确不实现的首版范围

首版不提供用户模板、项目模板复制、自定义检查项、自定义点位类型、多套计划、多时段、临时任务、备选人、逐点人员覆盖、临边点位二维码、手机定位、匿名月表、公开页、复杂 Excel 或异步含图导出。
