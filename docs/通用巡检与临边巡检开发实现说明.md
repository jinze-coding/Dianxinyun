# 通用巡检与临边巡检开发实现说明

更新时间：2026-08-26

## 当前结论

通用巡检已经按独立数据域实现，首个公司参考实例为“临边通用参考模板”。现有电箱巡检的六项日检、统一码、专用月表和整改逻辑没有改成动态模板；两类巡检只在个人待办和统一看板聚合。

功能受两层权限控制：角色的 `INSPECTION` 业务模块与项目级通用巡检试点开关。项目开关默认关闭且只能由 `PLATFORM_ADMIN` 启停，因此代码部署和迁移完成后也不会自动向任何项目开放。首次上线必须只选择一个试点项目，由平台管理员显式开启。

正式迁移为 `backend/src/main/resources/sql/migrations/20260826_general_inspection.sql`。长期本地 `dianxinyun` 和生产库均未执行该迁移；不得把隔离验证结果当成正式环境已升级。

## 已实现范围

### Web 配置与管理

- 公司模板仅平台管理员创建、编辑、预览、未来时间发布和归档；项目管理员可复制公司已生效版本为项目草稿。
- 项目模板支持 1—50 个动态检查项，每项配置不适用、提示、规范依据、正常/异常说明要求和 0—9 张照片规则；模板支持 0—9 张整体照片和总备注规则。
- 模板与计划均为草稿、预览、未来发布、归档生命周期。发布版本不可变；新任务按任务开始时刻选择已生效版本，旧任务永久保留快照。
- 点位支持预置和项目自定义类别、编码、区域/楼栋/楼层、位置、风险、最多 9 张参考图、启停/归档、匿名月表开关及不透明场景码。
- 点位启用二维码后，关联待执行任务同步为强制扫码；换码会提升二维码版本、清除旧扫码凭证并同步全部未提交任务，不提供人工跳过。
- 计划支持每天、每周、每月 1—28 日或月末，最多 12 个命名时间段、跨午夜不超过 24 小时，提前 0—1440 分钟执行。
- 计划支持一组默认主巡检人、备选巡检人、整改人/天数、主复查人和备选复查人；批量关联点位后可逐点覆盖。备选人只保留候选快照，不会自动接手。
- 任务管理支持批量取消、明确改派、乐观锁纠错、追加更正说明，以及有整改反馈后的“作废原记录并生成重检修订”。

### 小程序现场闭环

- 巡检首页和个人待办聚合电箱巡检与通用巡检，通用任务可按项目、状态和类型查看。
- `P:<不透明码>` 统一进入扫码中转；登录用户按本人当前任务分流，匿名用户仅在点位主动开放时进入最近 12 个月月表。
- 动态表单只提交任务检查项快照 ID、结果、说明、附件和异常指派；名称、规则、人员权限及二维码版本均由后端重新校验。
- 本地草稿保存选择、文字和持久化后的本地照片路径；正式提交必须联网，失败的新暂存附件会清理，任务/权限/码/版本冲突不会被本地草稿绕过。
- 每个异常检查项独立生成整改。整改人提交说明和照片，明确指派的主/备选复查人关闭或退回；平台管理员未被指派时也不能直接复查。
- 人员或授权失效时，未执行任务转为待改派，未反馈整改转 `UNASSIGNED`，待复查记录清空失效复查人，并形成管理待办。

### 公开、统计、导出和事件

- 匿名月表在任何点位查询前按容器确认后的 `request.getRemoteAddr()` 限流；项目开关、点位状态或公开开关关闭时返回真实 HTTP `403`。
- 公开结果只含项目简称、点位、日期/时段、脱敏检查人、公开备注和动态检查结果，不含照片、异常详述、整改人员、内部 ID 或日志；不同模板版本分段展示。
- 统一看板合并电箱与通用巡检，并返回巡检类型、点位、人员、日期四个维度的应检、完成、按时、逾期补检、仍未检、异常、整改关闭率和平均关闭时长。
- 异步 Excel 最多 31 天、500 个通用任务，按模板版本生成动态检查表，并附任务、检查项、整改明细和压缩缩略图；文件保留 7 天。
- 任务可执行、临近截止、逾期、整改待分派和待复查只写入幂等事件发件箱并发布 Spring 事件。微信订阅、短信和企业微信渠道未接入，事件失败不改变业务提交结果。

## 数据结构

迁移新增 14 张表：

1. `general_inspection_project_setting`
2. `general_inspection_template`
3. `general_inspection_template_version`
4. `general_inspection_template_item`
5. `general_inspection_point_category`
6. `general_inspection_point`
7. `general_inspection_plan`
8. `general_inspection_plan_version`
9. `general_inspection_task`
10. `general_inspection_task_item`
11. `general_inspection_rectification`
12. `general_inspection_action_log`
13. `general_inspection_export_job`
14. `general_inspection_event_outbox`

`general_inspection_task` 以“计划 + 点位 + 时段 + 日期 + 修订号”唯一；任务、检查项、人员、照片规则、模板版本和二维码版本均快照化。平台管理员删除项目时，新数据域纳入影响预览、事务级依赖删除和提交后文件清理；普通配置只允许归档。

## 权限与接口

- 配置、取消、改派、纠错：`inspection.manage`
- 执行：`inspection.submit`、`CUSTOM_INSPECTION_SUBMIT`、当前任务主责人三者同时满足
- 记录：`inspection.view`、`INSPECTION_RECORD_VIEW`
- 看板：`inspection.view`、`SUMMARY_VIEW`
- 整改、复查、导出：`inspection.rectify`、`inspection.review`、`inspection.export`

内部接口统一为 `/api/v1/general-inspections/**`，公开月表为
`/api/v1/public/general-inspection-points/{code}/monthly-records`。通用巡检照片使用
`INSPECTION_CUSTOM_POINT_PENDING / TASK_PENDING / RECTIFICATION_PENDING` 暂存类型，后端校验真实栅格文件，单图最大 15MB。

## 临边参考模板

迁移只内置公司级参考模板和 6 类点位，不直接为项目发布：楼层边、楼梯边、屋面边、基坑沟槽、洞口、接料平台。9 个参考项覆盖防护连续性、栏杆固定、封闭与挡脚、专项防护、警示、坠物风险、临时拆改、恶劣天气后复查及条件性个人防护与监护。

参考依据为上海住建委公开的
[JGJ 80-2016](https://zjw.sh.gov.cn/cmsres/dd/dd2874d657124e648b54c66a113fb0b1/2b641c95070e63127349d11cc3109bc6.pdf)
和[GB 55034-2022 住建部公告信息](https://policy.mofcom.gov.cn/claw/clawContent.shtml?id=96208)。
模板固定提示“必须结合项目施工方案审核并复制为项目模板后使用”，不得把参考模板视为项目专项施工方案或自动合规结论。

2026-08-26 已完成：

- 后端全量 `mvn test` 通过。
- Web `npm run check` 通过，包括 lint、类型检查、80 项测试和生产构建。

- 当前 70 表长期本地库的隔离副本双跑成功，表数变为 84；除允许变化的权限、菜单、角色关联和迁移标记表外，其余 65 张既有表校验值不变。临时数据库已销毁。

仍未完成、上线前必须执行：

1. 对目标长期数据库和上传目录做正式备份，记录校验值和回滚负责人。
2. 在目标环境预检管理员、角色、项目成员、文件根目录和迁移标记，再明确授权执行迁移。
3. 只开启一个试点项目，配置项目模板、点位、人员和至少一个完整计划周期。
4. 使用巡检人、整改人、复查人、管理者和匿名访客做微信真机验收；Web 构建通过不等于现场扫码验收通过。
5. 完成一个周期后核对应检、逾期补检、漏检、整改关闭率、匿名月表和 Excel，再逐项目开放。
