# 固定式临边巡检开发实现说明

更新时间：2026-09-02

## 当前结论

已停止面向用户的开放式通用巡检方案。业务端只显示“临边巡检”，项目不能创建模板、修改检查项、新增点位类型或配置多套计划。`general_inspection_*` 仅作内部表名和历史兼容数据域，不是产品名称。

“巡检管理”分成完全独立的两个专区：

- 电箱巡检：继续使用电箱台账、六项日检、专用月表、统一二维码和原整改流程。
- 临边巡检：使用 8 类系统固定检查表，提供点位、项目周期设置、任务、记录、整改、统计和 Web 含图 Excel 导出。

临边巡检不再设置项目试点或启停开关。项目有效成员在具备 `INSPECTION` 模块和对应
`EDGE_INSPECTION_*` 权限后直接使用；历史 `general_inspection_project_setting` 只保留数据兼容，
不再参与接口鉴权、任务生成、附件访问或两端展示。

## 点位、任务与个人数字口径

- 点位是 Web 登记的固定检查位置；任务是某个点位在某个计划日期的一次现场巡检。两者不是同一
  数量。项目有 8 个启用点位且使用每日周期时，每个执行日生成 8 项任务，连续 7 天就是 56 项任务。
- `enabledPointCount` 是项目范围的启用点位数。`myToday* / myOverdue* / myRectification* /
  myReview*` 全部是当前登录用户范围，Web 项目统计和小程序“我的任务”不得再直接比较或共用标签。
- 后台可按调度窗口提前生成任务，但 `availableTime` 到达前，未来任务和相应待改派事项都不进入个人
  待办。进入窗口后正常显示；超过截止时间仍未提交的任务进入逾期补检，补交后永久保留迟交事实。
- 业务主流程固定为“点位设置 → 自动生成任务 → 小程序巡检 → 异常整改 → 复查闭环”。正常任务提交
  后完成；异常任务按任务聚合为一张整改单，全部异常关闭后任务闭环。

### 计划启用与任务生成边界

- 项目首次启用或从停用恢复周期设置时，如果当天执行时段已经开始但尚未超过截止时间，系统仍生成
  当前时段任务，并使用本次启用版本中的巡检人、整改人和复查人快照。超过截止时间后不再追补该时段。
- 新建点位与计划启用采用不同边界：点位只进入其创建后的适用任务，不反向生成点位创建前已经开始的
  当日任务。停用点位继续取消未提交任务，且首版不可恢复。
- 生成器按 `Asia/Shanghai` 判断开始与截止；每个计划在取得计划行锁后重新读取业务时间。跨午夜时段
  每轮至少回看前一业务日，防止 25 小时预生成游标跨日后漏掉仍未截止的前夜任务。
- 任务唯一约束和生成游标继续保证重复调度不重复写入；已生成任务的人员、计划版本和检查项快照不被
  后续设置修改覆盖。

## 固定点位类型和检查表

系统内置且只允许以下 8 类点位，每类对应一份不可编辑、不可删除的固定检查表：

1. 楼层、阳台及挑檐边。
2. 楼梯口、平台及梯段边。
3. 屋面边。
4. 基坑、沟槽边。
5. 洞口、预留洞。
6. 电梯井口、井道。
7. 升降机、物料提升机停层平台。
8. 接料、卸料平台。

每份表约 5 项，任务生成时根据点位类型选择对应系统模板，并保存不可变检查项快照。只允许 `NORMAL / ABNORMAL`，不提供“不适用”。检查提示和规范依据只读展示。

参考依据为现行公开的 [JGJ 80-2016](https://zjw.sh.gov.cn/xcsc2020-jsbz/20200430/f141c8d12a494a1c8a9eb155a6e420ce.html)、[JGJ 311-2013](https://zjw.sh.gov.cn/xcsc2020-jsbz/20200430/b6b94960c50e48fd83484b27845f1c6d.html)、[GB 55034-2022](https://szwb.sz.gov.cn/gwszwfw/zsk/hybz/index_5.html) 和[房屋市政工程生产安全重大事故隐患判定标准（2024 版）](https://zjw.sh.gov.cn/xwfb/20241224/8929913b394e4777b7ccb79921251af4.html)。系统检查表只用于日常巡检，不能替代项目专项施工方案、验收和法定责任。

## Web 与小程序交互

Web 临边专区固定为 3 个子页：

- 三页上方常驻紧凑流程条，明确当前项目启用点位数，并可打开说明抽屉查看“启用点位 × 计划日期 =
  执行日任务数”、各角色职责及状态流转。Web 数字标注为项目范围，小程序数字标注为“我的”。

- 待处理：默认首页，只显示逾期未提交任务、`UNASSIGNED / PENDING / REJECTED` 整改单和
  `COMPLETED` 待复查整改单。同一异常任务只展示整改单，逾期优先并按期限升序排列；任务和整改单
  详情、改派均从右侧抽屉进入。
- 巡检记录：只显示临边任务，状态为待巡检、逾期未检、按时完成、逾期补检、整改中、已闭环或
  已取消。日期、点位、类型和状态筛选常驻，表格只保留五组核心信息；批量取消按需进入选择模式。
  统计由页面右侧抽屉承载，后台含图 Excel 支持最长 31 天以及全部或指定点位。
- 基础设置：上方只读展示项目当前周期、时段、责任人、整改期限和状态，修改时才打开编辑弹窗；
  下方直接维护点位台账。点位只填写名称、固定类型、楼栋、楼层和位置说明，编码由服务端生成。
  已生成任务的点位不能修改类型；停用自动取消未提交任务且首版不可恢复。每项目只保留
  `EDGE_PROJECT_SCHEDULE` 一套设置，支持每天、每周指定星期、每月 1—31 日或月末和单一时段。

小程序巡检首页和个人待办都把“电箱巡检”和“临边巡检”分区展示。临边首页主数字只显示项目
“启用点位”，另列“我的今日巡检 / 我的逾期补检 / 我的待整改 / 我的待复查”；首页仅预览本人今日
待巡检任务，没有本人任务时明确提示“项目有 N 个启用点位，但当前账号暂无本人任务”。

“我的临边巡检”固定为“今日巡检 / 逾期补检 / 巡检记录”三页：今日页显示当天全部状态和进度；逾期
页只显示超过截止时间仍未提交的任务；记录页默认显示最近 30 天已提交、整改中、闭环和取消任务。
整改与复查不混入这三页，继续使用独立“临边整改闭环”入口。任务卡采用纵向信息结构，点位名称、
类型、位置、日期时段、状态和操作各自成行，并统一清理业务可见文本中的演示标记。

临边表单必须满足：

- 每次任务至少 1 张现场全景照片。
- 所有检查项都必须选择正常或异常。
- 异常项必须填写说明并至少上传 1 张证据照片；正常项不要求单项说明和照片。
- 总备注选填，本地草稿保留选择、文字和持久化照片路径；正式提交前必须联网重新校验任务、权限和快照版本。

## 整改与复查

一次巡检的全部异常项在数据库内仍逐项保存，但对外只提供一张聚合整改单：

1. 整改人必须对每个异常项填写整改说明并上传至少 1 张整改后照片，一次事务性提交全部项。
2. 全部异常反馈成功后，整单进入待复查。
3. 复查人只能“全部通过并关闭”或“整单退回整改”；退回原因必填。
4. 管理者可以改派整改人或复查人，但必须填写原因并写入操作日志。
5. 执行、整改、复查均只允许当前明确指派人。平台管理员未被指派时也不能代替业务人员复查。
6. 复查退回前重新校验原整改人的项目成员与整改权限；已失效时整单转为 `UNASSIGNED` 并进入管理待分派，不把任务退给无权人员。

## 权限与接口

临边巡检接口同时校验项目有效成员、`INSPECTION` 业务模块和下列独立权限：

- `EDGE_INSPECTION_VIEW`
- `EDGE_INSPECTION_MANAGE`
- `EDGE_INSPECTION_SUBMIT`
- `EDGE_INSPECTION_RECTIFY`
- `EDGE_INSPECTION_REVIEW`
- `EDGE_INSPECTION_EXPORT`

含图 Excel 要求 `EDGE_INSPECTION_VIEW + EDGE_INSPECTION_EXPORT`；普通用户只能查看、下载本人创建的
任务，平台管理员可查看项目全部任务。临边权限不再依赖电箱的 `inspection.* / SUMMARY_*`，电箱
专区的台账、记录、统计、导出和整改授权也不由临边权限替代。

Web 菜单码为 `INSPECTION_EDGE / 临边巡检`。业务接口前缀统一为 `/api/v1/edge-inspections`，包含固定类型、点位、项目设置、任务、整改、统计和 `export-jobs`，不提供项目功能开关接口。`/api/v1/general-inspections/**` 和 `/api/v1/public/general-inspection-points/**` 不再注册为业务接口。

`GET /projects/{projectId}/workspace-summary` 使用 `Asia/Shanghai` 一次返回项目启用点位数和当前用户
今日任务总数、今日待巡检、今日已提交、今日已取消、历史逾期、待整改、待复查。今日总数包含已提交
和已取消任务；已提交以 `submitted_time` 为准；整改和复查按整改单 `taskId` 去重，只计算明确指派
本人，`UNASSIGNED` 不算本人事项。接口校验有效项目范围、`INSPECTION` 模块及任一六项临边权限；
平台管理员继续使用既有全局放行，但未被指派时仍不能代替巡检、整改或复查人员执行业务动作。

临边任务照片使用 `EDGE_INSPECTION_TASK_PENDING`，整改后照片使用 `EDGE_INSPECTION_RECTIFICATION_PENDING`；只允许真实 JPEG/PNG/WebP 等栅格图片，单图最大 15MB。

## Web 工作台与含图导出

Web 顶部“电箱巡检 / 临边巡检”使用紧凑分段切换，不再显示独立“巡检管理”说明卡或大尺寸专区卡。
临边三个普通页签不显示说明和全量数量，仅待处理存在非零红色徽标。首次只加载待处理所需的逾期
任务与未闭环整改单，记录、设置和统计在进入页面或打开抽屉时按需加载。记录详情、整改详情和统计
均使用右侧抽屉；页面本身禁止整体横向滚动，窄屏常驻筛选允许自然换行，只有超宽表格允许在自身
容器内滚动。

导出工作簿固定包含“巡检汇总”、每点位一张“临边检查记录表”、“照片明细”和“整改明细”。创建时
冻结任务 ID，单次最多 31 天、500 个任务、800 张照片、120MB 原始照片；取消任务进入明细但不计
应检和漏检，损坏或缺失图片只在对应单元格标记“图片不可读取”。成功或失败均生成站内通知，文件
保留 7 天。

## 明确不实现的首版范围

首版不提供用户模板、项目模板复制、自定义检查项、自定义点位类型、多套计划、多时段、临时任务、备选人、逐点人员覆盖、临边点位二维码、手机定位、匿名月表或公开页。含图 Excel 仅在登录后的 Web 管理端异步生成。
