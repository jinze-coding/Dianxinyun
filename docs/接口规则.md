# 接口规则

## 2026-09-11 会议资料接口

内部资料组 `/api/v1/site-access/invitations/{id}/materials`、`/site-access/materials/{id}`、
`/site-access/material-versions/{id}` 与会议分片上传接口支持列表、版本、发布、撤下、预览和下载。
GET 读取使用 view，变更使用 manage；文件 content 特例在控制器验证原登录绑定的 HttpOnly 短 Cookie，
每次重新检查登录和真实项目权限。开发代理保留 `/api/v1` 路径，确保 Cookie Path 匹配。

公开 POST `/api/v1/public/site-access/meeting/materials/resolve` 仅在请求体接收 inviteToken，允许已结束会议；
GET/HEAD `…/content/{publicCode}` 只接收随机版本资源编号，重新验证当前发布、资料、会议和项目状态，支持 Range。
公开资源编号可转发，旧公开版、撤下、内部资料和作废会议均拒绝读取；不恢复预约或签到会话。
完整接口表、请求字段及存储规则见 [会议资料专题](会议完整详情与资料留档.md)。

> [访客复用与门卫会议联动](访客复用与门卫会议联动.md)。


## 2026-09-02 共享会议现场签到接口

所有路径以 `/api/v1` 为前缀。内部接口继续经过 `SITE_ACCESS` 模块、目标项目范围和
`site_access.view/manage/export` 校验；公开接口只通过请求体接收不透明 scene，并在业务解析前执行
受信 IP 限流，建立会话后再按用途隔离微信身份限流。

| 方法与路径 | 权限/请求 | 关键规则 |
| --- | --- | --- |
| `GET/PUT /site-access/invitations/{id}/meeting-check-in/settings` | `view/manage` | 读取或更新签到窗口、50～2000 米留痕半径；只允许会议邀请 |
| `POST .../meeting-check-in/status`、`POST .../rotate` | `site_access.manage` | 停用/启用或轮换；每场仅一个当前码，旧码立即失效，写会议审计 |
| `GET .../meeting-check-in/mini-code` | `site_access.manage` | 返回 `MC:` scene 对应小程序码，不复用 `M:` 邀请码 |
| `GET .../meeting-attendance/summary`、`GET .../meeting-attendees` | `site_access.view` | 返回五项统计和按来源、签到状态、定位结果、关键词分页人员台账 |
| `POST .../meeting-attendees/walk-ins` | `site_access.manage` | 工作人员现场补录登记组；微信身份可空，原因必填 |
| `POST /site-access/meeting-attendees/{personId}/manual-check-in` | `site_access.manage` | 服务端当前时间或窗口内且不晚于当前的历史时间；原因必填 |
| `POST .../{personId}/revoke`、`PUT .../{personId}` | `site_access.manage` | 撤销签到或更正人员；按人员真实会议/项目鉴权、乐观冲突 HTTP 409、原因必填 |
| `GET /site-access/meeting-attendance/export` | `site_access.export` | 最多 50000 人，固定“签到汇总/参会人员明细”两 Sheet，公式注入防护并写导出审计 |
| `POST /public/site-access/meeting-check-in/session` | 公共；`scene/wechatCode` | scene、会议、项目、AppID 与微信身份绑定；校验窗口、二维码状态及会议状态后返回预约组或现场表单 |
| `POST /public/site-access/meeting-check-in/confirm` | `X-Visitor-Session` | 预约组逐人签到；跨组人员固定 403，重复/并发幂等，多人任一步失败整组回滚 |
| `POST /public/site-access/meeting-check-in/walk-in` | `X-Visitor-Session` | 未预约身份原子创建 `WALK_IN` 登记、人员、签到和审计，同身份重试不重复建组 |
| `POST /public/site-access/meeting-check-in/profiles/list\|detail\|disable` | `X-Visitor-Session` | 仅当前项目、AppID 和微信身份的本人常用资料，签到窗口或会话失效后拒绝 |

公共定位请求接收一次性 GCJ02 经度、纬度和精度，只用于即时计算；数据库和普通日志只允许保存
`IN_RANGE / OUT_OF_RANGE / UNAVAILABLE / NO_REFERENCE / MANUAL`、距离、精度和项目定位版本。

## 2026-08-26 固定式临边巡检接口

临边业务接口统一前缀 `/api/v1/edge-inspections`，不再对业务客户端提供
`/api/v1/general-inspections`：

| 资源 | 主要接口 | 服务端约束 |
| --- | --- | --- |
| 固定类型 | `GET /point-types` | 只返回系统预设 8 类；无新增、修改或删除接口 |
| 点位 | `GET/POST /points`、`PUT /points/{id}`、`POST /points/{id}/status/{status}` | 所属项目不可变；产生任务后类型不可修改；停用取消未提交任务并写审计 |
| 项目设置 | `GET/PUT /projects/{projectId}/setting`、`GET /user-options` | 每项目一套设置、一个时段、统一人员；后端校验每天/每周/每月频率及人员资格 |
| 工作台汇总 | `GET /projects/{projectId}/workspace-summary` | 返回项目启用点位数和当前用户的今日巡检、逾期、待整改、待复查数量；使用上海业务日期，整改和复查按整改单去重 |
| 任务 | `GET /tasks`、`GET /tasks/{id}`、`POST /tasks/{id}/submit`、`POST /tasks/cancel`、`POST /tasks/{id}/reassign` | 任务按点位类型带固定检查项快照；提交、取消和改派使用乐观版本及记录级权限 |
| 整单整改 | `GET /rectifications`、`GET /rectifications/{taskId}`、`POST /rectifications/{taskId}/reassign|complete|close|reject` | 以任务 ID 聚合全部异常；整改逐项反馈，复查只能整单关闭或整单退回 |
| 统计 | `GET /statistics` | 只统计临边应检、按时完成、逾期补检、仍未检、异常点位和整改关闭率 |
| 含图导出 | `POST/GET /export-jobs`、`GET /export-jobs/{id}`、`GET /export-jobs/{id}/download` | 创建时固化任务 ID；后台生成、七天有效；普通用户只访问本人任务，平台管理员可查看项目全部任务 |

任务提交请求只接受服务端快照项 ID：

```json
{
  "expectedVersion": 1,
  "overallPhotoFileIds": [101],
  "remark": "选填总备注",
  "items": [
    {"taskItemId": 201, "result": "NORMAL"},
    {"taskItemId": 202, "result": "ABNORMAL", "description": "异常说明", "photoFileIds": [102]}
  ]
}
```

`overallPhotoFileIds` 至少 1 张；结果只允许 `NORMAL / ABNORMAL`；异常项必须有说明和至少 1 张真实
栅格证据图。整单整改 `complete` 请求按异常项提交
`rectificationId + expectedVersion + feedback + photoFileIds`，每项至少 1 张整改后照片；`reject`
的 `comment` 必填，`close` 的 `comment` 选填。

临边图片仍通过 `/api/v1/files` 上传，暂存业务类型仅为
`EDGE_INSPECTION_TASK_PENDING / EDGE_INSPECTION_RECTIFICATION_PENDING`，正式绑定后去掉
`_PENDING`。首版没有模板、自定义类别、二维码、扫码校验、匿名月表和公开接口；电箱既有
统一二维码和公开月表接口保持原路径及语义。

含图导出创建参数为 `projectId/startDate/endDate/pointIds`，`pointIds` 为空表示全部点位。日期闭区间
最长 31 天且结束日期不得晚于当天；单次最多 500 个任务、800 张照片和 120MB 原始照片，每人最多
同时存在 2 个 `PENDING/RUNNING` 任务。导出要求 `EDGE_INSPECTION_VIEW + EDGE_INSPECTION_EXPORT`。
取消任务保留在明细但不计应检和漏检；损坏或缺失图片在工作簿中标记，不终止整份导出。

临边没有项目试点或功能启停接口；`GET/PUT /projects/{projectId}/feature` 已移除。项目能否访问临边
巡检只由有效项目范围、`INSPECTION` 模块、六项 `EDGE_INSPECTION_*` 权限及当前任务指派决定。

工作台汇总响应固定为：

```json
{
  "enabledPointCount": 8,
  "myTodayDueCount": 8,
  "myTodayPendingCount": 8,
  "myTodaySubmittedCount": 0,
  "myTodayCancelledCount": 0,
  "myOverdueCount": 2,
  "myRectificationPendingCount": 1,
  "myReviewPendingCount": 1
}
```

`enabledPointCount` 是项目范围的启用点位数；其余字段均为当前登录用户范围。`myTodayDueCount` 是本人
当天被指派的全部任务，包含已提交和已取消任务，便于与当日进度对账；`myTodaySubmittedCount` 以
`submitted_time` 为准，覆盖 `COMPLETED / RECTIFICATION_PENDING / CLOSED`。`myOverdueCount` 只统计
截止时间早于上海当前时间且仍为 `PENDING` 的本人任务；整改只计本人 `PENDING / REJECTED`，复查只计
本人 `COMPLETED`，二者均按 `taskId` 去重，`UNASSIGNED` 不算本人待办。接口要求有效项目范围、
`INSPECTION` 模块和任一 `EDGE_INSPECTION_*` 权限，平台管理员继续按既有全局规则放行。

任务可以由调度器提前写入数据库，但 `/me/todos` 和 `/me/work-summary` 在任务 `availableTime` 到达前
不生成临边巡检或待改派待办；进入执行窗口后正常展示，截止后的 `PENDING` 任务继续作为逾期补检。

## 2026-08-14 预约邀请项目定位与导航接口

统一前缀为 `/api/v1`。本次复用 `project_info` 既有定位字段，没有数据库迁移，也不新增公开接口。

| 方法与路径 | 请求/权限 | 关键规则 |

`projectLocation` 结构如下：

```json
{
  "address": "项目公开地址",
  "navigable": true,
  "longitude": 121.000000,
  "latitude": 31.000000,
  "coordinateType": "GCJ02"
}
```

后端只在坐标完整、范围有效且存储坐标系为 `BD09 / GCJ02 / WGS84` 时设置 `navigable=true`，并统一

坐标系；地址变化必须通过定位接口与坐标一起保存。现有预约码按解析时读取项目当前定位，无需轮换。
门卫固定登记码的公开会话与提交响应本次不增加 `projectLocation`。

标准微信注册提交时，Redis 微信临时身份使用一次性占用标记防止并发重复消费。申请事务
提交成功后清理占用标记；字段校验、重复申请或数据库写入导致事务回滚时，恢复原临时身份
会话及 10 分钟有效期并释放占用，允许用户修正表单后重试，无需重新微信授权。

## 电箱巡检极简版接口口径（2026-08-26 兼容提交加固）

当前巡检产品保留：

- `POST /api/v1/inspection/records`：完成巡检；外观照片和内部照片必须各有至少 1 个有效文件 ID，
  备注可为空，异常项说明不可为空。六项均正常时写入 `COMPLETED`；存在异常时必须选择同项目
  合格电工和整改期限，记录写入 `RECTIFICATION_PENDING` 并聚合创建一条整改任务。
- `POST /api/v1/inspection/records/{id}/submit`：仅为旧客户端兼容；事务内锁定目标记录，只允许已
  绑定外观、内部照片各至少 1 张的历史 `DRAFT` 完成。对当前已是 `COMPLETED /
  RECTIFICATION_PENDING / CLOSED` 的记录幂等返回，其他历史状态返回 HTTP `409`，不得覆盖异常
  整改或历史复核状态。
- `GET /api/v1/inspection/records`、`GET /api/v1/inspection/records/{id}`：查询当前真实记录状态；
  不再返回历史逐条复核操作留痕。
- `GET /api/v1/inspection/todos`：返回 `INSPECTION` 今日待巡检、当前负责人
  `RECTIFICATION` 待整改和安全员 `RECHECK` 待复查任务，不生成新的历史 `REVIEW` 待办。
- `GET /api/v1/inspection/records/summary`：供 Web 与小程序计算月度或单日应检、已检、漏检和异常统计。
- `GET /api/v1/inspection/records/export`：继续兼容 Web 与小程序月表；Web 还可通过 `startDate/endDate/boxIds` 导出日期范围内的单箱、部分电箱或全部电箱正式报表。
- `GET /api/v1/scan/electric-boxes/{sceneCode}`：一码两用分流。拥有 `INSPECTION_DAILY_SUBMIT` 的项目巡检员始终返回 `directAction=START_INSPECTION`；当天已有记录时同时返回 `todayRecordId`，巡检页据此只读回显。领导返回 `VIEW_RECORDS`，外部返回 `VIEW_PUBLIC_MONTHLY`。
  调用者没有目标项目巡检权限且该电箱已关闭公开访问时，接口在巡检范围和当天记录查询
  前返回 HTTP `403`，不得返回电箱编号、名称、位置等元数据；匿名公开扫码不查询当天
  内部巡检记录。
- `GET /api/v1/public/electric-boxes/{publicCode}/monthly-records`：外部只读月表。
- `/api/v1/inspection/rectification-assignees` 与 `/api/v1/inspection/rectifications*`：当前异常巡检
  整改闭环正式接口，覆盖候选电工、列表/详情、整改提交、改派、复查关闭和退回。

已退出 Controller 映射：历史逐条巡检复核、复核人改派、复核日志和安全抽查。历史 Service、表和
数据暂留用于兼容，不允许新前端继续调用这些旧接口；当前整改接口不属于退出范围。

## 接口基础规则

后端基础路径：`/api/v1`。

前端请求基础路径：`/api`。

Vite 代理规则位于 `frontend/vite.config.js`：

```js
proxy: {
  '/api': {
    target: 'http://localhost:8080',
    changeOrigin: true,
    rewrite: (path) => path.replace(/^\/api/, '/api/v1'),
  },
}
```

因此前端调用 `get('/projects')` 实际请求：

```text
前端：/api/projects
后端：/api/v1/projects
```

## 返回格式

大多数接口返回：

```json
{
  "code": 200,
  "message": "success",
  "data": {}
}
```

对应类：`backend/src/main/java/com/example/siteplatform/common/Result.java`。

异常规则：

- 业务异常使用 `BusinessException`。
- `GlobalExceptionHandler` 会将异常转成 `Result.error(code, message)`。
- HTTP 状态与业务码保持一致：参数错误、未登录、无权限、资源不存在和冲突分别使用 `400 / 401 / 403 / 404 / 409` 等实际状态；前端同时检查 HTTP 状态和 `res.code`。
- 文件下载接口是例外，返回 `ResponseEntity<Resource>`。

## 登录态和 token 处理方式

登录接口：

```text
POST /api/v1/auth/login
```

成功后返回：

```json
{
  "token": "JWT",
  "userId": 1,
  "username": "admin",
  "realName": "系统管理员"
}
```

前端保存位置：

- token：`localStorage.site_platform_token`
- 用户信息：`localStorage.site_platform_user`

axios 请求拦截器位于 `frontend/src/services/api.js`，会自动添加：

```http
Authorization: Bearer <token>
```

后端常见读取方式：

```java
@RequestHeader(value = "Authorization", required = false) String token
authService.getCurrentUser(token)
```

重要规则：

- 后端不能信任前端传入的 `userId`、`username`、`role`。
- 当前登录用户必须从 JWT 解析获得。
- 涉及当前用户、上传人、权限判断的数据，必须以后端登录态为准。
- 涉及 `projectId` 的接口必须校验当前用户是否有该项目权限。

当前规则：

- `AuthService.getCurrentUser` 同时校验 JWT 与 Redis 会话键；同一账号可保留多个独立会话。
- 当前正式资料、巡检、质量接口已增加通用操作权限守卫，并继续由业务服务校验项目范围；摄像头、设备等本期隐藏旧模块仍待单独补齐细粒度项目权限。

## 当前主要接口清单

### 认证接口

#### POST /api/v1/auth/login

前端方法：`login(username, password)`，文件 `frontend/src/services/auth.js`。

用途：用户登录并获取 token。

请求体：

```json
{
  "username": "example_user",
  "password": "用户设置的密码"
}
```

返回：

```json
{
  "code": 200,
  "message": "success",
  "data": {
    "token": "JWT",
    "userId": 1,
    "username": "admin",
    "realName": "系统管理员"
  }
}
```

权限：无需 token。

注意：

- 不提供默认测试账号或明文密码提示。
- 数据库存储 BCrypt 摘要，密码必须为 8–72 位并同时包含字母和数字；非 BCrypt 历史密码和待重置账号拒绝登录。
- 管理员密码只能通过系统管理重置，或在启动时同时提供一次性的 `ADMIN_RESET_USERNAME`、`ADMIN_RESET_PASSWORD` 环境变量显式重置。
- 每次登录签发带唯一 `jti` 的 JWT，并写入独立 Redis 会话，不会覆盖同一账号在其他端的 Token。
- 密码登录和微信绑定登录同时按真实客户端 IP、规范化账号执行两组独立限流；账号限流不随
  IP 改变而重置。Redis 键只保存使用当前环境 JWT 密钥生成的 HMAC-SHA256 摘要，不保存
  明文用户名、手机号、IP 或扫码 challenge。

#### GET /api/v1/auth/user-info

用途：获取当前登录用户信息。

请求头：

```http
Authorization: Bearer <token>
```

返回：`CurrentUserVO`，不包含密码。

核心字段：

- `id`, `username`, `realName`, `phone`, `email`, `status`, `passwordLoginEnabled`
- `wechatBound`, `wechatBindingStatus`
- `roles`: 当前用户全局角色编码列表，例如 `PLATFORM_ADMIN`
- `menus`: 按角色聚合的菜单树
- `permissionCodes`: 平台角色聚合的通用操作权限码
- `projectRoles` / `projectContexts`: 当前用户项目级授权列表，字段包括 `projectId`、`projectName`、`shortName`、`projectRoleCode`、`permissionTemplateId`、`permissionTemplateName`、`permissionTemplateCode`、`permissionCodes`
- `accessibleProjectIds`: 当前用户可访问项目 ID 列表

说明：

- 平台管理员返回全部项目，项目职责和权限模板按 `PLATFORM_ADMIN` 表示，并拥有全部电箱巡检权限码。
- 非平台管理员按 `sys_user_project` 返回授权项目、兼容项目职责和电箱巡检权限模板。
- PC 和小程序只用该接口做按钮显隐，后端接口仍必须独立校验权限。

权限：登录用户。

#### POST /api/v1/auth/logout

用途：登出并仅删除当前 Token 对应的 Redis 会话。账号停用、微信停用或解绑时，后台仍会清理该用户全部会话。

权限：登录用户。

#### PUT /api/v1/projects/{projectId}/location

用途：更新项目定位信息。

请求体：

```json
{
  "longitude": 121.543743,
  "latitude": 31.233568,
  "province": "上海市",
  "city": "上海市",
  "district": "浦东新区",
  "address": "上海市浦东新区陆家嘴环路1000号",
  "coordinateType": "BD09",
  "expectedVersion": 7
}
```

返回：`ProjectMapPointVO`。

校验：

- `longitude`: 必填，范围 -180 到 180。
- `latitude`: 必填，范围 -90 到 90。
- `coordinateType`: 只允许 `BD09`、`GCJ02`、`WGS84`，为空默认 `BD09`。
- `expectedVersion`: 必填，必须等于当前 `profile_version`；版本不一致返回 HTTP `409`。
- `province/city/district`: 各最长 64 字符；`address` 最长 500 字符。

权限：

- 平台管理员可更新。
- 对该项目有权限的项目管理员可更新。

副作用：

- 写入 `sys_operation_log`，`operationType = UPDATE_PROJECT_LOCATION`。
- 项目行在事务内锁定；地址、坐标、坐标系和 `profile_version + 1` 与审计日志原子写入。版本冲突或
  任一步影响行数不是 1 时返回 HTTP `409` 并回滚。

#### POST /api/v1/projects

用途：新增项目。

请求体：`ProjectInfo`。

权限：当前代码仅平台管理员。

字段规则：项目名称必填且最长 200 字符；简称、面积、阶段和项目经理最长 50，工期最长
100，安全/质量目标和施工单位最长 200，项目描述最长 5000 字符。状态只允许
`normal / warning / danger / stopped`，截止日期不能早于开工日期。请求中的 `id`、删除
标记和创建/更新时间被忽略；新增未传状态时默认 `normal`。

#### PUT /api/v1/projects/{projectId}

用途：更新项目基础信息。

请求体：`ProjectInfo`。

权限：当前代码仅平台管理员。

更新字段规则与新增一致，通用更新不能覆盖主键、删除标记和创建时间；写入影响行数不是
1 时返回 HTTP `409`。

#### DELETE /api/v1/projects/{projectId}

用途：删除项目。

权限：当前代码仅平台管理员。

安全规则：仅允许删除不存在任何成员、角色、资料、巡检、质量、人员、设备、摄像头、
微信申请等关联记录的空项目。存在任一关联记录时返回真实 HTTP `409`，不得只删除
`project_info` 主记录，也不得由该接口级联清理业务数据。

### 质量周检与问题闭环接口

统一鉴权前提：质量接口必须先校验目标项目 `ACTIVE` 访问、`QUALITY` 模块和
`quality.view`；写动作再按 `quality.manage`、`quality.rectify`、`quality.review`
细分。普通项目角色与受保护项目角色使用同一权限码规则，不再额外要求
`PROJECT_ADMIN` / `SAFETY_ADMIN` 固定角色编码。

当前整改负责人。`passed` 必填；复查意见最长 1000 字符，退回时仍由服务层条件
校验为必填；复查照片最多 20 个有效正数文件 ID。

权限：`quality.review`，不再额外要求 `quality.manage` 或固定管理角色。

#### POST /api/v1/quality/issues/{id}/assign

用途：Web/小程序管理端改派整改人或调整整体闭环期限，已关闭或已作废问题不允许
操作，变更写入 `ASSIGN` 留痕并提醒当前整改负责人。整改人 ID 如提供必须为正数，
期限不能早于当天，改派说明最长 1000 字符；整改人和期限至少提供一项的条件校验
继续由服务层执行。

权限：`quality.manage`。

#### POST /api/v1/quality/issues/{id}/void

用途：作废误建、重复或不属于质量问题的记录。具备 `quality.manage` 的用户可以把
`PENDING / RECHECK` 转为 `VOIDED`；作废原因必填且最长 1000 字符。操作写入
`VOID` 留痕，作废后不可整改、复查或改派，不计入逾期和闭环率分母。

整改、复查、改派和作废均以读取到的原状态和 `version` 作条件更新；并发操作只有一个
能够成功，其他请求返回 HTTP `409` 并要求刷新。微信提醒写入失败不会回滚业务状态。

统一权限：周检记录、问题列表、统计和详情需要 `quality.view`；共享草稿创建、整体保存、提交、
放弃以及问题改派、期限调整和作废需要 `quality.manage`；整改需要 `quality.rectify` 且满足“本人被指派或同时具备
`quality.manage`”；复查通过和退回只需要 `quality.review`。上述动作均继续要求目标
项目 `ACTIVE` 访问和 `QUALITY` 模块，不附加固定项目角色白名单。创建与改派使用同一
整改人资格校验，不能把问题指派给停用账号、暂停成员、质量模块不可见或缺少查看/整改
权限的人员。操作人一律从 token 解析，不接受前端伪造。所有质量写接口的 JSON 请求体
都经过 Jakarta Validation，字段缺失、超长、非法枚举、非法 ID 或过去日期统一返回
真实 HTTP `400`；退回意见、改派至少一项等条件约束继续由服务层校验。

### 工程资料库接口

后端代码：`backend/src/main/java/com/example/siteplatform/document/`。

前端方法：`frontend/src/services/document.js`。

字段口径：正式业务只使用 `folderId` 和 `status`。`folderId` 是当前项目内的一级资料目录，`status` 是归档状态，仅使用 `ACTIVE`（使用中）和 `ARCHIVED`（已归档）。历史 `category` 参数和字段只为旧数据/旧客户端兼容，正式 Web 与小程序不再展示、筛选或编辑资料类型。

- `GET /api/v1/document-folders?projectId={id}`：查询当前项目目录。
- `POST /api/v1/document-folders`：新建一级目录，`parentId` 必须为 `0`，仅平台/项目管理员。
- `PUT /api/v1/document-folders/{id}`：重命名目录，仅平台/项目管理员。
- `DELETE /api/v1/document-folders/{id}`：平台管理员携带统一确认结构删除目录；非空目录按预览结果级联资料和版本。
- `GET /api/v1/project-documents`：按项目、一级目录、名称/编号、归档状态、更新时间服务端分页查询；历史 `category` 查询参数继续兼容旧客户端。
- `GET /api/v1/project-documents/summary`：返回总数、使用中、已归档、近七日更新统计和当前用户 `canManage`；历史图纸/表格字段仅兼容旧客户端。
- `GET /api/v1/project-documents/recycle-bin`：管理员分页查询回收站。
- `GET /api/v1/project-documents/{id}`：返回资料属性、全部版本和最近操作。
- `POST /api/v1/project-documents`：`multipart/form-data` 上传资料并创建 V1。
- `POST /api/v1/project-documents/{id}/versions`：上传新版本；事务内锁定资料并递增版本号。
- `PUT /api/v1/project-documents/{id}`：修改名称、编号、一级目录和备注；历史 `category` 字段继续兼容旧客户端。
- `POST /api/v1/project-documents/{id}/archive|unarchive`：归档或管理员恢复归档。
- `DELETE /api/v1/project-documents/{id}`：仅平台管理员逻辑删除并进入回收站。
- `POST /api/v1/project-documents/{id}/restore`：管理员从回收站恢复。
- `DELETE /api/v1/project-documents/{id}/purge`：平台管理员携带统一确认结构永久删除全部版本和物理文件。事务内
  先标记文件元数据并删除资料关系，数据库提交后才删除物理对象；事务回滚不触碰原文件。
  提交后物理清理失败时保留逻辑删除元数据，避免数据库恢复而文件已经丢失。
- `POST /api/v1/project-documents/batch`：批量 `MOVE`、`ARCHIVE`、`DELETE`；其中 `DELETE` 仅平台管理员。
- `GET /api/v1/project-documents/{id}/preview|download`：预览或下载当前/指定版本，使用可选 `versionId`。
- `POST /api/v1/project-documents/{id}/client-actions`：记录小程序原生保存菜单成功打开或文件成功发送给微信好友。
- `GET /api/v1/project-documents/activities`：按项目或资料查询操作记录。

字段边界：资料名称必填且最长 200 字符，资料编号最长 100 字符，资料备注和版本说明
最长 500 字符。服务端必须在存储物理文件前完成校验，超长字段返回 HTTP `400`，不得
交给数据库产生截断错误或 HTTP `500`。

写入完整性：目录、文件元数据、资料主记录、版本、当前版本指针、归档/回收站状态、
恢复、永久删除及操作日志的单记录写入都要求数据库影响行数为 1。任一步未生效返回
HTTP `409` 并回滚；上传事务回滚时清理本次新物理文件，永久删除仍只在数据库提交后
清理旧物理文件。批量操作中任一资料失败时整个事务回滚，不返回部分成功。

权限：授权项目成员可查询、预览、下载和上传；上传人可维护自己的使用中资料；授权项目 `PROJECT_ADMIN` 可管理资料、目录和恢复；移入回收站、目录删除和永久删除只允许平台管理员。所有身份从 JWT 获取，所有资料和目录均按 `projectId` 校验。

上传人：创建资料和版本时，上传用户 ID 始终从当前 JWT 获取；列表与详情展示实时查询 `sys_user.real_name`，姓名为空才回退 `username`，前端不能自行提交上传人姓名。

客户端：Web 使用完整桌面管理能力；小程序 `src/api/document.ts` 使用同一组接口，提供单条资料核心闭环和管理员目录/回收站，不建立移动端专用资料接口。

存储：默认 `file.storage.type=local`，文件落在 `file.upload.path`；可通过环境变量配置 MinIO。文件写入后数据库事务失败会补偿删除新文件。

上传安全：单个工程资料最大 50MB；服务端同时校验扩展名和文件头，支持 PDF、栅格图片、
Office/WPS、CAD、安全文本和常见压缩包，拒绝 HTML、SVG、脚本和可执行文件。只有 PDF
与栅格图片允许 `inline`，其他格式即使调用预览接口也会强制 `attachment`；全部文件流
返回 `X-Content-Type-Options: nosniff`。

#### POST /api/v1/project-documents/{id}/client-actions

用途：在小程序完成原生客户端文件操作后，为目标资料和版本补充操作留痕。下载接口原有的“下载”记录继续保留，本接口只记录下载之后的最终客户端动作。

请求体：

```json
{
  "action": "OPEN_SAVE_MENU",
  "versionId": 123
}
```

`action` 只允许：

- `OPEN_SAVE_MENU`：PDF 或 Office 文档已由 `openDocument({ showMenu: true })` 成功打开，操作记录显示“打开保存菜单”。
- `SHARE_WECHAT_FILE`：`wx.shareFileMessage` 已成功完成文件发送，操作记录显示“发送文件”。

返回：`Result<ProjectDocumentActivityVO>`，内容为本次新增的资料操作记录。

权限与校验：

- 沿用资料查看权限；服务端先查询路径中的资料，再按资料真实 `projectId` 校验当前 JWT 用户。
- `versionId` 可省略，省略时使用资料当前版本；传入时必须属于路径中的目标资料，当前版本和历史版本执行相同校验。
- 客户端只有在微信原生 API 成功回调后才调用本接口；用户取消、格式不支持、基础库过低、下载失败或原生操作失败均不写对应的最终动作记录。
- 本接口复用现有 `sys_operation_log` 与 `PROJECT_DOCUMENT_{projectId}` 业务类型，不新增数据库表、字段或迁移。

用途：获取文件详情。

用途：下载文件。

返回：文件流。

权限：先查询文件，再按文件所属项目校验访问权。

- 成功返回文件时写入 `FILE_DOWNLOAD` 操作记录。

用途：在线预览文件。

返回：文件流。只有 PDF 和真实栅格图片使用 `Content-Disposition: inline`；其他历史

权限：先查询文件，再按文件所属项目校验访问权；成功返回时写入 `FILE_PREVIEW` 操作记录。

#### GET /api/v1/files/activities

用途：查询当前项目的资料操作记录。

查询参数：

- `fileId`: 可选，限定单个资料。

#### POST /api/v1/files

用途：上传文件。

Content-Type：`multipart/form-data`。

表单字段：

- `file`: 必填。
- `projectId`: 必填。
- `fileName`: 可选。
- `fileType`: 默认 `其他`。
- `businessType`: 可选。
- `businessId`: 可选。
- `remark`: 可选。

返回：`FileResource`。

规则：

- 同一项目下未删除文件不允许同名。
- 文件存储目录取 `file.upload.path`，默认 `./uploads`。
- `uploaderId` 使用当前登录用户 ID。
- 新上传文件的 `status` 固定写为 `UPLOADED`。
- 人员证件附件还必须以 `PERSON_CERTIFICATE` 类型上传；未绑定附件只能由上传人本人
  绑定，已绑定附件不能被其他证件抢占。质量附件继续使用各自暂存业务类型。
- 服务端同时校验文件大小、扩展名和文件头，不信任浏览器 `accept` 或客户端 MIME。
- 巡检及质量流程照片只允许 JPG/JPEG、PNG、GIF、WebP、BMP、HEIC/HEIF，单张最大
  15MB；其他通用业务附件沿用工程资料安全白名单，最大 50MB。
- 全局 multipart 超过 50MB 返回 HTTP/业务码 `413`，不再返回笼统 `500`。

权限：上传前校验目标项目访问权。质量附件只允许以下类型：

- `QUALITY_PENDING`：需要 `quality.manage`；
- `QUALITY_WEEKLY_PENDING`：周检现场照片暂存，需要 `quality.manage`；
- `QUALITY_WEEKLY_ITEM_PENDING`：周检问题整改前照片暂存，需要 `quality.manage`；
- `QUALITY_RECTIFICATION_PENDING`：需要 `quality.rectify`；
- `QUALITY_REVIEW_PENDING`：需要 `quality.review`；
- `QUALITY_DOCUMENT`：需要 `quality.manage`，由 PC 端人工维护。

这些权限均在上传目标项目的 `ACTIVE` 范围和 `QUALITY` 模块内生效；普通项目角色
可以通过相应细分权限上传，不再附加 `PROJECT_ADMIN` / `SAFETY_ADMIN` 角色门槛。

上述质量暂存类型上传时 `businessId` 必须为空。`QUALITY_WEEKLY_PENDING` 只能转换为
`QUALITY_WEEKLY_DRAFT`，提交后转换为 `QUALITY_WEEKLY_INSPECTION`；
`QUALITY_WEEKLY_ITEM_PENDING` 只能转换为 `QUALITY_WEEKLY_DRAFT_ITEM`，提交后按问题隔离转换为
`QUALITY_ISSUE`。客户端不能直接上传
`QUALITY_ISSUE / QUALITY_RECTIFICATION / QUALITY_REVIEW / QUALITY_WEEKLY_INSPECTION` 最终附件；最终类型只能由
质量业务事务校验上传人、真实项目、暂存阶段及未绑定状态后转换。工程资料仍必须通过
独立资料管理接口上传。

质量暂存附件清理：

- 定时任务只处理 `QUALITY_PENDING`、`QUALITY_RECTIFICATION_PENDING`、`QUALITY_REVIEW_PENDING`、`QUALITY_WEEKLY_PENDING`、`QUALITY_WEEKLY_ITEM_PENDING` 五种未绑定暂存类型，并同时要求 `business_id IS NULL` 且 `create_time` 早于 TTL 截止时间。已绑定的 `QUALITY_WEEKLY_DRAFT / QUALITY_WEEKLY_DRAFT_ITEM` 是长期共享草稿附件，不受 24 小时暂存清理影响。
- 默认 TTL 为 24 小时、每小时执行一次、单批最多 200 条；可通过 `QUALITY_STAGING_CLEANUP_ENABLED`、`QUALITY_STAGING_CLEANUP_TTL_HOURS`、`QUALITY_STAGING_CLEANUP_BATCH_SIZE`、`QUALITY_STAGING_CLEANUP_INITIAL_DELAY_MS`、`QUALITY_STAGING_CLEANUP_FIXED_DELAY_MS` 配置。
- 清理前以条件更新抢占记录，业务绑定先完成时清理会跳过；清理先抢占时业务提交会失败并要求重新上传，避免已进入质量闭环的附件被误删。
- 物理文件删除成功后才永久删除元数据；单文件失败保留可重试记录、写入服务日志并继续处理后续文件。最终质量附件、`QUALITY_DOCUMENT`、工程资料和巡检附件不在该任务范围内。

请求体：`FileUpdateRequest`，可修改 `fileName`、`fileType`、`status`、`remark`；不允许通过该接口改变项目、上传人或物理路径。

`status` 只接受规范值 `UPLOADED`、`PENDING_CONFIRM`、`ARCHIVED` 及对应历史中文别名；
服务端写库前统一转换为规范值，未知值返回 HTTP `400`。

`QUALITY_ISSUE / QUALITY_RECTIFICATION / QUALITY_REVIEW` 禁止通过通用文件接口修改；
质量暂存附件还必须具备对应阶段权限，且只允许平台管理员或原上传人维护；

权限：平台管理员可见全部；项目/安全管理员可见授权项目；普通用户只看自己负责电箱和分配给自己的整改。

#### POST /api/v1/inspection/records

用途：新增电箱日检记录。当前极简巡检模式不再通过该接口新增安全员抽查。

请求体核心字段：

```json
{
  "projectId": 1,
  "electricBoxId": 1,
  "templateCode": "ELECTRIC_BOX_DAILY",
  "source": "ELECTRICIAN_DAILY",
  "problemCategory": "APPEARANCE",
  "checkDate": "2026-06-29",
  "outerPhotoFileIds": [1],
  "innerPhotoFileIds": [2],
  "assigneeId": 9,
  "requirement": "请按异常说明完成整改并上传现场照片",
  "deadline": "2026-07-02",
  "remark": "现场正常",
  "items": [
    { "itemCode": "APPEARANCE", "itemName": "内外观", "result": "NORMAL" }
  ]
}
```

业务规则：

- 服务端固定写入 `templateCode=ELECTRIC_BOX_DAILY`、`source=ELECTRICIAN_DAILY`，并忽略客户端伪造的模板、来源、问题分类和检查项名称。
- 外观照片和内部照片均为必填，每组 1–20 个正整数且不重复的文件 ID；缺少任一组时返回 HTTP `400`。请求中的照片必须全部通过上传人、项目、暂存类型和未绑定状态校验后才能创建记录。
- 请求必须恰好包含六个不重复的规范检查项：`APPEARANCE`、`LEAKAGE_PROTECTOR`、`FUSE`、`PROTECTIVE_ZERO`、`SOCKET_220V`、`SOCKET_380V`；名称统一由服务端写入。
- 每项结果只允许 `NORMAL`（正常）、`ABNORMAL`（异常）、`NA`（不适用）。
- 任一检查项为 `ABNORMAL` 时，`description` 必填且最长 500 字符；总备注最长 1000 字符。本轮不支持单项异常照片，只使用外观/内部照片。
- 存在任一异常项时，`assigneeId` 必填且必须是账号启用、项目访问有效、具有 `ELECTRICIAN`
  项目角色和 `inspection.rectify` 的当前项目电工；`deadline` 为空时默认当天后 3 天。项目还必须
  存在至少一名 `SAFETY_OFFICER + inspection.review` 的有效安全员，否则返回 HTTP `409`。
- 六项均正常时记录直接为 `COMPLETED` 且不建整改；一个或多个异常项只聚合生成一条
  `PENDING` 整改任务，记录为 `RECTIFICATION_PENDING`。
- 仅允许补录今天及往前 7 天，不能填未来日期。
- 服务端先对目标电箱行加锁，再检查同一电箱同一天只能存在一条有效日检；`REVIEW_REJECTED` 退回记录不计入有效重复，并发冲突返回 HTTP `409`。
- 巡检主记录、六条检查项和巡检设置均要求数据库影响行数为 1；未生效返回 HTTP `409` 并回滚整次写入和附件绑定。
- 项目内拥有 `INSPECTION_DAILY_SUBMIT` 的用户可巡检本项目任意启用且处于巡检范围内的电箱，不再依赖电箱负责人关系。

#### POST /api/v1/inspection/records/{id}/submit

用途：旧客户端兼容入口；当前新客户端不依赖该接口。服务端在事务内锁定目标记录，只允许照片

#### GET /api/v1/inspection/records/summary

用途：获取月度或单日巡检汇总。

查询参数：

- `projectId`: 必填。
- `boxId`: 可选。
- `month`: 可选，格式 `yyyy-MM`。
- `checkDate`: 可选，格式 `yyyy-MM-dd`。

`month` 与 `checkDate` 不能同时提交；格式不合法或 `checkDate` 为未来日期时返回 HTTP `400`。返回值新增：

- `periodType`: `MONTH` / `DAY`。
- `periodValue`: 对应的 `yyyy-MM` / `yyyy-MM-dd`。
- `month`: 继续保留，兼容只识别月度字段的旧客户端；日模式取所选日期所在月份。

返回：应检、已检、漏检、异常、未闭环整改数量和记录列表。

统计口径：

- 月模式下，`shouldCheck` 表示截至统计日已经到期的应检箱次，不表示电箱数量。
- 历史月份统计该月完整巡检范围；当前月份只统计到服务器当天；未来月份返回 `0`。
- `checked` 只统计巡检范围内、已到期且同箱同日去重后的有效记录。
- `missed = shouldCheck - checked`，未来日期不计入漏检。
- `records` 仍返回所选月份实际存在的巡检记录，未检任务不会伪造记录行。
- 日模式选择全部电箱时，`shouldCheck / checked / missed / abnormal` 分别表示当日应检、已检、未检和异常电箱数；选择指定电箱时各指标为 `0` 或 `1`。统计按该日有效巡检范围计算，同箱同日多条有效记录只计一次。

#### GET /api/v1/inspection/records/export

用途：导出月度巡检 Excel，或按日选择日期范围生成正式巡检报表。

查询参数：

- `projectId`: 必填。
- `templateCode`: 可选，默认 `ELECTRIC_BOX_DAILY`。
- `month`: 旧月报参数，可选，格式 `yyyy-MM`。
- `boxId`: 旧单箱月报参数，可选。

- 单箱文件名为 `{电箱编号}-电箱检查记录表-{yyyy-MM}.xlsx`，包含标题、工程名称、电箱信息、安装位置和检查月份。

- 传多个 `boxIds` 或不传任何电箱参数：仅允许 `SUMMARY_EXPORT`，生成巡检汇总和每个目标电箱的明细 Sheet。
- 日期范围汇总的应检、已检、漏检和异常按范围内历史巡检范围计算；检查项和范围历史批量加载，不逐日查询数据库。

### 小程序照片上传与回显规则

小程序真实模式 `VITE_USE_MOCK=false` 时：

- 照片先调用 `POST /api/v1/files` 上传，必须携带 `Authorization: Bearer <token>`。
- 日检照片建议参数：`projectId`、`businessType=inspection_record`、`fileType=INSPECTION_OUTER_PHOTO|INSPECTION_INNER_PHOTO`。
- 电工日检提交前必须分别取得至少 1 个外观照片和内部照片文件 ID；任一照片上传失败时不得调用业务提交接口，并清理本次已上传但尚未绑定的暂存文件。
- 首次提交日检时记录尚未生成，上传照片必须省略 `businessId`，不得传空值、`undefined` 或其他占位字符串；创建巡检记录时，服务端根据照片文件 ID 在同一事务内完成业务绑定。
- 历史安全抽查问题照片类型只作旧数据兼容，当前客户端不得再从扫码页发起安全抽查。
- 整改照片建议参数：`businessType=inspection_rectification`、`fileType=RECTIFICATION_PHOTO`；上传
  暂存时必须省略 `businessId`，提交整改接口根据文件 ID 在事务内校验并绑定任务。
- 业务接口只保存文件 ID，不直接保存匿名图片 URL。
- 图片回显通过 `GET /api/v1/files/{id}/download` 下载，仍需携带 token；小程序端用 `uni.downloadFile` 获取临时路径后展示。

#### GET /api/v1/public/electric-boxes/{publicCode}/summary

用途：外部人员扫码查看电箱近 30 天只读巡检汇总。

权限：无需登录。

访问控制：

- 仅按 `publicCode` 查询，不接受内部 `qrCode`。
- 对应电箱 `public_access_enabled = 1` 时才允许查看。
- 电箱公开访问被后台停用后，该接口返回业务错误，不继续展示历史汇总。
- 近 30 天摘要按真实客户端 IP 每 10 分钟最多 60 次；公开逐日月表每 10 分钟最多
  30 次。限流必须在巡检范围和记录查询前执行，超限返回 HTTP `429`。

脱敏规则：

- 只展示项目简称、电箱编号/名称/位置、状态、近 30 天起止日期、应检/已检/漏检/异常/未闭环数量和最近记录摘要。

  非巡检范围和未来日期不计入，`missedDays = shouldCheckDays - checkedDays`。
- 近 30 天摘要和公开逐日月表应一次加载目标日期范围的巡检范围历史，不得按自然日逐次
  查询数据库；批量解析不能改变历史范围和建箱日期口径。
- `recentRecords` 仅包含 `checkDate`、`inspectedAt`、`source`、`status`、`abnormalCount`。
- 不展示手机号、账号、内部用户 ID、检查人姓名、照片文件 ID、检查项明细、备注、复核人、复核意见或复核日志。
- 不提供任何写操作。

## 新增接口要求

### 2026-07-11 电箱统一巡检码接口

- `GET/PUT /api/v1/electric-boxes/{id}/inspection-scope`：查询或变更日检范围历史区间。变更前
  服务端锁定目标电箱，关闭旧开放区间并新增历史区间；任一步影响行数不是 1 时返回 HTTP
  `409` 并回滚。`reason` 最长 300 字符，操作人 ID/姓名来自登录态。
- `GET/PUT /api/v1/inspection/settings/{projectId}`：查询或保存项目截止时间和提醒设置。
- `GET /api/v1/scan/electric-boxes/{sceneCode}`：可选登录态解析 `B:<publicCode>`；巡检员进入可写/只读巡检页，领导进入本箱记录，未登录或无项目权限人员进入公开月表。
  该免登录入口按真实客户端 IP 每 10 分钟最多 60 次，并在可选登录态解析和业务查询前
  限流；超限返回 HTTP `429`。
- `GET /api/v1/electric-boxes/{id}/unified-code`：获取统一码预览。
- `POST /api/v1/electric-boxes/{id}/unified-code/rotate`：换码并使旧码失效。
- `GET /api/v1/public/electric-boxes/{publicCode}/monthly-records?month=yyyy-MM`：免登录公开逐日月表，限制最近 12 个月。
- `POST /api/v1/auth/wechat/session`、`POST /api/v1/auth/wechat/phone`：兼容旧扫码入口；手机号只用于判断“应绑定已有账号或应统一注册”，不能自动绑定。
- `POST /api/v1/auth/wechat/project-access`：已绑定用户扫码进入未授权项目时提交项目权限申请。
- `GET /api/v1/wechat-access-applications`：分页查询申请，支持 `projectId/status/keyword/page/size`；项目管理员只返回可管理项目。
- `POST /api/v1/wechat-access-applications/{id}/approve`：审批已有用户的项目访问。`permissionTemplateId`、项目职责、已有 `userId` 和审批意见必填；不再允许创建微信专用随机账号。
- `POST /api/v1/wechat-access-applications/{id}/reject`：拒绝申请，拒绝原因必填。

### 2026-07-12 微信绑定用户管理兼容接口

- `GET /api/v1/wechat-users`：分页查询已注册/绑定用户，支持项目、关键词、微信状态、项目状态、职责和权限模板筛选，返回 `{records,total,page,size}`。
- `GET /api/v1/wechat-users/{userId}`：平台管理员可不传 `projectId` 查看脱敏的全局管理详情；非平台管理员必须传入自己有管理权限的明确 `projectId`，且目标用户必须属于该项目。非平台管理员只返回该项目授权和该项目申请，不返回全局微信绑定历史或操作日志。所有响应均不返回 OpenID、UnionID。
- `PUT /api/v1/wechat-users/{userId}/bindings/{bindingId}/status`：平台管理员停用或恢复微信登录，原因必填；停用后当前登录令牌立即失效。
- `POST /api/v1/wechat-users/{userId}/bindings/{bindingId}/unbind`：平台管理员解绑微信，原因必填；不删除系统账号、项目授权和历史巡检记录。

权限规则：平台管理员可跨项目管理；拥有 `PERMISSION_MANAGE` 或当前项目 `system.project.manage` 的项目管理员只能在显式传入的授权项目内查询用户、申请、职责、模板和项目访问状态，不能枚举其他项目，也不能执行微信全局停用、恢复或解绑。

公开月表允许返回完整检查人姓名和业务备注，但禁止返回手机号、照片文件 ID、内部用户 ID、复核意见和操作日志。

新增接口必须：

1. 放在 `/api/v1/**` 下。
2. 使用 `Result<T>` 返回，文件流除外。
3. 明确请求参数和返回字段。
4. 需要登录的接口必须从 token 解析当前用户。
5. 涉及项目数据必须校验项目权限。
6. 不要信任前端传入的用户身份字段。
7. 写操作要考虑操作日志，至少重要业务如项目定位、删除、归档应记录。
8. 同步更新本文件和前端 `services` 封装。

前端把接口业务字段写入打印页、下载 HTML 或其他字符串模板时必须做 HTML 文本/属性转义，
并通过 CSP 限制资源；服务端返回的 SVG 或 Data URL 不能作为任意原始标记直接拼接。

当前账号微信绑定、解绑和项目访问申请属于敏感自助操作，必须同时按受信客户端 IP 和
规范化账号限流；所有兼容入口共享同一业务额度，解绑密码校验不得在限流之前执行。
