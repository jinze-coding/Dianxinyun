Web 的管理能力通常多于小程序，页面不要求逐控件相同，但项目、状态、数量和业务记录必须来自同一后端数据。小程序“我的”是账号、区域授权和退出入口，不对应 Web 一级业务菜单。

小程序五个正式一级页面统一使用浅蓝灰工作台主题和共享字体层级。质量模块已取消独立靛蓝辅助色，与资料、巡检、待办和我的共用页面背景、模块层、主操作、底部导航和动效规则；绿、橙、红仅用于正常、预警、逾期等业务状态。历史 `pages/design-preview/index` 仍保留多辅助色设计稿，仅作隔离预览，不代表正式产品主题。

资料管理只保留“资料目录 / 归档状态”两个组织维度：目录是项目内自定义一级目录，归档状态只表达使用中或已归档。历史 `category` 字段不再由正式界面展示、筛选或编辑；Web 与小程序继续共享 `folder_id`、`status` 和同一资料数据，不建立移动端专用资料表。

正式开发服务强制小程序 H5 和微信监听使用 `VITE_USE_MOCK=false`；`restart` 会清理本仓库遗留的微信编译监听，`open-miniprogram` 每次清理开发者工具编译缓存。显式 mock 模式会在施工区域头部显示“演示数据”，该模式下上传只存在于前端内存，不能用于跨端联调验收。

正式产品仍未恢复：项目概况、人员、安全总览、安全复核、现场抽查、安全整改、复查及其旧前端路由；旧版综合待办由当前统一待办替代，不再恢复旧路由。Web 当前按“场内管理 / 资料管理 / 巡检管理 / 质量管理”顺序保留四个顶部业务入口，并按权限显示“系统管理”。项目、账号及授权作为平台基础配置保留。旧巡检复核与安全整改表、Service 和部分未注册小程序源码仅作历史兼容，不是当前正式业务入口。

Web 端界面主题已固定为白色舒适密度，不再提供主题切换、主题面板或信息密度切换。

## 登录认证模块

业务作用：

- 用户输入用户名密码登录。
- 后端生成 JWT。
- 前端保存 token 和用户信息到 localStorage。
- axios 请求拦截器统一加 `Authorization: Bearer <token>`。

当前状态：

- 已能使用 BCrypt 密码登录并获取 token；历史非 BCrypt 密码和 `password_reset_required=1` 的账号必须由管理员重置后才能登录。
- 登录不再提供或依赖任何默认测试账号。管理员应通过 `ADMIN_RESET_USERNAME`、`ADMIN_RESET_PASSWORD` 显式重置，并在启动成功后移除环境变量。
- JWT 带唯一 `jti` 和 `credentialVersion`；`getCurrentUser` 同时校验签名、凭证版本及 Redis 会话键。同一账号可保留多端独立会话，普通登出只注销当前会话。
- 登录后通过 `/api/v1/auth/user-info` 加载菜单树、平台权限码、项目角色/权限及微信绑定状态。
