## 系统定位

电信云平台项目现场综合管理系统是一个多项目 Web 与微信小程序协同平台，当前正式业务范围为：

- 场内管理：内部人员在 Web 创建单次外访邀请和专属小程序码；访客免登录一次性填报本人、同行人员及一辆车；项目人员按权限查看、纠错、作废和逐人导出。
- 工程资料：一级目录、文件版本、预览下载、归档和回收站；用印申请、用户直指派审批、盖章件回传和按日/周/月导出的用印台账。
- 电箱巡检：电箱台账、每日巡检、按月/按日记录查询、月表和统一二维码；Web 与小程序共用电箱编号、名称、位置及负责电工模糊搜索口径。
- 质量管理：问题发起、整改、复查和操作留痕。
- 系统管理：注册审核、用户、角色权限、菜单功能、用印审批、微信绑定和操作日志。项目与角色只在注册审核或用户管理中分配。

Web 与小程序共用 Spring Boot 后端、MySQL、Redis 和文件存储。前端只负责入口和按钮显隐，后端始终按操作权限码及具体项目范围执行授权。

## 账号、注册与登录

新用户不能直接创建 `sys_user`，必须通过 Web 或小程序写入独立的
`registration_application`。申请状态固定为
`PENDING / APPROVED / REJECTED / CANCELLED`：

```text
提交申请
→ 待审批账号、手机号和微信身份并发占用
→ 平台审核
→ 事务内创建用户、分配项目角色/项目范围
→ 小程序申请按微信身份自动绑定
→ 清除申请表密码摘要
```

Web 申请使用图形验证码，手机号首版由管理员人工核验；申请状态只能使用随机查询令牌查询或取消。密码使用 BCrypt，非 BCrypt 历史凭证禁止登录并标记为待重置。系统不提供默认测试账号。

微信快捷登录遵循同一 AppID 下用户、OpenID、UnionID 有效绑定一对一：

- 小程序未绑定微信时，只能使用账号密码显式绑定已有账号或提交注册申请。
- 手机号相同不能自动绑定。
- 已启用密码登录的用户重新验证密码后可自行解绑；仅微信登录账号由平台管理员处理。
- Web 扫码登录使用 2 分钟 Redis challenge，小程序必须确认；浏览器使用私有校验密钥和一次性交换码换取普通 JWT。
- Web 与小程序的正常登录、扫码登录确认及已有会话恢复统一进入本人个人待办。小程序首次密码设置和明确的业务扫码续跳仍优先执行，避免中断正在处理的安全业务链路。

正式环境必须配置真实 AppID、AppSecret、合法 HTTPS 域名并关闭 mock。微信 mock 仅允许显式 `dev/local/test` Profile。

## 生产部署边界

生产配置必须由部署平台注入，完整占位模板见 `backend/.env.example`，该文件不会被
Spring Boot 自动加载。无开发 Profile 或启用 `prod/production` 时，后端启动门禁要求：

- 独立、非 `root` 的 MySQL 账号和非空密码；
- `DB_URL` 启用 TLS，且不能使用 `allowPublicKeyRetrieval=true`；
- Redis 使用非空密码；
- JWT 和正式微信配置满足各自生产门禁；
- 独立且至少 32 字节的 `VISITOR_DATA_ENCRYPTION_KEY`，不得与 JWT 等其他密钥共用；
- 独立且至少 32 字节的 `SEAL_SCENE_ENCRYPTION_KEY`，用于加密用印二维码原始 scene，不得与
  `VISITOR_DATA_ENCRYPTION_KEY`、JWT 或其他业务密钥共用；
- Knife4j、Swagger UI 和 OpenAPI JSON 全部关闭。

生产环境误开接口文档或使用不安全的数据库/Redis 配置会在监听端口前失败。关闭文档时，
后端路径级过滤会使 `/doc.html`、`/webjars/**`、`/swagger-ui/**` 和
`/v3/api-docs/**` 返回 `404`。本地 `scripts/dev-services.sh` 显式启用
`local` Profile 和文档，只用于开发联调。

## 权限模型

权限结果由四部分共同决定：

```text
平台角色
+ 当前项目的项目角色
+ 角色菜单
+ 操作权限码
+ ACTIVE 项目成员范围
```

`GET /api/v1/auth/user-info` 返回菜单树、平台权限码和各项目上下文。平台级系统管理接口只认可平台角色权限；项目角色的权限只在对应有效项目内生效。平台管理员可管理完整系统目录，并可在用户管理页查看、分配用户的项目与项目角色；项目管理员只能管理已授权项目的成员、项目角色和项目访问申请。

菜单和操作权限是两个独立条件：菜单决定入口是否可见，操作权限决定页面内动作，后端接口仍作最终校验。详细规则见 `docs/权限规则.md`。

## 数据与迁移

已有数据库只能按 `docs/数据库结构.md` 执行增量迁移。`backend/src/main/resources/sql/init.sql`
已改为直接中止的兼容入口；全新空库只能使用带空库检查和精确确认的
`scripts/init-empty-database.sh`。

统一注册/RBAC 使用：

```text
backend/src/main/resources/sql/migrations/20260728_unified_registration_rbac_wechat_login.sql
```

该迁移新增 6 张表，并通过 `sys_data_migration` 记录一次性权限种子。重复执行只补结构和缺失字典，不应恢复管理员已经停用的菜单或撤销的角色关联。正式本地 `dianxinyun` 在应用前必须备份；当前验证使用隔离数据库副本。

场内管理追加迁移 `20260807_site_access_visitor_invitation.sql`，新增邀请、逐人实名和加密审计 3 张表，并加入 `SITE_ACCESS / WEB_SITE_ACCESS / SITE_VISITOR` 目录。当前长期本地库未执行该脚本时保持 47 表，应用后为 50 表；不得以构建通过代替数据库迁移和真实扫码验收。

## 本地开发

优先使用：

```bash
./scripts/dev-services.sh start
```

脚本显式启用 `local` Profile 和微信 mock，并继续使用真实后端数据。手动启动、管理员密码恢复和正式微信配置见 `backend/README.md`。

## 验收边界

每次认证/RBAC 变更至少验证：

- BCrypt 正误、停用/待重置账号和全会话失效。
- Web/小程序注册、审批事务、取消、重复与并发占用。
- 微信唯一绑定、显式绑定、解绑、小程序快捷登录。
- Web 扫码确认、取消、过期、跨浏览器、重复消费和账号停用。
- 菜单可见性、操作权限、A/B 项目隔离和受保护接口 HTTP `403`。
- 外访邀请有效/过期/已提交/已作废状态、并发只提交一次、敏感字段密文、逐人 Excel 和真实微信扫码闭环。
- Web 构建，小程序类型检查、H5 与微信构建。
- 正式 AppID/AppSecret、HTTPS 域名和微信真机最终验收。
