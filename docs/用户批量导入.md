# 系统用户批量导入与首次登录绑定微信

更新日期：2026-09-15。本功能交付到原本地开发系统；正式部署、真实名单导入和微信发布另行安排。未经用户明确要求，不提交或推送 Git。

## 管理员与用户流程

平台管理员进入「系统管理 → 用户管理 → 批量导入」，按以下顺序操作：

1. 下载当前系统生成的 Excel 模板，在「用户名单」填写姓名、手机号、所属项目和项目角色。
2. 上传名单校验，核对新增人数、跳过人数以及逐行项目、角色、结果和原因。可只看错误行。
3. 全部错误修正后重新上传；没有错误且有新增账号时，填写「本批统一临时密码」和「确认临时密码」，再点击「确认导入」。后台准备账号，窗口可关闭，稍后从「导入记录」查看进度。
4. 成功后 24 小时内下载账号发放表，将每个人的凭据分别发给本人。不要将整份发放表发给普通用户。
5. 用户使用手机号和临时密码登录 Web 或小程序，先设置个人密码，再进入个人待办。
6. 微信绑定由用户在小程序「我的」中自行完成，沿用登录身份和新的微信登录 code；不能根据手机号自动认领微信。

每批 `.xlsx` 最多 5MiB、500 人、5000 行。模板包含「用户名单 / 项目参考 / 角色参考 / 填写说明」四张表，手机号列采用文本格式；后台兼容 Excel 数值型的 11 位手机号。项目选项为 `项目名称 [P:稳定ID]`，角色选项为 `角色名称 [R:稳定ID]`，通过稳定 ID 匹配，重名不串项目。不要移除选项中的标识。

同一手机号多行合并成一个账号，姓名必须一致；多个项目、同项目多个角色及重复授权行均可处理。角色必须是启用的 PROJECT 角色，允许管理员明确分配项目经理，禁止 PLATFORM 角色。项目必须存在、未删除且不是 stopped 状态。

已有账号优先跳过，不修改姓名、密码、授权、成员状态或微信绑定；停用及仍占位的历史账号也不能通过导入恢复。待审核注册申请占用相同手机号或登录名时，整批校验不通过，由管理员先处理原申请。自主注册审核继续保留，导入属于平台管理员直接批准建号的独立入口，不创建或自动审批注册申请。

## 确认、事务与中断恢复

预览状态为 `PREVIEW` 或 `INVALID`，逐行返回 `NEW / DUPLICATE / SKIPPED / ERROR`；错误人员的其他行也标记需要一起修正。预览有效期 24 小时，原始 Excel 只用于当次解析，不保存为业务附件；数据库保留人员和授权快照、逐行结果及审计。

确认要求原导入管理员、合法幂等键、管理员设置的临时密码、无错误且有新增账号；每管理员最多两个排队或执行中的任务。同一批次、同一请求键及相同密码重试只返回原任务，其他请求键或不同密码返回 HTTP 409；不覆盖已经确认的密码。旧版已完成且无密码摘要的历史批次仍按原请求键返回结果。确认前重新检查新账号占用、待审核申请、项目和角色，变化时要求重新校验。

任务状态为 `QUEUED → PROCESSING → SUCCEEDED`，失败为 `FAILED`，业务状态冲突为 `CONFLICT`。单独后台线程每 3 秒领取任务，使用 2 分钟数据库租约和逐人心跳；中断后重新领取过期租约，解密恢复管理员已设置的密码，并重新计算尚未发布账号的独立 BCrypt 摘要。BCrypt 计算在账号事务之外进行，进度表示已准备人数；全部准备完成后再次检查管理员、项目、角色及手机号占用。

最终账号、项目成员、项目角色、明细结果、加密发放凭据和成功审计在一个事务提交；任一步失败整批回滚，已跳过账号始终不改。导入、注册提交和注册批准共用受保护平台管理员角色行的建号互斥锁，防止并发占用检查穿透。确认/执行也锁定所选项目、角色，授权对象失效不能继续发布。

## 临时密码及首次改密

- 管理员在名单校验通过后填写本批统一临时密码并再次确认，所有新增账号共用。密码为 8–72 位、同时包含字母和数字；UTF-8 不超过 BCrypt 的 72 字节上限。每个账号独立加盐计算 BCrypt，工作因子仍为 12。临时密码从建号时起 30 天有效，已有/跳过账号不变。
- 排队时使用独立导入密钥 AES-GCM 保存批次密码，认证上下文绑定批次 ID、管理员 ID 与请求键。执行和租约恢复使用同一密码，任务成功/失败后显式清除批次密文；定时任务补清终态残留，执行中不清理。仅保留用于重复确认的 BCrypt 摘要，批次 JSON/日志不包含密码、密文或摘要。旧版未执行任务缺少密码时返回冲突，需重新校验并设置，不随机回退。
- `sys_user` 只保存 BCrypt 摘要；新增 `must_change_password` 和 `temporary_password_expires_at`，存量账号默认 0/NULL。不得复用会直接禁止密码登录的 `password_reset_required`。
- 账号发放凭据单独 AES-GCM 加密，只在 24 小时下载窗口内可取，绑定明细 ID、用户 ID、凭证版本及设置管理员。下载每次核验原管理员资格、账号启用/未删除、仍须首次改密、凭证版本、两种有效期。
- 批次发放表只允许原导入管理员下载。已改密、失效或已由其他管理员重新设置的行不再返回；全部无可下载凭据时返回 HTTP 410。下载返回 `no-store / no-cache / nosniff`，密码不会返回普通用户或批次 JSON。
- 未完成改密的导入账号在用户管理显示「临时密码」。平台管理员填写与原临时密码不同的新密码并确认后重新设置，原密码和全部会话立即失效，新密码重新计时 30 天；新发放表只允许本次设置管理员在 24 小时内下载。下载失败可以再取当前发放表，无需再次生成。
- 已完成首次改密的账号使用原密码重置入口，不能重新设置临时密码；停用账号不能生成或下载凭据。
- 每分钟清理过期、已改密、已删除或凭证版本变化的加密发放凭据；下载在到期瞬间即拒绝。首次改密和删除用户在对应事务内清除发放密文。导入记录及历史审计保留。

导入账号密码登录成功后只获得受限会话，`/auth/user-info` 返回必要本人信息、`initialPasswordSetupRequired=true`、`initialPasswordSetupReason=ADMIN_IMPORT` 和临时密码到期时间，不返回项目、菜单或业务权限。其他私有业务接口及微信绑定拒绝访问。原微信快捷注册仍返回 `WECHAT_QUICK` 并沿用已有设密方式。

首次改密复用 `/auth/initial-password`，新密码按现有 8–72 位且字母数字组合规则校验，不能与临时密码相同。服务端校验会话和凭证版本后锁定用户，再检查状态、首次改密标记和临时密码期限；完成时清除标记、期限和发放凭据，注销旧会话并签发新会话。并发改密只有一次成功。IP 与账号分别限流，账号限流主体复用不可逆摘要。

Web 在加载业务项目和通知前读取首次改密状态，只显示独立设密页和退出；页面提示后续在小程序绑定微信。小程序复用原首次设密页，私有页面守卫和后台项目/待办轮询同步拦截，成功后提示「我的」绑定入口并按原导航进入个人待办；显式业务扫码续跳继续优先。失败保留输入，成功清除输入并替换会话。

## 接口

以下管理员接口均以 `/api/v1/system` 为前缀，必须为启用的 PLATFORM_ADMIN；普通项目角色不能借系统权限码访问。

| 方法与路径 | 参数与结果 |
| --- | --- |
| `GET /user-imports/template` | 下载当前有效项目/角色模板 |
| `POST /user-imports/preview` | multipart `file`；返回批次、人数和逐行结果 |
| `POST /user-imports/{id}/confirm` | JSON `requestKey`（16–80 位字母数字、下划线或短横线）及必填 `temporaryPassword`；返回原或新排队任务 |
| `GET /user-imports` | `pageNo/pageSize`，默认 1/20，每页最多 50 |
| `GET /user-imports/{id}` | `includeRows` 默认 true，轮询可传 false 只取进度 |
| `GET /user-imports/{id}/credentials` | 原导入管理员下载当前仍有效的发放行 |
| `POST /users/{id}/temporary-password` | JSON 必填 `temporaryPassword`；为未激活导入账号重新设置临时密码，不在 JSON 返回密码 |
| `GET /users/{id}/temporary-password` | 本次设置管理员下载单人发放表 |

账号状态仍由 `/auth/user-info` 提供；`POST /auth/initial-password` 接收 `newPassword` 并返回新登录会话。验证错误 HTTP 400，旧/失效会话 401，无权或临时密码过期 403，状态/幂等冲突 409，发放表无有效行 410，独立加密配置缺失 503。Web 保留服务端错误消息和当前预览，重新上传才能替换名单。
