# 小程序与 PC 管理后台交互测试计划

更新时间：2026-07-30。

本文用于验证“PC 作为管理后台、小程序作为现场端”的现行极简电箱巡检闭环。测试重点是
PC 管理数据能同步到小程序，小程序日检能回流到 PC，巡检记录、照片、日/月汇总和公开
扫码等状态在两端一致。新巡检提交后直接完成；复核、现场抽查和电箱整改 Controller
已退出，仅保留历史数据兼容，不作为可执行正向流程。

> 现行口径（2026-07-28）：本计划新增统一注册、微信绑定、小程序微信快捷登录、Web 微信扫码登录和通用 RBAC 验收。下文 TC-01～TC-12 保留为既有电箱巡检业务回归用例；其中与当前产品流程不一致的历史描述，不替代当前代码、增量迁移和本节新增用例。

## 一、测试范围

本轮覆盖：

- 登录、项目权限和项目隔离。
- PC 电箱台账、二维码、公开访问管理与小程序同步。
- 小程序扫码日检和照片回流到 PC。
- PC 与小程序两端巡检记录、日/月汇总和公开访问状态一致性。
- 历史复核/整改状态只读兼容，以及已退出接口不会被新客户端重新调用。
- 外部公开只读码免登录访问和脱敏展示。
- 关键异常场景：无权限、停用/拆除、旧二维码、文件上传失败、token 失效。

本轮不覆盖：

- PC 发起扫码日检。
- 新增安全复核、现场安全抽查或电箱整改流程；这些属于历史方案，不再执行。
- 视频流、摄像头、人员安全教育等非电箱检查业务。
- 性能压测和大批量导入稳定性测试。

## 二、测试准备

### 2.1 环境

| 端 | 要求 |
| --- | --- |
| 后端 | `http://localhost:8080`，连接同一个 `dianxinyun` 开发库 |
| PC 前端 | `http://localhost:3002`，接口通过 `/api` 代理到后端 |
| 小程序 H5 | `wechat-miniprogram/site-platform-miniprogram` 执行 `npm run dev:h5` |
| 微信小程序 | 执行 `npm run dev:mp-weixin:real` 后，用微信开发者工具打开 `dist/dev/mp-weixin`；`.env.mp-real` 必须配置绝对 API 地址 |
| 小程序数据模式 | `VITE_USE_MOCK=false`，不得使用 mock 数据验收真实联动 |

### 2.2 账号和权限

至少准备 4 类账号：

| 账号类型 | 验收用途 |
| --- | --- |
| 平台管理员 | PC 项目、电箱、权限、台账和汇总全量管理 |
| 项目管理员 | 授权项目内台账、二维码、公开访问和汇总管理 |
| 负责电工 / 巡检员 | 小程序扫码日检 |
| 无项目权限普通用户 | 验证项目隔离和无权限拦截 |

### 2.3 基础数据

准备 1 个测试项目和至少 3 个电箱：

| 电箱 | 初始状态 | 测试用途 |
| --- | --- | --- |
| A | 启用 | 正常日检、汇总、公开扫码 |
| B | 启用后停用 | 停用后不可日检/抽查 |
| C | 有未闭环整改或可拆除 | 拆除限制、拆除后禁扫、公开访问关闭 |

测试前确认：

- 文件上传和下载接口可用。
- PC 可生成内部巡检码和公开只读码。
- 小程序扫码、手输编码或模拟扫码能解析同一后端数据。
- PC 和小程序连接同一个后端和数据库。

## 三、核心交互用例

### TC-01 登录与项目权限

| 项 | 内容 |
| --- | --- |
| 优先级 | 阻断 |
| 前置条件 | PC 已配置项目用户授权和电箱巡检权限模板 |
| 操作步骤 | 1. 分别用平台管理员、安全员、电工、无权限用户登录小程序。2. 查看项目列表和项目工作台。3. 在 PC 修改某用户项目授权后，小程序重新登录或刷新。 |
| 预期结果 | 小程序只展示当前用户有权限的项目；无权限用户不能进入项目工作台、电箱详情、日检或汇总；PC 授权变更后小程序权限同步正确。 |

### TC-02 PC 电箱台账同步到小程序

| 项 | 内容 |
| --- | --- |
| 优先级 | 阻断 |
| 前置条件 | 管理账号已进入 PC 电箱巡检模块 |
| 操作步骤 | 1. PC 新增电箱，填写编号、名称、位置、负责电工、安全负责人。2. 小程序进入项目工作台和电箱台账。3. PC 编辑位置、负责人和状态。4. 小程序刷新列表和详情。 |
| 预期结果 | 小程序能看到 PC 新增电箱；编号、名称、位置、负责人、状态和二维码绑定状态一致；PC 修改后小程序刷新同步。 |

### TC-03 电箱停用和拆除联动

| 项 | 内容 |
| --- | --- |
| 优先级 | 高 |
| 前置条件 | 存在启用电箱 B 和待拆除电箱 C |
| 操作步骤 | 1. PC 停用电箱 B。2. 小程序扫码或打开 B 详情并尝试日检。3. PC 尝试拆除存在历史未闭环整改的 C。4. 闭环历史整改后再次拆除 C。5. 小程序扫码或打开 C。 |
| 预期结果 | 停用电箱可查看历史但不可日检；存在历史未闭环整改时拆除被阻止；拆除后小程序展示拆除/不可用状态，内部码和公开访问不可继续使用。 |

### TC-04 二维码管理和扫码解析

| 项 | 内容 |
| --- | --- |
| 优先级 | 阻断 |
| 前置条件 | PC 已生成内部巡检码和公开只读码 |
| 操作步骤 | 1. 小程序扫描或输入内部巡检码。2. 小程序扫描公开只读码。3. PC 换绑内部二维码。4. 小程序扫描旧码和新码。5. PC 关闭公开访问后再次打开公开页。 |
| 预期结果 | 内部码进入电箱业务动作面板；公开码进入免登录只读汇总页；旧码换绑后失效，新码可识别；关闭公开访问后公开页不可继续查看。 |

### TC-05 小程序日检和照片回流到 PC 巡检记录

| 项 | 内容 |
| --- | --- |
| 优先级 | 阻断 |
| 前置条件 | 电工账号有项目权限，电箱 A 启用 |
| 操作步骤 | 1. 电工小程序扫码进入日检表。2. 先选择外观照片，再从相机/相册返回并选择内部照片。3. 填写六项检查项并完成巡检。4. PC 打开巡检记录详情并依次放大两类照片。5. 再分别验证无照片、仅外观、仅内部和上传失败重试。 |
| 预期结果 | 相机/相册/预览或切到后台返回后，两类照片、备注和检查项草稿均不丢失；记录直接为已完成；PC 与小程序显示相同照片和检查结果；未选择照片可正常提交，已选择照片上传失败时不创建记录并保留草稿；同一电箱同一天重复提交限制生效。 |

### TC-06 历史安全复核兼容（当前流程不新增）

| 项 | 内容 |
| --- | --- |
| 优先级 | 阻断 |
| 前置条件 | 数据库中存在历史复核状态记录 |
| 操作步骤 | 1. PC 与小程序分别查看历史记录。2. 查询相同项目、电箱和月份。 |
| 预期结果 | 历史状态对外按当前“已完成”口径兼容显示；新巡检不出现复核、退回或整改入口，也不生成相关待办。 |

### TC-07 已退出复核接口不会被新客户端调用

| 项 | 内容 |
| --- | --- |
| 优先级 | 阻断 |
| 前置条件 | 新客户端连接当前后端 |
| 操作步骤 | 1. 检查 Web 与小程序导航、待办和记录详情。2. 直接请求历史 `/review`、`/assign-reviewer`、`/review-logs` 路径。 |
| 预期结果 | 新客户端不展示复核、退回、转整改入口，也不生成复核待办；未登录请求先返回 `401`，具备有效登录与巡检管理权限后，历史 Controller 路径返回 `404`，不能恢复旧流程。 |

### TC-08 已退出安全抽查不会被扫码结果恢复

| 项 | 内容 |
| --- | --- |
| 优先级 | 阻断 |
| 前置条件 | 巡检员和只读领导分别扫描电箱 A |
| 操作步骤 | 1. 巡检员扫码。2. 只读领导扫码。3. 检查动作面板和网络请求。 |
| 预期结果 | 巡检员只获得今日巡检/本箱记录，领导只查看记录；不出现安全抽查入口，也不调用历史抽查接口。 |

### TC-09 已退出电箱整改接口不可调用

| 项 | 内容 |
| --- | --- |
| 优先级 | 阻断 |
| 前置条件 | 数据库可包含历史整改记录 |
| 操作步骤 | 1. 检查 PC 和小程序是否存在电箱整改管理入口。2. 直接请求历史整改提交、改派、提醒、关闭、退回和复查路径。 |
| 预期结果 | 历史整改只影响拆除约束和只读兼容，不进入新待办；未登录请求先返回 `401`，具备有效登录与巡检管理权限后，已退出 Controller 路径返回 `404`。质量模块整改继续按独立质量接口验收。 |

### TC-10 新巡检直接完成且不生成历史流程数据

| 项 | 内容 |
| --- | --- |
| 优先级 | 阻断 |
| 前置条件 | 电箱 A 当日尚未巡检 |
| 操作步骤 | 1. 小程序完成一条正常日检。2. PC 与小程序刷新记录和待办。3. 核对数据库/接口返回状态。 |
| 预期结果 | 记录直接为 `COMPLETED`；不生成复核日志、复核待办或新的电箱整改任务；两端按“已完成”显示。 |

### TC-11 电箱搜索、日/月汇总和导出一致性

| 项 | 内容 |
| --- | --- |
| 优先级 | 高 |
| 前置条件 | 同一项目有多个不同编号、名称、位置和负责电工的电箱，并在不同日期产生正常及异常巡检记录 |
| 操作步骤 | 1. Web 与小程序分别按编号、名称、位置、负责电工搜索电箱。2. 分别选择“全部电箱”和一个具体电箱。3. 在两端切换月度和按日模式，选择相同日期。4. 组合正常/异常筛选并核对记录。5. 月度模式导出检查记录，按日模式检查导出入口。 |
| 预期结果 | 两端搜索结果只包含当前项目有权电箱；扫码进入本箱记录时不能切换到其他电箱；相同项目、电箱、日期条件下记录和应检/已检/未检/异常统计一致；按日模式不提供月表导出，月度 Excel 数量和原有口径不变。 |

### TC-12 外部公开扫码只读汇总

| 项 | 内容 |
| --- | --- |
| 优先级 | 高 |
| 前置条件 | 电箱 A 已启用公开访问 |
| 操作步骤 | 1. 未登录状态打开公开只读码页面。2. 检查页面字段。3. PC 关闭公开访问后刷新公开页。4. 拆除电箱后再次访问公开页。 |
| 预期结果 | 公开页免登录可访问；只展示脱敏汇总，不展示检查人姓名、账号、手机号、照片 ID、检查项明细、备注、复核意见；关闭公开访问或拆除后不可继续展示。 |

## 四、异常与边界用例

| 编号 | 场景 | 预期结果 | 优先级 |
| --- | --- | --- | --- |
| E-01 | 小程序 token 过期或后端返回 401 | 清理本地登录态并提示重新登录 | 高 |
| E-02 | 照片上传失败后提交日检 | 阻止提交并提示上传失败，保留草稿且不创建记录 | 阻断 |
| E-03 | 调用已退出复核、抽查或电箱整改接口 | 未登录返回 `401`；有效授权上下文返回 `404`；均不写历史流程数据 | 高 |
| E-04 | 无巡检提交权限用户直接调用日检接口 | 后端返回 `403`，前端提示无权限 | 高 |
| E-05 | 扫描停用、拆除、换绑旧码 | 不允许发起日检，提示二维码不可用 | 高 |
| E-06 | 未授权项目访问电箱、检查或汇总接口 | 后端拒绝，前端显示无权限或空态 | 阻断 |
| E-07 | 公开码访问已关闭公开访问的电箱 | 公开页显示不可访问，不泄露历史数据 | 高 |
| E-08 | 重复提交同一电箱同一天有效日检 | 前端拦截且后端拒绝重复记录 | 高 |

## 六、通过标准

- PC 创建、编辑、停用、拆除、换绑、公开访问等管理动作，小程序刷新后全部一致。
- 小程序日检完成后，PC 管理后台能刷新看到相同记录、照片和汇总。
- 新巡检不出现复核、抽查或电箱整改流程；历史数据只读兼容，已退出接口保持不可调用。
- 汇总统计、公开只读页在 PC 和小程序两端状态一致。
- 权限、项目隔离、二维码失效、公开脱敏、照片上传等关键边界无绕过。
- 阻断和高优先级缺陷必须修复并回归通过；中低优先级缺陷需记录责任和后续处理结论。

## 七、建议执行顺序

1. 先执行 TC-01 到 TC-04，确认权限、台账和二维码基础链路。
2. 再执行 TC-05 到 TC-10，跑通日检并验证历史复核、抽查和电箱整改不会被恢复。
3. 最后执行 TC-11、TC-12 和异常边界用例。
4. 每修复一个阻断或高优先级问题，至少回归对应主链路和关联汇总统计。

## 八、2026-07-28 统一身份与权限增量验收

### 8.1 增量测试准备

- Web、小程序和后端连接同一套测试数据库及 Redis；只执行可重复检查的增量迁移，不执行 `init.sql`。
- 准备平台管理员、注册审核员、项目管理员、两个不同项目的普通成员、已停用用户及仅微信登录用户。
- 准备同一 AppID 下的已绑定微信、未绑定微信，并确认 OpenID、UnionID、用户三类唯一约束已生效。
- Web 和小程序真实联调均设置 `mock=false`；最终微信验收必须使用正式 AppID、AppSecret、合法 HTTPS 域名和真机。
- Web 扫码登录 challenge 有效期为 2 分钟；测试时保留浏览器 A、浏览器 B、同一微信真机及可观察 Redis 状态的环境。
- 执行撤权场景前，记录用户当前菜单、权限码、项目角色、JWT 和首个有权页面。

### 8.2 统一注册与微信登录用例

| 编号 | 场景与步骤 | 预期结果 | 优先级 |
| --- | --- | --- | --- |
| ID-01 | 分别从 Web、小程序提交新账号注册申请，填写账号、密码、姓名、手机号、说明和期望项目 | 提交时不创建 `sys_user`；申请为 `PENDING`；返回一次性状态查询令牌；Web 手机号标记人工核验 | 阻断 |
| ID-02 | 使用同一账号名或手机号并发提交两次，再用手机号直接猜测查询申请 | 仅一条申请占用成功；另一请求得到统一错误；状态只能用查询令牌获取，不能通过手机号枚举 | 阻断 |
| ID-03 | 注册审核员批准申请并分配项目角色和项目范围 | 审批事务内创建用户、项目角色、项目范围和可选微信绑定；申请密码摘要被清除；任一步失败全部回滚；不得通过注册审核授予平台全局身份 | 阻断 |
| ID-04 | 驳回申请后重新使用相同账号和手机号申请 | 原申请变为 `REJECTED` 且密码摘要清除；账号占用释放；新申请可正常提交 | 高 |
| ID-05 | 小程序用未绑定微信快捷登录，再选择“绑定已有账号”，输入错误及正确账号密码 | 错误密码不得绑定；正确密码与新的 `uni.login` code 校验后建立唯一绑定并登录；不得因手机号相同自动绑定 | 阻断 |
| ID-06 | 从电箱公开页进入内部权限申请，绑定已有账号后继续 | 绑定成功后显式创建或返回已有 `PROJECT_ACCESS` 申请；有权限时回到对应电箱业务页，无权限时展示申请状态 | 阻断 |
| ID-07 | 小程序注册申请携带微信身份，管理员批准后再次微信快捷登录 | 审批通过后自动绑定当前微信；快捷登录加载 `/auth/user-info`、菜单、权限和项目范围，并进入第一个有权页面 | 阻断 |
| ID-08 | 已绑定用户在小程序执行自助解绑；分别测试密码错误、密码登录被禁用和正确密码 | 只有已启用密码登录且重新验证成功时可自助解绑；仅微信登录账号提示由平台管理员处理；解绑后全部会话失效 | 阻断 |
| ID-09 | 使用非 BCrypt 历史密码、停用账号、待审批账号和错误密码登录 | 均不得登录；历史密码账号提示重置；错误信息统一且不泄露账号是否存在；限流达到阈值后拒绝继续尝试 | 阻断 |

### 8.3 Web 微信扫码登录状态机

| 编号 | 操作 | 预期状态及约束 |
| --- | --- | --- |
| QR-01 | 浏览器 A 创建二维码，小程序扫描但不确认 | `WAITING → SCANNED`；二维码仅包含随机 challenge ID，不包含 JWT 或浏览器校验密钥 |
| QR-02 | 用户点击确认，浏览器 A 轮询并兑换 | `SCANNED → CONFIRMED → CONSUMED`；浏览器只取得一次性交换码并兑换普通 JWT，随后加载用户信息和首个有权页面 |
| QR-03 | 用户点击取消 | 状态变为 `CANCELLED`；浏览器停止轮询并允许重新生成二维码，不能兑换登录凭证 |
| QR-04 | 超过 2 分钟后扫描、确认或消费 | 状态为 `EXPIRED`；所有后续确认和兑换均失败 |
| QR-05 | 对已确认二维码重复确认或重复兑换 | 首次消费后保持 `CONSUMED`；后续请求失败，不产生第二个有效登录会话 |
| QR-06 | 浏览器 B 使用截图中的 challenge 或交换码兑换 | 因缺少浏览器 A 的校验密钥而失败，不得跨浏览器登录 |
| QR-07 | 同一浏览器并行创建两个二维码并分别确认 | 两个 challenge 独立；确认其中一个不改变另一个状态，也不得串用交换码 |
| QR-08 | 扫码期间停用账号、解绑微信、撤销关键权限或发生网络中断 | 确认/兑换时重新校验账号和绑定状态；失效账号不得登录；网络恢复后不得重复消费已消费凭证 |

### 8.4 RBAC、项目隔离与撤权回落

| 编号 | 场景与步骤 | 预期结果 | 优先级 |
| --- | --- | --- | --- |
| RBAC-01 | 给角色分配资料菜单但不分配上传/管理权限，再分别访问列表、上传页、目录和回收站 | 菜单可见；查看接口按 `document.view` 校验；上传、目录和回收站按钮隐藏，直接访问或调用接口返回 403 | 阻断 |
| RBAC-02 | 同一用户在项目 A 有管理权限、项目 B 只有查看权限，分别切换项目执行资料、巡检和质量写操作 | 权限只按当前 `projectId` 聚合；项目 A 可操作，项目 B 对写按钮隐藏且后端返回 403；不得借用项目 A 权限 | 阻断 |
| RBAC-03 | 项目管理员进入系统管理 | 只看到当前授权项目的成员、项目角色和项目访问申请；可调整现有成员；不能新增全量账号、审批新账号或授予平台权限 | 阻断 |

| RBAC-05 | 管理员删除角色菜单、撤销操作权限、暂停项目成员或停用用户 | 关键权限变更后该用户全部会话失效；重新登录后菜单和按钮立即更新，不保留旧缓存权限 | 阻断 |
| RBAC-06 | 用户停留在刚被撤权的 Web/小程序页面后刷新或继续操作 | 当前页面不再有权时自动回落到第一个有权页面；若无业务菜单则进入“我的”或登录页；原页面接口返回 403 | 高 |
| RBAC-07 | 停用某菜单后使用拥有该菜单的非管理员角色重新登录 | 停用菜单不进入 `/auth/user-info` 菜单树；Web、小程序均不展示入口；平台管理员按设计保留管理能力 | 高 |

### 8.5 视觉与正式微信验收

- Web 分别在 1280、1440、1920 像素宽度检查登录页、顶栏和系统管理七个栏目；不得出现横向遮挡、时间错位、按钮重叠或表格操作区不可达。
- 顶栏保留日期时间，固定白色舒适密度；不得再出现主题按钮、主题弹层或密度设置；有权限用户在原位置看到“系统管理”，普通用户不可见。
- 小程序检查注册、申请状态、微信绑定、Web 登录确认、自定义底部导航和撤权回落页面；不得通过路径直接进入无权页面。
- 分别在 iOS、Android 真机从资料、巡检、质量首页打开施工区域弹层；弹层显示期间自定义底部导航必须完全隐藏，当前及其他项目均可点击或滚动到达，关闭动画结束后底部导航恢复。开发者工具表现不能替代此项真机结果。
- 微信开发者工具 mock、`touristappid` 或本地 H5 只能作为开发回归，不能作为上线通过证据。
- 最终必须在真机、正式 AppID/AppSecret、`mock=false`、合法 HTTPS request/upload/download 域名下完成：微信快捷登录、首次绑定、注册后自动绑定、Web 扫码确认/取消/过期、解绑及再次登录。
- 上线门槛：新增阻断用例全部通过，原有 31 项测试保持通过；保留测试账号类型、项目范围、截图、接口响应和后端日志证据，但不得在文档中记录真实 OpenID、UnionID、密码或完整手机号。
