## 一、测试范围

本轮覆盖：

- 登录、项目权限和项目隔离。
- PC 电箱台账、二维码、公开访问管理与小程序同步。
- 小程序扫码日检和照片回流到 PC。
- PC 与小程序两端巡检记录、日/月汇总和公开访问状态一致性。
- 异常巡检整改任务的指派、提交、复查、退回、改派和待办联动。
- 历史逐条复核状态只读兼容，以及已退出接口不会被新客户端重新调用。
- 统一场景码的外部公开分支免登录访问和脱敏展示。
- 关键异常场景：无权限、停用/拆除、旧二维码、文件上传失败、token 失效。

本轮不覆盖：

- PC 发起扫码日检。
- 历史逐条安全复核和现场安全抽查流程；这些属于历史方案，不再执行。
- 视频流、摄像头、人员安全教育等非电箱检查业务。
- 性能压测和大批量导入稳定性测试。

## 二、测试准备

### 2.1 环境

| 端 | 要求 |
| --- | --- |
| 后端 | `http://localhost:8080`，连接同一个 `dianxinyun` 开发库 |
| PC 前端 | `http://localhost:3002`，接口通过 `/api` 代理到后端 |
| 小程序 H5 | `wechat-miniprogram/site-platform-miniprogram` 执行 `npm run dev:h5` |
| 微信小程序 | 执行 `npm run dev:mp-weixin:real` 后，用微信开发者工具打开 `dist/dev/mp-weixin`；`.env.mp-real` 必须配置绝对 API 地址 |
| 小程序数据模式 | `VITE_USE_MOCK=false`，不得使用 mock 数据验收真实联动 |

### 2.2 账号和权限

至少准备 4 类账号：

| 账号类型 | 验收用途 |
| --- | --- |
| 平台管理员 | PC 项目、电箱、权限、台账和汇总全量管理 |
| 项目管理员 | 授权项目内台账、二维码、公开访问和汇总管理 |
| 负责电工 / 巡检员 | 小程序扫码日检 |
| 无项目权限普通用户 | 验证项目隔离和无权限拦截 |

### 2.3 基础数据

准备 1 个测试项目和至少 3 个电箱：

| 电箱 | 初始状态 | 测试用途 |
| --- | --- | --- |
| A | 启用 | 正常日检、汇总、公开扫码 |
| B | 启用后停用 | 停用后不可日检/抽查 |
| C | 有未闭环整改或可拆除 | 拆除限制、拆除后禁扫、公开访问关闭 |

测试前确认：

- 文件上传和下载接口可用。
- PC 可生成每箱唯一的统一场景码，并可单独启停该码的外部公开访问。
- 小程序扫码、手输编码或模拟扫码能解析同一后端数据。
- PC 和小程序连接同一个后端和数据库。

### 2.4 自动化隔离角色闭环

上线前可执行以下命令，验证当前开发库结构和角色配置能完成真实 HTTP 状态流转：

```bash
./scripts/verify-inspection-role-workflow.sh
```

该脚本只允许本机 MySQL，自动创建名称以 `dianxinyun_acceptance_` 开头的唯一临时库，
并使用独立的 18080 后端端口、16380 Redis 端口和临时上传目录。它会在数据库副本中为
平台管理员、电工、安全员设置随机临时密码，依次验证异常巡检、整改照片上传、电工完成、
安全员关闭、跨角色 HTTP 403、重复流转 HTTP 409 和审计日志；退出时删除临时库及临时文件。
脚本不读取、不输出、不保存真实明文密码，也不写入源 `dianxinyun` 库。

若本机端口冲突，可通过 `ACCEPTANCE_API_PORT`、`ACCEPTANCE_REDIS_PORT` 指定空闲端口。
该自动化用于后端认证、权限、文件和状态流转门禁，不能替代微信正式 AppID、真机扫码、
相机/相册授权以及 PC/H5 的人工视觉与交互验收。

## 三、核心交互用例

### TC-01 登录与项目权限

| 项 | 内容 |
| --- | --- |
| 优先级 | 阻断 |
| 前置条件 | PC 已配置项目用户授权和电箱巡检权限模板 |
| 操作步骤 | 1. 分别用平台管理员、安全员、电工、无权限用户登录小程序。2. 查看项目列表和项目工作台。3. 在 PC 修改某用户项目授权后，小程序重新登录或刷新。 |
| 预期结果 | 小程序只展示当前用户有权限的项目；无权限用户不能进入项目工作台、电箱详情、日检或汇总；PC 授权变更后小程序权限同步正确。 |

### TC-02 PC 电箱台账同步到小程序

| 项 | 内容 |
| --- | --- |
| 优先级 | 阻断 |
| 前置条件 | 管理账号已进入 PC 电箱巡检模块 |
| 操作步骤 | 1. PC 新增电箱，填写编号、名称、位置、负责电工、安全负责人。2. 小程序进入项目工作台和电箱台账。3. PC 编辑位置、负责人和状态。4. 小程序刷新列表和详情。 |
| 预期结果 | 小程序能看到 PC 新增电箱；编号、名称、位置、负责人、状态和二维码绑定状态一致；PC 修改后小程序刷新同步。 |

### TC-03 电箱停用和拆除联动

| 项 | 内容 |
| --- | --- |
| 优先级 | 高 |
| 前置条件 | 存在启用电箱 B 和待拆除电箱 C |
| 操作步骤 | 1. PC 停用电箱 B。2. 小程序扫码或打开 B 详情并尝试日检。3. PC 尝试拆除存在历史未闭环整改的 C。4. 闭环历史整改后再次拆除 C。5. 小程序扫码或打开 C。 |
| 预期结果 | 停用电箱可查看历史但不可日检；存在历史未闭环整改时拆除被阻止；拆除后小程序展示拆除/不可用状态，统一场景码不可继续使用且公开访问保持关闭。 |

### TC-04 二维码管理和扫码解析

| 项 | 内容 |
| --- | --- |
| 优先级 | 阻断 |
| 前置条件 | PC 已生成 `B:<publicCode>` 统一场景码并开启公开访问 |
| 操作步骤 | 1. 有巡检权限的登录用户扫描统一码。2. 未登录用户扫描同一统一码。3. PC 轮换统一码。4. 小程序分别扫描旧码和新码。5. PC 关闭公开访问后，以未登录和无项目巡检权限两种身份再次扫码。 |
| 预期结果 | 同一码按身份分流：有权限用户进入电箱业务动作面板，未登录用户进入公开只读月表；轮换后旧码失效、新码可识别；关闭公开访问后，无项目巡检权限的调用在返回电箱元数据前被拒绝。 |

### TC-05 小程序日检和照片回流到 PC 巡检记录

| 项 | 内容 |
| --- | --- |
| 优先级 | 阻断 |
| 前置条件 | 电工账号有项目权限，电箱 A 启用 |
| 操作步骤 | 1. 电工小程序扫码进入日检表。2. 先选择外观照片，再从相机/相册返回并选择内部照片。3. 填写六项检查项并完成巡检。4. PC 打开巡检记录详情并依次放大两类照片。5. 再分别验证无照片、仅外观、仅内部和上传失败重试；用同一登录态直调接口验证服务端缺图校验。 |
| 预期结果 | 相机/相册/预览或切到后台返回后，两类照片、备注和检查项草稿均不丢失；正常记录直接为已完成；PC 与小程序显示相同照片和检查结果；无照片、仅外观或仅内部均被前端阻止且后端返回 HTTP `400`，上传失败时不创建记录并保留草稿；同一电箱同一天重复提交限制生效。 |

### TC-06 历史逐条安全复核兼容（当前流程不新增）

| 项 | 内容 |
| --- | --- |
| 优先级 | 阻断 |
| 前置条件 | 数据库中存在历史复核状态记录 |
| 操作步骤 | 1. PC 与小程序分别查看历史记录。2. 查询相同项目、电箱和月份。 |
| 预期结果 | 历史逐条复核状态可只读兼容；新巡检不出现逐条复核、退回或转整改入口。正常巡检直接完成；异常巡检只进入当前整改闭环并生成对应待办。 |

### TC-07 已退出复核接口不会被新客户端调用

| 项 | 内容 |
| --- | --- |
| 优先级 | 阻断 |
| 前置条件 | 新客户端连接当前后端 |
| 操作步骤 | 1. 检查 Web 与小程序导航、待办和记录详情。2. 直接请求历史 `/review`、`/assign-reviewer`、`/review-logs` 路径。 |
| 预期结果 | 新客户端不展示逐条复核、复核退回或复核转整改入口，也不生成历史复核待办；未登录请求先返回 `401`，具备有效登录与巡检管理权限后，历史 Controller 路径返回 `404`，不能恢复旧流程。当前 `/rectifications` 整改接口不属于此项退出范围。 |

### TC-08 已退出安全抽查不会被扫码结果恢复

| 项 | 内容 |
| --- | --- |
| 优先级 | 阻断 |
| 前置条件 | 巡检员和只读领导分别扫描电箱 A |
| 操作步骤 | 1. 巡检员扫码。2. 只读领导扫码。3. 检查动作面板和网络请求。 |
| 预期结果 | 巡检员只获得今日巡检/本箱记录，领导只查看记录；不出现安全抽查入口，也不调用历史抽查接口。 |

### TC-09 异常巡检整改闭环与记录级权限

| 项 | 内容 |
| --- | --- |
| 优先级 | 阻断 |
| 前置条件 | 异常巡检已指派给当前项目有效电工，项目有具备 `inspection.review` 的安全员 |
| 操作步骤 | 1. 被指派电工提交整改说明和至少一张整改照片。2. 非指派电工直接调用提交接口。3. 安全员复查关闭一条任务，并退回另一条任务。4. 电工再次提交被退回任务。5. 安全员改派负责人或调整期限。6. 核对 PC、小程序、个人待办和操作留痕。 |
| 预期结果 | 只有当前指派且具备 `inspection.rectify` 的电工可在 `PENDING/REJECTED` 提交；说明和照片缺失均返回 HTTP `400`；安全员只在 `COMPLETED` 复查，关闭或退回后状态、待办和日志一致；越权返回 `403`，重复或错误状态流转返回 `409`。质量模块整改继续使用独立质量接口。 |

### TC-10 正常与异常巡检分支

| 项 | 内容 |
| --- | --- |
| 优先级 | 阻断 |

### 8.3 Web 微信扫码登录状态机

| 编号 | 操作 | 预期状态及约束 |
| --- | --- | --- |

| QR-06 | 浏览器 B 使用截图中的 challenge 或交换码兑换 | 因缺少浏览器 A 的校验密钥而失败，不得跨浏览器登录 |
| QR-07 | 同一浏览器并行创建两个二维码并分别确认 | 两个 challenge 独立；确认其中一个不改变另一个状态，也不得串用交换码 |
