# 小程序现场检查与电箱检查规格

更新时间：2026-08-26。

本文档细化小程序现场检查模块的数据、流程、接口和导出规则。当前基础后端接口、数据库表和小程序页面框架已实现，真实微信扫码、真实文件上传和小程序接口联调仍待完善。

> 当前正式口径：正常巡检直接完成；异常巡检聚合生成一条整改任务并指派当前项目电工，电工
> 提交整改后由当前项目安全员复查关闭或退回。巡检人以 `inspection.submit` 定义，电工以
> `ELECTRICIAN + inspection.rectify` 定义，安全员以 `SAFETY_OFFICER + inspection.review`
> 定义。历史“所有巡检都安全复核”和安全抽查入口停用；电工日检的外观照片、内部照片均为
> 必填且每类至少 1 张，备注仍为选填。

## 一、来源表单与流程

用户提供的 Word 表单为历史需求来源：

```text
电箱检查记录表
工程名称：陆家嘴金融城文化分中心装修工程
```

原始表单附带的流程要求如下；其中“所有日检推送逐条复核”和“现场抽查”已被当前极简流程替代，
不得据此恢复旧入口：

1. 电工每日巡检二级电箱，扫描电箱二维码，上传电箱外表照片和内部照片，提交后推送安全员复核。
2. 现场电箱总数和巡检覆盖范围由项目安全员确定。
3. 安全员现场发现不合规电箱时，可扫码上传问题照片，系统派给电工限时 3 天整改。
4. 每个电箱和二维码一一对应，编号明确。
5. 外部检查或公司检查可通过微信扫码查看现场电箱巡检记录汇总表。

原表头字段：

```text
日期 | 内外观 | 漏电保护器 | 熔断 | 保护接零 | 220V插座 | 380V插座 | 检查人 | 备注
```

样张包含 2024.11.1 至 2024.11.30 的每日行。系统中改为“每日扫码填写一条记录，按月份导出 Excel 工作簿”。

## 二、业务模型

当前现场检查模块抽象为：

```text
电箱台账
→ 二维码
→ 检查模板
→ 检查记录
→ 检查项结果
→ 正常直接完成 / 异常聚合整改任务
→ 电工整改
→ 安全员复查关闭或退回
→ 月度导出
```

含义：

- 电箱台账：项目内所有临时电箱的基础档案和负责关系。
- 二维码：每个电箱唯一绑定一个二维码，用于扫码巡检和查看汇总。
- 检查模板：如电箱检查、设备巡检、安全检查。
- 检查项：模板下的具体检查字段。
- 检查记录：某项目、某电箱、某日期、某检查人提交的一次检查。
- 检查项结果：每个检查项的正常、异常、不适用等结果。
- 异常整改：一个或多个异常检查项聚合为一条任务，提交时指定当前项目合格电工。
- 整改复查：电工提交说明和整改照片后，由当前项目合格安全员关闭、退回或改派。
- 历史逐条安全复核和现场安全抽查：表与部分源码保留兼容，不属于当前正向业务模型。

## 三、电箱台账规格

表规划：

```text
electric_box
```

字段规划：

| 字段 | 类型建议 | 含义 | 规则 |
| --- | --- | --- | --- |
| `id` | BIGINT | 电箱 ID | 主键 |
| `project_id` | BIGINT | 所属项目 | 必填，按项目权限校验 |
| `box_code` | VARCHAR | 电箱编号 | 同一项目内唯一 |
| `box_name` | VARCHAR | 电箱名称 | 可选 |
| `install_location` | VARCHAR | 安装位置 | 必填 |
| `responsible_electrician_id` | BIGINT | 负责电工 ID | 可选，建议必填 |
| `responsible_electrician_name` | VARCHAR | 负责电工姓名 | 冗余展示 |
| `safety_manager_id` | BIGINT | 安全负责人 ID | 可选 |
| `safety_manager_name` | VARCHAR | 安全负责人姓名 | 冗余展示 |
| `qr_code` | VARCHAR | 历史内部二维码编码 | 同一项目内唯一，当前仅兼容 |
| `public_code` | VARCHAR | 统一场景码主体 | 服务端生成，现场贴纸编码为 `B:<publicCode>` |
| `qr_status` | VARCHAR | 二维码状态 | `UNBOUND`、`BOUND`、`DISABLED` |
| `status` | VARCHAR | 电箱状态 | `ACTIVE`、`INACTIVE`、`REMOVED` |
| `public_access_enabled` | TINYINT | 外部只读开关 | 关闭时无内部权限调用者不得获得电箱元数据 |
| `remark` | VARCHAR | 备注 | 可选 |
| `deleted` | TINYINT | 逻辑删除 | 默认 `0` |
| `create_time` | DATETIME | 创建时间 | 审计字段 |
| `update_time` | DATETIME | 更新时间 | 审计字段 |

台账规则：

- 项目安全员确定现场电箱数量和巡检覆盖范围。
- 同一项目内 `box_code` 唯一。
- 历史 `qr_code` 和当前 `public_code` 均保持唯一，统一码与电箱一一对应。
- 停用电箱不可新增日检，可查看历史记录。
- 统一码生成、打印、轮换、停用和拆除均写入 `electric_box_qr_log`。

## 四、二维码规则

现场贴纸使用统一场景码 `B:<publicCode>`，同一码按调用者身份和电箱公开访问状态分流，不携带
用户、项目权限或内部数据库 ID：

```text
GET /api/v1/scan/electric-boxes/{sceneCode}
```

规则：

- 已登录且拥有当前项目 `inspection.submit` 的巡检员进入“今日巡检”；有记录查看权限的成员进入
  “本箱记录”；未登录或无内部权限人员在公开访问启用时进入“月度公示”。
- 后端只按场景码反查电箱和项目，不信任客户端解析出的项目或电箱 ID。
- 停用、拆除或换码后的旧场景码不可继续巡检；换码、打印和状态变化写入二维码日志。
- 调用者无目标项目巡检权限且电箱关闭公开访问时，必须在读取巡检范围和内部记录前返回 HTTP
  `403`，不得泄露电箱编号、名称或位置。
- 匿名公开分支不查询当天内部记录；公开月表只返回脱敏统计，不返回检查人、照片、检查项明细、
  备注或内部 ID。
- 历史内部码解析和公开近 30 天摘要接口保留兼容，但新贴纸和当前小程序只使用统一场景码。

## 五、电箱检查模板

模板编码：

```text
ELECTRIC_BOX_DAILY
```

模板名称：

```text
电箱检查记录表
```

检查频率：

```text
DAILY
```

记录来源：

| 值 | 文案 | 说明 |
| --- | --- | --- |
| `ELECTRICIAN_DAILY` | 电工日检 | 电工扫码每日巡检 |
| `SAFETY_SPOT_CHECK` | 历史安全员抽查 | 仅兼容旧数据，当前接口固定写入 `ELECTRICIAN_DAILY` |

检查项：

| 排序 | 字段名称 | 字段编码 | 输入类型 | 是否必填 | 异常时要求 |
| --- | --- | --- | --- | --- | --- |
| 1 | 内外观 | `APPEARANCE` | 单选 | 是 | 填写异常说明；本轮不支持单项照片 |
| 2 | 漏电保护器 | `LEAKAGE_PROTECTOR` | 单选 | 是 | 填写异常说明；本轮不支持单项照片 |
| 3 | 熔断 | `FUSE` | 单选 | 是 | 填写异常说明；本轮不支持单项照片 |
| 4 | 保护接零 | `PROTECTIVE_ZERO` | 单选 | 是 | 填写异常说明；本轮不支持单项照片 |
| 5 | 220V插座 | `SOCKET_220V` | 单选 | 是 | 填写异常说明；本轮不支持单项照片 |
| 6 | 380V插座 | `SOCKET_380V` | 单选 | 是 | 填写异常说明；本轮不支持单项照片 |

单选值：

| 值 | 展示文案 | 含义 |
| --- | --- | --- |
| `NORMAL` | 正常 | 检查通过 |
| `ABNORMAL` | 异常 | 存在问题，需要说明或整改 |
| `NA` | 不适用 | 当日或现场不适用 |

## 六、检查记录字段

表规划：

```text
inspection_record
inspection_record_item
```

检查记录主字段：

| 字段 | 含义 | 规则 |
| --- | --- | --- |
| `projectId` | 项目 ID | 必填，后端校验项目权限 |
| `electricBoxId` | 电箱 ID | 必填，后端反查项目 |
| `templateCode` | 模板编码 | 首版固定 `ELECTRIC_BOX_DAILY` |
| `source` | 记录来源 | 当前服务端固定 `ELECTRICIAN_DAILY`；旧 `SAFETY_SPOT_CHECK` 只读兼容 |
| `checkDate` | 检查日期 | 必填，默认当天 |
| `inspectorId` | 检查人 ID | 后端从 token 写入 |
| `inspectorName` | 检查人姓名 | 后端从当前用户写入 |
| `outerPhotoFileIds` | 外观照片 | 电工日检必填 |
| `innerPhotoFileIds` | 内部照片 | 电工日检必填 |
| `status` | 记录状态 | 见状态流转 |
| `reviewStatus` | 历史逐条复核状态 | 当前正常记录写 `NOT_REQUIRED`，异常记录写 `RECTIFICATION_REQUIRED` |
| `reviewerId / reviewerName / reviewTime` | 历史逐条复核字段 | 新流程不写入，整改复查人保存在整改任务中 |
| `remark` | 总备注 | 可选 |

检查记录唯一性：

- 同一 `projectId + electricBoxId + templateCode + checkDate + source=ELECTRICIAN_DAILY` 默认只允许一条有效记录。
- 历史 `SAFETY_SPOT_CHECK` 记录保留只读，不参与当前日检唯一性写入流程。
- 由于存在逻辑删除，实施唯一索引时需包含 `deleted` 或采用业务校验。

补录规则：

- 默认允许补录今天及往前 7 天日检。
- 本轮不开放超过 7 天补录入口；超过 7 天提交由后端拒绝。
- 补录记录必须保留真实创建时间和检查日期。

## 七、状态流转

### 7.1 电箱状态

| 状态 | 文案 | 说明 |
| --- | --- | --- |
| `ACTIVE` | 启用 | 可扫码巡检 |
| `INACTIVE` | 停用 | 不可新增巡检，可查看历史 |

### 7.2 二维码状态

| 状态 | 文案 | 说明 |
| --- | --- | --- |
| `UNBOUND` | 未绑定 | 尚未绑定电箱 |
| `BOUND` | 已绑定 | 可正常扫码 |
| `DISABLED` | 已停用 | 不可扫码巡检 |

### 7.3 检查记录状态

| 状态 | 文案 | 说明 |
| --- | --- | --- |
| `COMPLETED` | 已完成 | 六项无异常，提交后直接完成 |
| `RECTIFICATION_PENDING` | 整改中 | 存在异常并已聚合生成一条未闭环整改任务 |
| `CLOSED` | 已闭环 | 关联整改已由安全员复查关闭 |
| `DRAFT / REVIEW_PENDING / REVIEW_REJECTED / REVIEW_PASSED / VOIDED` | 历史状态 | 只作旧数据兼容，不生成新的逐条复核流程 |

### 7.4 历史逐条复核状态（当前不再生成）

| 状态 | 文案 | 说明 |
| --- | --- | --- |
| `PENDING` | 待复核 | 电工提交后自动进入 |
| `PASS` | 通过 | 记录归档 |
| `REJECT` | 退回 | 退回电工修改 |
| `RECTIFY` | 转整改 | 生成整改任务 |

### 7.5 整改任务状态

| 状态 | 文案 | 说明 |
| --- | --- | --- |
| `PENDING` | 待整改 | 已生成，等待整改人处理 |
| `COMPLETED` | 待复查 | 整改人已提交反馈，等待复查 |
| `CLOSED` | 已关闭 | 复查通过 |
| `REJECTED` | 复查退回 | 复查不通过，继续整改 |

逾期不建议作为单独状态落库，首版可通过 `deadline < today && status in (PENDING, REJECTED)` 动态计算。退回次数落到 `reject_count`，退回后再次提交复查截止日期落到 `recheck_deadline`。

## 八、核心流程

### 8.1 电箱台账初始化

```text
项目安全员进入电箱台账
→ 新增或导入电箱
→ 填写编号、位置、负责电工
→ 生成并绑定统一场景码
→ 打印单码贴纸张贴到现场电箱
```

规则：

- 电箱编号完全自定义，仅校验同项目唯一和 1-64 字符长度。
- PC 后台支持下载 Excel 模板、上传预检和提交导入。
- 导入存在 `ERROR` 时不写库，`WARN` 可提交。
- 二维码补打/打印会写入操作日志。

### 8.2 电工日检

```text
电工进入小程序
→ 扫描电箱二维码
→ 进入该电箱日检表
→ 外观照片和内部照片各拍摄上传至少 1 张
→ 填写六项检查结果
→ 提交
→ 六项均正常：记录状态为 COMPLETED
→ 存在异常：选择项目合格电工和期限，记录状态为 RECTIFICATION_PENDING
→ 多个异常项聚合生成一条 PENDING 整改任务
```

### 8.3 历史流程：安全员复核通过（当前已退出）

```text
安全员进入待复核
→ 查看照片和检查项
→ 复核通过
→ 记录状态为 REVIEW_PASSED
→ 当月导出可计入已检
```

### 8.4 历史流程：安全员复核退回（当前已退出）

```text
安全员进入待复核
→ 填写退回原因
→ 记录状态为 REVIEW_REJECTED
→ 电工待办出现待修改记录
→ 电工修改后重新提交
```

### 8.5 异常日检生成整改（当前流程）

```text
巡检员填写一个或多个异常项及说明
→ 从服务端候选列表选择当前项目电工
→ 设置整改期限（未传时默认 3 天）
→ 提交巡检并聚合生成一条整改任务
→ 记录状态为 RECTIFICATION_PENDING
```

### 8.6 历史流程：安全员现场抽查（当前已退出）

```text
安全员扫码
→ 选择现场抽查
→ 上传问题照片
→ 填写问题说明和整改要求
→ 提交
→ 生成 source=SAFETY_SPOT_CHECK 的记录
→ 同步生成整改任务
```

### 8.7 整改反馈和复查

```text
电工进入我的待整改
→ 填写整改说明
→ 上传整改照片
→ 提交
→ 安全员待复查
→ 复查通过关闭
→ 或复查退回继续整改
```

## 九、接口规格

基础接口已按 `/api/v1/**` 落地，统一返回 `Result<T>`，导出文件流除外。后续如果字段继续扩展，应同步更新本节和 `docs/接口规则.md`。

### 9.1 电箱列表

```text
GET /api/v1/electric-boxes?projectId=1&status=ACTIVE&keyword=EB
```

返回：电箱列表，包含编号、位置、负责电工、二维码状态、最近巡检状态。

权限：登录用户，按 `projectId` 校验项目权限。

### 9.2 电箱详情

```text
GET /api/v1/electric-boxes/{id}
```

规则：

- 先查电箱。
- 按电箱 `projectId` 校验项目权限。
- 返回电箱基础信息、二维码信息、最近巡检摘要和未闭环整改数。

### 9.3 新增电箱

```text
POST /api/v1/electric-boxes
```

请求体建议：

```json
{
  "projectId": 1,
  "boxCode": "EB-001",
  "boxName": "二级电箱 1",
  "installLocation": "一层东侧",
  "responsibleElectricianId": 5,
  "safetyManagerId": 3,
  "remark": "靠近材料堆场"
}
```

权限：平台管理员、项目管理员、安全管理员。

### 9.4 更新电箱

```text
PUT /api/v1/electric-boxes/{id}
```

规则：

- 先按 `id` 查询原电箱，再按原 `projectId` 校验权限。
- 不信任请求体里的 `projectId` 覆盖权限边界。
- 编号变更需校验同项目唯一。

### 9.5 停用电箱

```text
POST /api/v1/electric-boxes/{id}/disable
```

规则：后端将电箱 `status` 更新为 `INACTIVE`，并将内部二维码状态更新为 `DISABLED`。

### 9.6 拆除电箱

```text
POST /api/v1/electric-boxes/{id}/remove
```

规则：

- 存在未闭环整改时禁止拆除。
- 后端将电箱 `status` 更新为 `REMOVED`，将内部二维码状态更新为 `DISABLED`，并关闭 `public_access_enabled`。
- 拆除后不可新增巡检/抽查，可查看历史记录。

### 9.7 统一码换码、补打和日志

```text
GET  /api/v1/electric-boxes/{id}/unified-code
POST /api/v1/electric-boxes/{id}/unified-code/rotate
POST /api/v1/electric-boxes/{id}/qr/print-log
GET  /api/v1/electric-boxes/{id}/qr-logs
```

规则：

- 统一码由后端生成，场景固定为 `B:<publicCode>`；轮换后旧码失效。
- 旧码、轮换和打印/补打动作写入 `electric_box_qr_log`。
- `POST /qr/rebind` 只作旧内部码兼容，新贴纸不再生成双码。

### 9.8 台账导入与二维码图片

```text
GET  /api/v1/electric-boxes/import-template
POST /api/v1/electric-boxes/import
POST /api/v1/electric-boxes/qr-svg
```

规则：

- 导入模板字段包括电箱编号、名称、安装位置、负责电工账号/姓名、安全负责人账号/姓名、公开扫码启用、备注。
- 预检返回 `OK` / `WARN` / `ERROR` 行级结果，`ERROR` 不允许提交。
- PC 后台通过统一码接口取得正式图像；`qr-svg` 仅用于受控兼容内容生成，不恢复双码贴纸。

### 9.9 二维码解析

```text
GET /api/v1/scan/electric-boxes/{sceneCode}
```

规则：

- 新增电箱时后端自动生成统一 `publicCode`，贴纸场景为 `B:<publicCode>`。
- 内部分支按登录态、项目范围和巡检权限决定动作；公开分支受 `public_access_enabled` 控制。
- 旧内部码兼容解析保留，但当前客户端不再生成或张贴旧格式。

### 9.10 获取检查模板

```text
GET /api/v1/inspection/templates?projectId=1
```

返回建议：

```json
{
  "code": 200,
  "message": "success",
  "data": [
    {

      "templateName": "电箱检查记录表",
      "frequency": "DAILY",
      "items": [
        {
          "itemCode": "APPEARANCE",
          "itemName": "内外观",
          "inputType": "RADIO",

```

### 9.8 查询检查记录

```text
GET /api/v1/inspection/records?projectId=1&electricBoxId=10&templateCode=ELECTRIC_BOX_DAILY&month=2026-06&status=
```

返回：检查记录列表，包含电箱编号、检查日期、来源、复核状态、异常数量和整改状态摘要。

### 9.9 创建检查记录

```text
POST /api/v1/inspection/records
```

电工日检请求体建议：

```json
{
  "projectId": 1,
  "electricBoxId": 10,
  "templateCode": "ELECTRIC_BOX_DAILY",
  "source": "ELECTRICIAN_DAILY",
  "checkDate": "2026-06-29",
  "outerPhotoFileIds": [101],
  "innerPhotoFileIds": [102],
  "remark": "无",
  "items": [
    {
      "itemCode": "APPEARANCE",
      "result": "NORMAL",
      "description": ""
    },
    {
      "itemCode": "LEAKAGE_PROTECTOR",
      "result": "ABNORMAL",
      "description": "测试按钮无响应"
    }
  ],
  "assigneeId": 5,
  "requirement": "更换漏电保护器并复测",
  "deadline": "2026-07-02"
}
```

规则：

- 服务端固定写入 `ELECTRIC_BOX_DAILY / ELECTRICIAN_DAILY`；`inspectorId`、`inspectorName` 由后端当前用户写入。
- 电工日检外观照片和内部照片均为必填，每类至少 1 张；两类照片必须全部上传成功，任一缺失或上传失败时保留本地草稿并停止业务提交。
- 六项检查结果必须完整，结果值只允许 `NORMAL`、`ABNORMAL`、`NA`。
- 任一检查项选择 `ABNORMAL` 时必须填写异常说明；本轮不做每个异常项单独照片上传。
- 存在异常时 `assigneeId` 必填，且目标必须是当前项目有效 `ELECTRICIAN + inspection.rectify`；
  项目还必须存在 `SAFETY_OFFICER + inspection.review`，否则整次提交回滚。
- 小程序日检表单显示检查日期选择，默认当天，只允许选择今天及往前 7 天。
- 同一电箱同一天只允许一条有效电工日检。
- 六项均正常时进入 `COMPLETED`；存在异常时进入 `RECTIFICATION_PENDING` 并聚合生成一条整改任务。
- 历史 `REVIEW_*` 状态只作旧数据兼容。

### 9.10 历史更新检查记录设计（当前无 Controller 映射）

```text
PUT /api/v1/inspection/records/{id}
```

规则：

- 旧设计仅允许 `DRAFT` 或 `REVIEW_REJECTED` 编辑；当前客户端使用一次性 `POST /records` 原子提交。
- 更新时先查原记录，再按原记录 `projectId` 校验权限。
- 不能信任请求体里的 `projectId` 或 `electricBoxId` 覆盖权限边界。

### 9.11 兼容提交检查记录

```text
POST /api/v1/inspection/records/{id}/submit
```

规则：

- 仅供旧客户端处理历史草稿；事务内锁定目标记录，并校验外观和内部照片均已绑定。
- 对当前 `COMPLETED / RECTIFICATION_PENDING / CLOSED` 记录重复调用时幂等返回，不修改状态；早期终态记录缺少现行必填照片时也保持原状态返回。
- `REVIEW_PENDING / REVIEW_REJECTED / REVIEW_PASSED / VOIDED` 及未知状态返回 HTTP `409`，不得由兼容入口改写。
- 当前新客户端必须直接使用 `POST /records` 完成正常/异常分支，不通过本接口进入逐条复核。

### 9.12 历史逐条复核检查记录（当前无 Controller 映射）

```text
POST /api/v1/inspection/records/{id}/review
```

请求体建议：

```json
{
  "reviewAction": "PASS",
  "reviewComment": "现场照片清晰，检查项完整",
  "rectifications": []
}
```

转整改请求体建议：

```json
{
  "reviewAction": "RECTIFY",
  "reviewComment": "漏电保护器检查异常，需要整改",
  "rectifications": [
    {
      "itemCode": "LEAKAGE_PROTECTOR",
      "assigneeId": 5,
      "requirement": "更换漏电保护器并复测",
      "deadline": "2026-07-02"
    }
  ]
}
```

动作值：

| 值 | 说明 |
| --- | --- |
| `PASS` | 复核通过 |
| `REJECT` | 退回电工修改 |
| `RECTIFY` | 生成整改 |

### 9.13 完成整改

```text
POST /api/v1/inspection/rectifications/{id}/complete
```

请求体建议：

```json
{
  "feedback": "已更换漏电保护器，测试恢复正常",
  "photoFileIds": [301, 302]
}
```

权限：

- 当前任务整改负责人本人可提交，且操作时仍须具备当前项目 `ELECTRICIAN` 和
  `inspection.rectify`；平台管理员保留应急处理。
- 仅 `PENDING` / `REJECTED` 状态可提交。
- 整改说明和整改照片至少 1 张由后端强校验。

### 9.14 关闭整改

```text
POST /api/v1/inspection/rectifications/{id}/close
```

请求体建议：

```json
{
  "comment": "复查通过"
}
```

权限：

- 当前项目 `SAFETY_OFFICER + inspection.review` 或平台管理员可关闭。
- 仅 `COMPLETED` 状态可关闭。
- 关闭意见可选，关闭后如同一检查记录下无未关闭整改，检查记录置为 `CLOSED`。

### 9.15 退回整改

```text
POST /api/v1/inspection/rectifications/{id}/reject
```

请求体建议：

```json
{
  "comment": "整改照片不清晰，现场仍有线缆裸露"
}
```

权限与规则：

- 当前项目 `SAFETY_OFFICER + inspection.review` 或平台管理员可退回。
- 仅 `COMPLETED` 状态可退回。
- 退回原因必填，退回后 `reject_count` 累加，`recheck_deadline` 顺延 3 天。
- 完成整改、复查关闭、复查退回均写入 `inspection_rectification_review_log`。

### 9.16 改派整改

```text
POST /api/v1/inspection/rectifications/{id}/assign
```

仅当前项目 `SAFETY_OFFICER + inspection.review` 或平台管理员可操作；只能把 `PENDING / REJECTED`
任务改派给当前项目其他 `ELECTRICIAN + inspection.rectify` 电工，改派原因必填。候选人统一从
`GET /api/v1/inspection/rectification-assignees?projectId=...` 获取，提交时后端再次校验。

## 十一、导出规则

默认导出 Excel。

接口：

```text
GET /api/v1/inspection/records/export?projectId=1&templateCode=ELECTRIC_BOX_DAILY&month=2026-06&boxId=
```

Web 日期范围和部分电箱导出：

```text
GET /api/v1/inspection/records/export?projectId=1&templateCode=ELECTRIC_BOX_DAILY&startDate=2026-06-15&endDate=2026-07-15&boxIds=10,12,18
```

- `startDate/endDate` 首尾日期均包含，必须同时传入，结束日期不晚于当天且跨度最多 366 天。
- `boxIds` 使用英文逗号分隔；不传表示全部电箱，传一个表示单箱，传多个表示部分电箱。
- 日期范围参数不能与旧 `month/boxId` 参数混用，正式范围报表不应用巡检员或结果筛选。

工作簿：

- 文件名建议：月报使用 `{项目简称或项目名称}_电箱检查记录_{yyyy-MM}.xlsx`；范围报表包含起止日期。
- Sheet 1：`巡检汇总`
- 后续 Sheet：每个电箱一个明细 Sheet，名称建议 `{boxCode}`，过长时截断并避免重名。
- 仅选择一个电箱时生成一个正式《电箱检查记录表》Sheet；选择多个或全部电箱时生成汇总和逐箱明细。

巡检汇总 Sheet 字段：

| 字段 | 说明 |
| --- | --- |
| 电箱编号 | `boxCode` |
| 安装位置 | `installLocation` |
| 负责电工 | `responsibleElectricianName` |
| 应检天数 | 当月需巡检天数 |
| 已检天数 | 有有效日检记录的天数 |
| 漏检天数 | 无记录天数 |
| 异常次数 | 异常记录数或异常项数 |
| 未闭环整改 | 未关闭整改任务数 |
| 最近检查日期 | 最近一次日检日期 |

电箱明细 Sheet 表头：

```text
日期 | 内外观 | 漏电保护器 | 熔断 | 保护接零 | 220V插座 | 380V插座 | 检查人 | 备注
```

明细填充规则：

- 月报按当月每天一行；日期范围报表只生成所选范围内的日期行。
- 无有效日检记录的日期，各检查项显示 `未检`。
- `NORMAL` 显示 `正常`。
- `ABNORMAL` 显示 `异常`。
- `NA` 显示 `不适用`。
- 备注汇总巡检备注、异常说明和整改状态，不追加已退出的安全抽查流程。

导出权限：

- 平台管理员可导出全部项目。
- 项目管理员、安全管理员可导出授权项目。
- 拥有 `INSPECTION_DAILY_SUBMIT` 或 `SUMMARY_EXPORT` 的成员可导出一个指定电箱。
- 多个电箱、全部电箱或项目级导出必须拥有 `SUMMARY_EXPORT`。

## 十二、验收用例

小程序与 PC 管理后台的端到端联动验收详见 `docs/小程序与PC管理后台交互测试计划.md`。本节保留现场检查模块的基础验收点，实际联调时以交互测试计划中的用例编号、优先级和通过标准记录结果。

### 12.1 权限

- 普通用户不能访问未授权项目。
- 电工只能巡检负责电箱或授权范围内电箱。
- 电工只能处理分配给自己的整改。
- 安全员只能复核授权项目。
- 平台管理员可查看全部项目记录。

### 12.2 二维码

- 同一项目内二维码唯一。
- 扫码能解析到正确电箱。
- 停用电箱扫码提示不可巡检。
- 二维码换绑后旧二维码不可继续巡检。

### 12.3 巡检

- 同一电箱同一天只允许一条有效日检。
- 外观照片和内部照片各至少 1 张；两类照片都必须上传成功后才允许提交。
- 六项检查项必填。
- 近 7 天内可补录。
- 异常项必须填写说明。

### 12.4 历史逐条复核退出边界

- 新巡检不生成 `REVIEW` 待办，不展示逐条复核、复核退回或复核转整改入口。
- 直接请求历史 `/review`、`/assign-reviewer`、`/review-logs` 路径时，未登录先返回 `401`，
  有效授权上下文返回 `404`。
- 当前 `/rectifications*` 接口不属于历史退出范围。

### 12.5 异常整改与复查

- 一个或多个异常项只生成一条整改任务，负责人必须是当前项目合格电工。
- 被指派电工提交整改说明和至少一张整改照片后，安全员可关闭、退回或在待整改状态改派。
- 非指派电工、非安全员、跨项目调用和错误状态流转必须分别返回真实 `403 / 409`。
- 逾期任务可筛选。
- 关闭整改后关联记录状态正确更新。

### 12.6 导出

- 按项目月份导出全部电箱。
- 汇总页统计应检、已检、漏检、异常、未闭环数量。
- 明细页还原原表字段。
- 无记录日期显示 `未检`。
- 异常项显示 `异常`，备注包含问题和整改状态。

## 十三、联调前置

当前结构、模板、权限和基础闭环已实现。继续真机/生产候选验收前必须：

1. 使用 `VITE_USE_MOCK=false`、正式 AppID/AppSecret 和合法 HTTPS request/upload/download 域名。
2. 准备隔离项目、启用电箱、巡检员、`ELECTRICIAN + inspection.rectify` 电工和
   `SAFETY_OFFICER + inspection.review` 安全员，不得在长期业务数据上制造验收记录。
3. 先执行自动化后端门禁和全量构建，再在真机完成统一码、弱网、外观/内部照片、异常整改、
   复查关闭/退回及 Web 回显。
4. 任何目标环境迁移前先备份和预检，只执行该环境缺失且适用的增量脚本；不得执行 `init.sql`。
