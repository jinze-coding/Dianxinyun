# 用印台账 Word 导出

更新日期：2026-09-11。网页台账列表保持现状，仅替换导出格式与内容。

## 模板和字段

用户提供的“附件8：印章使用登记台账.docx”原样纳入
`backend/src/main/resources/templates/seal-ledger.docx`，SHA-256 为
`db7474731fa2324484a0efa3805e9bb6c1a04dd36b633f976ff754041a60f3ce`。
生成时不再依赖原微信临时目录。

| Word 字段 | 当前系统来源 |
| --- | --- |
| 序 | 导出明细从 1 连续编号 |
| 用印日期 | `approvalTime` 的日期部分，`yyyy-MM-dd` |
| 用印文件名称 | `seal_application_item.documentName` |
| 份数 | 该文件明细的 `copies` |
| 用印单位 | 申请的 `departmentName` 项目部名称快照 |
| 用印人 | 申请的 `applicantName` 姓名快照 |
| 项目部经办人 | 最终同意审批人的 `approverName` 快照 |

一份申请多项文件逐项生成行，重复日期和人员。申请按审批时间、申请编号、主键升序，
文件按明细顺序及主键升序。历史字段缺失留空，不以现成员姓名补写快照；历史申请缺失全部文件明细时，
保留一行申请信息，文件名称/份数留空。正常空查询结果只有抬头和表头，不补空白明细行。

## 版式和实现

固定保留“上海建工智慧营造有限公司”“项目部印章使用登记台账”两行抬头，右上角编号留空。
模板使用 A4 横向，页面 16838×11906 twips，页边距上 850、下 624、左右 1213 twips；
七列宽度为 631/1245/5700/780/2904/1404/1740 twips。“用印单位/用印人”只在表头合并。
抬头和正文沿用黑体 15 pt，表头沿用华文楷体 12 pt，编号沿用宋体 12 pt。

`SealLedgerWordRenderer` 读取类路径模板，仅修改 `word/document.xml`，其他 ZIP 部件字节保持不变。
复用首条空白行的段落、字体和单元格样式，改为固定列宽，按实际明细逐行写入压缩包，
避免为全部明细构建大型 DOM。文本按 XML 文本节点转义，不生成字段或公式。
长文件名称自动换行，行高随内容增长；窄日期列在年份后的连字符处分行，保留原字号和列宽。
表头在续页重复，单条明细设置不跨页拆分。生成过程纯 Java，不调用 Office，也不需要服务器安装字体。

## 接口与边界

- `/api/v1/seal/ledger/export` 和兼容 `/api/v1/seal/applications/export` 统一返回 DOCX，文件名为 `用印台账_起始日期_结束日期.docx`。
- 响应 MIME 为 `application/vnd.openxmlformats-officedocument.wordprocessingml.document`，附带文件长度、UTF-8 下载名、`nosniff` 和 `private, no-store`。
- 保留项目范围及 `seal.export` 后端鉴权、关键词、日/周/月/自定义日期、最多 10000 份申请和导出审计。
- 只查询 `APPROVED`；首日零点包含，结束日期下一日零点排除，其他显式状态返回业务错误。数量超限拒绝，不截断导出。
- 不新增业务字段、迁移、菜单或权限；申请附件选填、盖章件要求、小程序及单份/合并申请单 PDF 沿用现有规则。
- 模板外的电话、事由、审批意见、抄送与附件状态继续保留在系统内，不写入 Word 台账。

## 验证入口

后端 `mvn test` 包含 `SealLedgerServiceTest`、`SealLedgerWordRendererTest`、
`SealLedgerControllerTest` 与既有 `LedgerDateRangeTest`，覆盖多申请/多文件/份数、日期边界、
历史空值、无记录、筛选与排序、越权、非批准状态、超限、审计失败及两个入口的响应合同。
生成样本由测试输出，`-Dseal.ledger.qaOutputDir=...` 可指定目录。
包部件一致性、模板摘要、合并表头、重复表头、不拆行与可编辑文本均有断言。

Web 使用 `npm run check && npm run audit` 检查；下载按钮为“导出 Word 台账”，仍复用原 Blob 下载逻辑。
版式验证使用现有中文字体配置渲染单页、空表和 36 项明细（含 200 字文件名）的多页样本，逐页检查后在 WPS 核对。
本机未完整安装原模板字体，渲染检查使用黑体-简、宋体-简和汉仪楷体简等可用中文替代字体，
WPS 也显示字体缺失提示；输出 DOCX 的原字体定义不作替换。严格原字体效果需在安装相应字体的办公环境复核。
本地运行与最终验证结果见[开发状态](开发状态.md)。生产部署按正式手册另行处理。
