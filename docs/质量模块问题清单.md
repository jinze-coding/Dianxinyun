本文档依据当前 Web、小程序、后端、数据库结构和正式项目文档整理。正式模块已定义为“质量周检”：

## 已确认的正式业务口径

- 质量模块管理的是每周质量检查留档及其问题整改闭环，页面正式名称为“质量周检”。
- 自然周按 Asia/Shanghai 周一至周日计算。允许当前周及往期补录、禁止未来周；逾期提交显示“补录”并保留实际提交时间。
- 草稿允许字段暂不完整；正式提交前一次校验全部问题。任一问题失败整批回滚，已提交重复调用幂等返回。
- 零问题周检必须填写不超过 1000 字结论并上传 1–20 张现场照片；存在问题时现场照片可选。
- 新问题只能从周检产生。旧 `POST /api/v1/quality/issues` 返回 HTTP `410`，历史独立问题仍可查询、整改、复查、改派和作废。
- 周检提交后不可修改；保存 `submitted_issue_count` 快照，个别问题被管理员删除后仍保留周检留档。
- `deadline` 统一解释为问题整体闭环期限，待整改和待复查均纳入逾期判断。
- 质量资料由目标项目具备 `quality.manage` 的人员在 PC 端维护，小程序只读查看当前项目的有效资料。
- 工程资料、质量资料和质量问题附件继续保持独立，不自动合并。
- 普通项目角色可通过细分权限参与质量闭环，不再附加
  `PROJECT_ADMIN / SAFETY_ADMIN` 固定角色白名单。周检草稿创建/保存/提交/放弃、改派、期限调整、作废和质量
  资料管理使用 `quality.manage`；整改必须具备 `quality.rectify` 且为本人被指派或同时
  具有 `quality.manage`；复查使用独立的 `quality.review`。
- 当前质量闭环允许同一位分别具备 `quality.manage`、`quality.rectify` 和
  `quality.review` 的人员代办发起、整改或复查，不强制“发起人、整改人、复查人三者
  分离”；这是为兼容单质量管理员项目而保留的明确业务边界。
