# 用印申请单合并导出

更新日期：2026-09-11。直接更新当前本地开发系统，范围为 Web 合并 PDF 和两端单份 PDF 授权。

## 使用方法

进入“资料管理 → 用印管理 → 用印申请”，在查询区域点击“合并导出 PDF”。

- **当前筛选全部**：使用最近一次点击查询/重置后生效的项目、页签、状态、关键词与申请日期，
  包含全部分页中已审批通过的记录。输入框里尚未查询的新条件不参与导出，弹窗显示实际条件。
- **已勾选申请**：只能勾选后端允许导出的已通过记录，支持本页全选、跨页保留、清空。
  切换项目、页签或应用筛选条件会清空选择；仅翻页不会清空。
- 点击“开始合并”生成后台任务。关闭弹窗后继续执行，再打开可查看本人最近 20 个任务，
  其中包含数量、已处理数量、总页数、失败原因、重试和下载入口。

每批最多 500 份，超过时明确要求缩小范围，不截断；每人最多两个未完成任务，跨项目合计。
没有符合条件的记录时提示“当前条件下没有可导出的已通过申请”。

PDF 顺序与申请列表一致：创建时间倒序、ID 倒序。每份申请完整追加，下一份从新页开始，
保留原版式、中文字体、审批信息、原单份页码及续页；按单面打印排列，不补空白页。
文件明细中的份数只作为表单内容，每份申请仅输出一次。源附件、盖章件不并入 PDF。

## 权限

新增 `seal.application.export`，名称“导出用印申请单”，归属现有 `DOCUMENT_SEAL` 菜单。
后台“角色管理 → 权限配置 → 用印管理”可明确勾选；平台管理员自动拥有启用权限，
普通角色不会因迁移自动获得。小程序仅同步已有单份 PDF 按钮的 `canExportForm` 判断。

该权限控制单份 `form.pdf`、兼容 `pdf` 和合并接口；`seal.export` 继续只控制用印台账。
新权限不隐式授予 `seal.view`、菜单或记录查看资格。全部申请要求原 `seal.view`，
本人申请、审批任务和明确抄送沿用原记录 ACL。列表与详情的 `canExportForm` 同时要求
APPROVED 和目标项目的导出权限，后端始终独立校验。

创建、执行各份、完成发布、下载均重新校验有效账号、项目/模块、导出权限及原记录 ACL。
执行过程中撤权则失败；生成后撤权也不能下载。只允许创建人读取任务和下载结果，管理员同样不能读取他人的任务。
`SEAL_FORM_EXPORT` 文件沿用通用文件服务的 SEAL 专用通道保护，不能通过通用文件接口旁路读取、覆盖、删除或伪造上传。

## 接口

以下均在 `/api/v1/seal/applications/form-export-jobs` 下，由现有 JWT 登录态识别创建人。

| 方法与路径 | 用途 |
| --- | --- |
| POST `/` | 创建任务，固定申请集合和顺序 |
| GET `/?projectId=...` | 当前项目本人最近 20 个任务 |
| GET `/{id}` | 本人任务状态 |
| POST `/{id}/retry` | 重试失败或过期任务，按原申请集合重新校验并创建新任务 |
| GET `/{id}/download` | 受控 PDF 文件流，UTF-8 附件文件名、private/no-store、nosniff |

按筛选创建示例：

```json
{
  "projectId": 3,
  "requestKey": "客户端本次请求的随机唯一编号",
  "selectionMode": "FILTER",
  "scope": "INITIATED",
  "keyword": "材料报审",
  "startDate": "2026-09-01",
  "endDate": "2026-09-11"
}
```

`scope` 沿用 INITIATED/PENDING_FOR_ME/CC_TO_ME/ALL；可选 status，服务端另外限定 APPROVED。
SELECTED 提交 `projectId/requestKey/selectionMode/applicationIds`。服务端去重后按列表顺序保存，
任何不存在、跨项目、无记录权限或未通过项均拒绝整批，不静默遗漏。重试请求只提交新的 `requestKey`。

请求键按用户唯一，规范化请求摘要固定。同键同条件返回原任务；同键不同条件返回 409。
前端对网络结果不确定的重试复用同一请求键，已完成后用户再次主动导出会创建新任务。
空结果/字段无效为 400，无权 403，状态冲突/两个任务已在执行为 409；筛选超过上限为 413，
指定 ID 数组超过请求上限由字段校验拒绝。响应不暴露存储键、内部文件 ID 或工作租约。

## 后台与文件生命周期

任务状态为 PENDING → RUNNING → SUCCEEDED/FAILED，成功文件七天后 EXPIRED。
使用一个工作线程和一个有界排队槽，持久化队列每两秒领取一次；MySQL 行锁、SKIP LOCKED 和独立租约
防止多个执行器重复领取。每处理一份延长五分钟租约；重启后重新领取租约超时的 RUNNING 任务，
第三次中断后转失败，用户可以明确重试。

`SealFormPdfMerger` 复用 `SealPdfService` 单份渲染器，通过 PDFBox 逐份追加，合并文档使用临时文件缓存。
临时 PDF 最终经现有存储服务保存并通过 Resource 流下载。文件元数据先以 GENERATING 预留、绑定任务，
完成时在单一事务发布文件/任务状态并写入批次及每份申请的 EXPORT_MERGED_PDF 审计。
写入影响行数必须为 1；失败回滚发布事务后，将预留文件交由现有清理机制处理。

失败、重启接管旧文件、过期结果均显式更新 `deleted=1/status=PENDING_DELETE`，事务提交后由既有
清理调度物理清理，失败保留 DELETE_FAILED。不能依赖 MyBatis-Plus `updateById` 修改逻辑删除列。
临时文件在执行结束时清理，崩溃残留仅清理本模块独有前缀且超过 24 小时的文件，不触碰其他临时文件。
