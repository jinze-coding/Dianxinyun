执行数据库迁移或版本切换；进入维护窗口时必须重新备份并核对实时基线。

- 本地原开发库和附件在覆盖前另行完整备份。

## 3. 历史访客密文兼容

快照中共扫描 434 个访客 AES-GCM 密文字段：427 个由当前正式密钥生成，7 个历史值由早期开发默认
密钥生成。7 个候选只落在工具允许的一次性邀请令牌、接待人手机号和邀请审计快照三类字段。

一次性离线修复工具已在快照副本上完成两次独立 VERIFY/APPLY/VERIFY 演练：

- 修复前候选集合、计数和 SHA-256 指纹一致；
- 修复过程使用字段白名单、令牌摘要校验、行锁、原值 CAS、单事务及后验复扫；
- 修复后 434/434 均由当前正式密钥解开，15/15 条邀请详情可读；
- 唯一修复标记为 `20260901_SITE_ACCESS_REENCRYPT_LEGACY_DEVELOPMENT_KEY_V1`。

正式环境仍必须在停服后的同一维护窗口重新执行 VERIFY，并使用实时计数和指纹；禁止照抄本地值。

## 4. 程序验证

- 后端：861 项自动化测试通过；正式 JAR 内嵌并由组包脚本复核同一不可变源码清单 SHA-256；离线
  VERIFY 通过；独立端口启动后验证码接口 HTTP 200、业务码 200，OpenAPI 接口 404；
- Web：Lint、TypeScript、136 项测试和依赖审计通过；正式构建拆分为“过渡 Web”和“最终 Web”。
  过渡 Web 使用新质量周检接口并关闭会议创建，避免新后端与旧 Web 的 410 兼容断点；小程序正式
  生效后才允许切换最终 Web；
- 微信小程序：版本 0.1.8、versionCode 108、构建号
  `0.1.8-20260901-prod-compat`；43 个页面、正式 AppID、正式 HTTPS API、mock 关闭、
  `urlCheck=true`；DCloud `uniStatistics` 已显式关闭，正式产物拒绝统计采集域名；

发布工具同时要求 11 项 SQL、运维脚本、归档校验器和随包文档也只能从该已校验源码归档复制；工作区

避免旧 Spring 应用启动较慢时被固定 3 秒检查误判为恢复失败。

## 5. 正式发布仍需完成的外部门禁

1. 用户明确确认进入维护窗口；
2. 实时正式库、附件和当前程序的新鲜一致性备份完成并可读；
3. 生成并持久化独立的 `DOCUMENT_CIRCULATION_SCENE_ENCRYPTION_KEY`，显式设置
   `APP_SCHEDULING_ENABLED=true`；
4. 执行精确基线预检、11 项 fail-fast 迁移、正式密文 VERIFY/APPLY/VERIFY 和后端验收；
5. 在后端仍停止时安装并原子切换过渡 Web，再启动新后端；恢复流量前验证旧正式小程序、过渡 Web
   与新后端的关键业务兼容；
6. 微信公众平台合法域名、隐私指引、iOS/Android 真机流程、0.1.8 上传审核发布并确认用户端生效；
7. 最后切换最终 Web，开放共享会议创建并完成跨端验收。

任一步失败都必须停止后续阶段；数据库已经产生新写入后，不允许手工反向执行 DROP/ALTER，应按同一
维护窗口快照成对恢复数据库和 uploads，并同步恢复 JAR、Web、环境与 Nginx。
