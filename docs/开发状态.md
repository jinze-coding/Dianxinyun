## 2026-07-28 统一注册与权限管理

本节为当前认证、注册、微信登录和权限管理的最新口径，优先于后文按日期保留的历史描述。

- 认证底座已改为 BCrypt 校验和保存密码，密码强度为 8–72 位且必须同时包含字母和数字。非 BCrypt 历史密码不再放行，而是标记为待管理员重置；可通过环境变量 `ADMIN_RESET_USERNAME`、`ADMIN_RESET_PASSWORD` 显式执行管理员密码重置。JWT 与 Redis 会话有效期统一读取 `JWT_EXPIRATION_MILLIS`，默认 7 天；凭证版本变化、账号停用、微信解绑和关键授权变化会注销该用户全部会话。
- Web 和小程序共用独立的 `registration_application` 注册申请，不再用项目访问申请代替账号注册。提交申请时只保存 BCrypt 摘要，不创建 `sys_user`；状态固定为 `PENDING / APPROVED / REJECTED / CANCELLED`，账号、手机号和小程序微信身份在待审批期间由唯一约束防并发占用。审批通过才在事务内创建账号、分配平台角色和项目角色/范围、建立可用的微信绑定并记录审计；驳回或申请人取消后清除密码摘要并释放占用。
- Web 注册使用图形验证码，手机号首版为人工核验；小程序可使用微信手机号或手工手机号。申请结果只能用提交成功时一次性发放的随机状态令牌查询或取消，不能按手机号或账号枚举。
- 小程序登录页现提供账号密码登录、微信快捷登录、绑定已有账号和申请注册。未绑定微信时，绑定已有账号必须同时验证账号密码和新的 `uni.login` code；小程序注册获批后可直接建立申请时的微信身份绑定。“我的”页展示绑定状态，并且仅在密码登录已启用且重新验证密码时允许用户自行解绑。
- Web 登录页现提供账号密码、微信扫码、注册申请和申请状态查询；默认测试账号提示已删除。扫码 challenge 保存在 Redis 2 分钟，浏览器每 2 秒轮询，状态机为 `WAITING / SCANNED / CONFIRMED / CANCELLED / EXPIRED / CONSUMED`。二维码只承载随机 challenge，浏览器密钥只保存在创建二维码的浏览器；小程序确认后由浏览器用一次性交换码换取普通 JWT。
- Web 顶部继续显示日期时间，主题和密度按钮、弹层及状态已删除，界面固定为白色舒适密度；原主题按钮位置改为按权限显示的“系统管理”。系统管理左侧直接显示功能菜单，不再重复展示“系统管理 / 权限与账号中心”说明区。系统管理包含注册审核、用户管理、角色与权限、菜单与功能、项目授权、微信绑定和操作日志；“角色与权限”同时提供巡检权限角色模板的查看和维护，巡检管理中的旧“用户与权限”入口不再恢复，项目访问申请继续归入系统管理的项目授权。
- Web 登录页的品牌区和登录卡片在桌面端共用同一网格行高度；切换到内容较高的微信扫码登录时两侧会一起等高，不再出现白色登录卡片单独向上、向下撑出的错位。
- 通用 RBAC 已形成平台角色、项目角色、菜单、操作权限和项目数据范围四层结果。`/api/v1/auth/user-info` 返回菜单树、平台权限码和各项目角色/权限；Web 与小程序登录后进入首个有权页面，小程序使用权限驱动的自定义底部导航和页面守卫。前端隐藏只改善体验，资料、巡检、质量和系统管理的受保护接口由后端校验权限码及项目范围，无权调用返回真实 HTTP `403`。

## 风险点

- 权限风险：当前非项目模块可通过传入其他 `projectId` 访问数据。
- 数据风险：执行 `init.sql` 会清空表。
- 状态风险：状态枚举不统一会导致筛选、统计、完成逻辑失效。
- 安全风险：历史非 BCrypt 账号在迁移后会被阻止登录；上线前必须完成管理员密码重置，且 AppID/AppSecret、AK 和数据库密码不能写死。
- 前端风险：主页面都在 `App.jsx` 内联，文件大且容易引入局部运行时错误。
- 视频风险：当前视频展示不是实际播放，不要向用户承诺已接入海康实时流。
- 小程序风险：真实接口第一阶段已能构建，但微信真机扫码、拍照上传、真实账号权限和开发库样例数据仍需人工验收。
- 检查模块风险：基础闭环已实现，但附件权限、二维码换绑留痕、导出样式和更细的待办筛选仍需完善。
- 依赖风险：小程序工程当前使用 uni-app alpha 依赖链，`npm audit --omit=dev` 会报告上游依赖漏洞；`npm audit fix --force` 会触发破坏性变更，不建议在未评估前强制执行。
